## 三、C01 破妄的 P1 缺口

### C01-TPL-001：生命周期与初始属性同步

当前 C01 控制器在运行时注册之后才写入 actor 到单位的映射；而适配器同步英雄属性时只通过 actor 查找单位。首次同步可能因此找不到单位。

此外，延迟伤害、效果属性清理、控制租约和位移结束仍使用未登记的计时器或回调；外部命中确认与落空确认也没有要求生命周期令牌。角色移除后复用同一 actor_id 时，旧回调可能影响新角色。

修复要求：

1. 采用 C02 的注册顺序：先建立 registration 和单位映射，再执行 runtime.register。
2. 为每次注册生成递增生命周期令牌。
3. 将延迟伤害、效果清理、控制与位移回调纳入按 actor 与令牌管理的计时器表。
4. confirm_skill_hit 和 finish_skill_miss 必须拒绝缺失或过期令牌。
5. 新增“旧单位、旧计时器、旧外部回调对新 actor 静默”的桥接测试。

证据位置：implementation/powang/lua/powang_y3_controller.lua 的 register、confirm_skill_hit、finish_skill_miss、remove；implementation/powang/lua/powang_y3_adapter.lua 的 schedule_damage、效果清理与 move_safely。

### C01-TPL-002：回锋的伤害资格分类

回锋照影的反击入口只要护守状态仍在就可触发，控制器向运行时传入的只是普通受伤事件字段。它没有消费地图侧的“敌对、非周期、非自伤、可反击直击、实际有效保护”分类，因此持续伤害、环境伤害或不应计入的事件有刷反击、退款或护盾的风险。

修复要求：

1. 增加项目注入的 classify_guardable_damage 或等价接口。
2. 未绑定时默认 guardable_hit 为 false。
3. 回锋只在分类器确认的有效直击触发一次；若设计需要有效减伤资源，也单独读取实际保护结果。
4. 在花果山首领遭遇数据中登记可反击直击与不可计数伤害标签。

证据位置：implementation/powang/lua/powang_y3_controller.lua 的单位受到伤害事件；implementation/powang/lua/powang_skills.lua 的 trigger_guard_counter。

### C01-TPL-003：减伤类别、乘算与上限

踏虚位移、回锋护守、守意等效果会直接向受伤减免属性加值或减值。当前适配器没有将这些来源归类、取高、乘算并封顶，因此并发窗口的总减伤不可审计，也会让后续装备或团队效果难以接入。

修复要求：

1. 为 C01 定义减伤类别和职业或项目总上限。
2. 同类别取最高，跨类别乘算，再将最终结果写入单位属性。
3. 生命周期清理和共享效果回退时，重算当前有效总值而不是逐条反向相加。
4. 补充并发护守、位移减伤、守意减伤、外部团队减伤的白盒测试。

证据位置：implementation/powang/lua/powang_y3_adapter.lua 的 move_safely、contribution_fields 与 apply_contribution。

### C01-TPL-004：A08 的逐目标品级与显式控制范围

破妄目标筛选只记录第一个目标的 target_rank。A08 的控制指令没有 target_scope，适配器会回退到上下文目标集合并把主目标品级套用给其他被选中目标。矩形命中普通怪与 BOSS 混合目标时，BOSS 可能没有正确转为破韧，或普通/精英使用错误时长。

修复要求：

1. 在筛选上下文中写入 target_meta_by_id，为每个目标保存品级。
2. A08 控制明确标为 selected，并将逐目标元数据随命令传递。
3. 每个 BOSS 独立转换为破韧，普通与精英独立取得控制时长。
4. 清单增加 target_rank_resolver_bound，并补充混合目标的桥接测试。

证据位置：implementation/powang/lua/powang_y3_targeting.lua 的 build_context；implementation/powang/lua/powang_skills.lua 的 A08 控制命令；implementation/powang/lua/powang_y3_adapter.lua 的 apply_control。

### C01 的状态结论

破妄的资源循环、效果归属和离线测试仍是可复用资产，但不能在未完成上述四项前作为 v1.1 的完整桥接行为蓝本。原先的 offline-stage-accepted 只说明它满足当时的离线范围，不等于已满足后来补入的 P1 门禁。

### C01 修复后更新

四项 P1 已在离线桥接中关闭：注册和延迟任务具备生命周期隔离，回锋默认不接受未分类伤害，减伤改为类别取高后乘算并受 70% 上限约束，A08 使用显式 selected 和逐目标品级。地图侧的伤害分类、外部生命周期回调和目标品级 resolver 仍未绑定，因此不能标记 verified。

## 四、C02 镇界的反查结论

镇界是当前最接近 v1.1 的离线桥接样本，原因如下：

1. 界势在 Lv15 才显示可兑现，且 A06/A07/A08 的首级同为 Lv15，满足前期阈值邻接。
2. A05/A08 的点位缺失即拒绝结算；点位不回退到施法者脚下。
3. A04/A07 默认不从普通受伤事件产出守势，只有项目分类器确认的可格挡或有效保护才能结算。
4. A08 使用每目标元数据、本人私有界钉、explicit 子集与 BOSS 转破韧。
5. 减伤按格挡、个人、团队等类别取高后乘算，职业规格明确总上限。
6. 注册、延迟伤害、效果清理与外部命中确认都带生命周期令牌，旧回调会被拒绝。

但镇界仍有以下待真实接入门禁，不能标记 verified：

| Gate | 当前状态 | 真实接入要做的事 |
|---|---|---|
| cast_point_resolver_bound | 未绑定 | 从真实 Y3 施法事件提供同步施法点 |
| guardable_damage_classifier_bound | 未绑定 | 从首领攻击标签与伤害事件生成可格挡、有效保护判断 |
| lifecycle_callback_contract_bound | 未绑定 | 让地图侧命中/落空回调携带原生命周期令牌 |
| 生产资源门禁 | 未就绪 | 地图、脚本根、ID、图标、模型、距离尺度、模板回读 |
| C02-BAL-001 | 未执行 | 在同地图、同装备白名单的木桩与高压战斗日志中校准 90 秒输出、爆发、首绝技和生存 |

结论：C02 可以作为后续职业的**离线契约样本**，但不能替代实际地图与多人验证。

## 五、后续处理顺序

1. 先完成 C01 模板一致性修复包：生命周期、伤害分类、减伤合成、A08 逐目标品级与显式范围，并更新 C01 清单的 feature gates 和测试。
2. C02 与 C01 共用真实地图接入门禁：施法点、伤害分类、保护结果、目标品级、生命周期回调、公共 BOSS 贡献。
3. 地图接入后，在统一木桩和装备白名单下完成 C01/C02 的 90 秒、10 秒爆发、首绝技、高压存活与四人隔离日志。
4. C03 持明、C04 巡猎从 v1.1 模板开始施工；不得复制 C01 修复前的旧桥接版本。公共层只继续抽取已有跨职业实证的模块。

## 六、反查结论

模板有必要修订，且修订已完成。它把“目标归属正确”进一步细化为点位、逐目标品级、伤害资格、实际保护、生命周期和减伤合成六类硬门禁。

当前推荐关系更新为：**C01 破妄与 C02 镇界都可作为离线桥接样本；两者都还不是生产或实机样本。**
