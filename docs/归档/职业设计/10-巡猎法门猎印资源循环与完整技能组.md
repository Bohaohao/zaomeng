### 0.1 全篇身份、存档与时钟键

本篇所有 `actor_id` 均为玩家当前选定角色存档的稳定 `character_profile_id`，不是英雄 Unit ID、玩家槽位、连接 ID 或临时队伍序号。运行时实体必须以 `(actor_id, lifecycle_id, source_unit_id)` 共同定位：Unit ID 与来源引用可随死亡、跨层、重连和重注册改变，`lifecycle_id` 每次注册递增；同一角色存档回归仍使用原 `actor_id`，切换角色存档必须得到不同 `actor_id`。

所有路线选择、路线通过、一次性领取、回照候选、绝技阶级、普通绝技值和已提交的 `recovery_next_eligible_tick` 都只以 `actor_id` 为持久键。`cast_id`、目标 Unit ID、来源 Unit ID、会话 ID 与生命周期令牌只服务当次事件校验，不能替代或覆盖角色存档进度。除明确写为会话覆盖层的训练状态外，任何跨层、死亡、重注册或私有会话退出都不得让同一 `actor_id` 复用另一存档的键或提前持久绝对时钟。

本篇所有 `sync_tick` 都指项目级、权威、单调递增的 `60Hz` 时钟；地图、层、私有会话、死亡、重连和重注册均不得令它归零或改用局部 epoch。`recovery_next_eligible_tick`、首回收资格、入口 `entry_tick` 与公共事件排序必须读取同一时间源；若该时间源缺失或与事件 epoch 不匹配，本次资源提交、一次性领取或私有会话进入一律拒绝，绝不以局部 tick 换算、重置或猜测。

## 一、职业定位

| 维度 | 巡猎 |
|---|---|
| 职业代码 | `C04` |
| 法门使命 | 追踪并清除随裂隙进入六层世界的跨界残响；先辨认残响之痕，再将其从宿主外层与地脉中剥离 |
| 武器 | 灵弓；允许后续外观替换为弓、弩或符矢器，但维持远程物理投射语法 |
| 战斗距离 | 中远程，常规普攻与主击目标距离暂定 `7.5` 身位，真实 Y3 距离尺度待地图回读后校准 |
| 核心体验 | 在正确目标上维持本人私有的猎印，判断何时继续积累、何时以低层消费维持压迫、何时以五印裁决换取完整爆发与绝技进度 |
| 三条分支 | 猎首：单体锁定与裁决；逐风：位移、风筝与连射；缚影：区域压迫、软限制与多目标收网 |
| 单人价值 | 安全距离、稳定持续伤害、有限自我回复和可控的场地处理；没有护盾、净化、硬控或宠物替身作为生存捷径 |
| 团队价值 | 对选定首领或精英持续造成可预期的远程伤害，并处理小怪/落点压力；不提供团队减伤、团队护盾、团队净化、共享易伤或必带控制 |
| 明确短板 | 需要持续命中同一目标才有完整裁决；被迫频繁转火、遮挡、强位移或目标不可攻击会让猎印自然流失；短时间爆发低于贴身爆发职业 |

巡猎并不是旧天庭授予的猎官。承命者以灵弓读取裂隙残响留下的“痕”，将其钉在当前敌对目标上，再循痕回收。`C04_M01` 首先是巡猎本人建立的战斗追踪，不等于目标被道德定罪或一定遭受污染；只有遭遇侧明确标注 `trace_bearing=true` 的目标，才会把完成回收表现为剥离裂隙残响、恢复宿主或稳定地脉。其处理对象是跨界污染和失序残响，而不是任何特定种族或普通生灵；这使其能同时进入人界、四海、幽冥、天界、外天与梦墟，而不依赖旧天庭的名籍授权。

### 1.1 承命、猎痕与六层世界

| 成长节点 | 世界观含义 | 战斗含义 |
|---|---|---|
| Lv8 初识猎印 | 花果山水脉、山灵与外来潮息留下的痕迹可被承命者辨认 | 启用目标私有猎印与三条核心分支；不是获得旧天庭的册封 |
| Lv35 猎路二阶 | 承命者能分辨同一残响在不同地形中的迁移路径 | 绝技期间维持猎印，不让短暂走位直接抹掉既有追踪进度 |
| Lv55 万痕三阶 | 承命者能在六层裂隙边缘同时维持有限的追猎回响 | 绝技内的完整裁决获得有限范围回响，不改变地图规则或跨层传送规则 |

**巡猎之誓。** “先辨其痕，再问其来；能还于原处的，不以弓断之；已越界而将伤人的，我替后来者收束。” Lv8 首次识别真实潮痕时使用前半句。U01 对 `trace_bearing=true` 的遭遇目标才使用“我替后来者收束”；普通敌对目标与道统试影使用“锁痕既定，断其遁路”。首次职业引导必须解释：**审痕是审视来路，裁决是裁断裂痕，不是审判宿主；日、月、星只是行者弓术的方位与弹道术语。** 这不是玩家角色的道德审判，也不把普通敌人的猎印解释为污染判词。

| 分支 | 处事方式与短誓 | Lv8 通过回应 | 不改变的战斗定位 |
|---|---|---|---|
| 猎首 | 辨明源头后裁断最深的一道裂痕。`辨其源，断其遁。` | `已辨源：猎路可通。` | 单体裁决 |
| 逐风 | 沿迁移痕追索，不让残响借地形脱离。`循其痕，不失其踪。` | `已循痕：猎路可通。` | 位移连射 |
| 缚影 | 先划定残响不得外溢的界线，再收束其中目标。`划其界，收其溢。` | `已划界：猎路可通。` | 区域收网 |

动作语言为拉弓、定点、折步、回弦和收网。表现以青白灵羽、细金追痕、短促风线和裂隙残屑为主；不复刻原作角色形象、宠物、专属招式或标志性动作。

## 二、设计标尺与英雄成长

### 2.1 离线数值目标

- 以破妄同装备、同等级、无外部增益的 Lv60 单体 BOSS 构筑为 `100` 伤害基准。
- 巡猎 90 秒单体持续输出的离线预算为破妄的 `93%-96%`；其稳定站位与远程可用时间是交换近战爆发的价值，不是额外白送的伤害。
- 巡猎 10 秒爆发不高于破妄同条件的 `88%`；五印裁决是完整循环的高点，不应变成脱离追踪过程的一键爆发。
- 首次绝技目标为 `68.87-80` 秒；`<68.87` 秒或 `>90` 秒均视为 `C04-BAL-001` 白盒失败。该下限由统一的定猎回收资格窗口、普通攻击每目标 `2.2` 秒产印限制与动作前后摇共同保证，不能被单个技能冷却、攻速、装备、宠物或目标数量压缩。
- 巡猎不承担主破韧预算。首发技能不创建 BOSS 硬控或默认破韧；其公共 BOSS 价值首先来自合规 `final_damage`，而非绕开项目级击杀或掉落规则。

#### `C04-BAL-003-S01`：猎首裁星完整快照与输入脚本

```text
技能点：A01-A08 均为 5 级；P01/P02/P03/P04 均为 5 级；P05-P08 均未学习。A01 的 Lv1 为自动授予，但由初始化时的 `auto_allocated_skill_point=1` 预分配，**计入**本构筑的 60 点，不是额外的免费技能等级。
核算：8 个主动 × 5 级 = 40 点（含 A01 自动预分配的 Lv1）；4 个被动 × 5 级 = 20 点；合计 60 点。
五槽：A01 / A02 / A03 / A04 / A06；A05/A07/A08 虽已学满，但本样本不装配、不施放。

```

每个可行动 `sync_tick` 按下列顺序只提交第一个合法动作；未列条件、无有效主目标、冷却未就绪、前后摇未结束或资源预留不成立时跳过该项。普通攻击在所有主动均不合法时，于第一个可攻击 tick 立即发出。边界桶内的命中在该 tick 先完成排序/资源提交；若它使绝技值首次达到 `100`，且该 tick 尚未提交新动作，则只允许对 U01 进行一次 `post_resolution_U01` 重检并在同 tick 起手。该例外只能覆盖**本次已接受定猎回收来源动作**的剩余后摇，必须原子写入 `action_lock_override_source_cast_id=<本次回收来源 cast_id>`；来源 A03-A08 的命中、资源与 `finalize` 仍保持已收口状态，不取消、不回滚、不重开。该 tick 禁止第三个动作、普通攻击或任何其他主动提交。除这一命名例外外，全程不移动、不切换目标、不手动取消动作，也不使用法宝、宠物或消耗品。

1. `C04_U01`：绝技值 `100`、M11 未存活且锁定目标仍有效时立即施放。
2. `C04_A06`：主目标有本人 `5` 印、施法快照中的本人 M04 仍有效时施放。
3. `C04_A03`：静态样本只在主目标恰有本人 `5` 印、本人 M04 不存在或剩余时间不大于 `0.75s`，且本次 `begin_cast_tick` 正处于定猎回收可用窗口时施放；M11 存在时允许按同一五印条件继续施放。这个等待只定义样本输入，不改变正常玩家可在低层或资格冷却时消费的玩法；它避免把样本的首个五印消费浪费在起势门槛前，不排队也不补偿资源。
4. `C04_A01`：冷却就绪即施放。
5. `C04_A02`：冷却就绪即沿固定 +X 朝向施放；该单体只接受扇形内的静态主目标。
6. 普通攻击：按基础攻击间隔在第一个合法 tick 发出。

`C04_A04` 虽处于五槽，但在此静态单目标对照中**不施放**：它是站位工具，若把安全落点带入木桩会改变距离、行动时间和目标夹具。A04 的折步、追风箭及同 tick 窗口消费只在独立事务白盒中验收，不能混入 `C04-BAL-003-S01` 的 D90/D10 样本。

#### `C01-BAL-REF-SINGLE-v1`：破妄对照快照

这是用于本对照的冻结参考，而非由 C04 Lua 猜测出的破妄循环。它取自[破妄 BOSS 与通天塔构筑](02-破妄法门资源循环与完整技能组.md#92-boss-与通天塔)：`开锋式 / 贯心式 / 叠锋三破 / 踏虚行 / 断岳裁` 五槽均为 5 级；`回锋照影` 为 3 级；未装配的 `照妄横扫 / 定真贯阵` 各为 1 级；`P01/P05/P02/P06/P03/P07` 均为 5 级，合计 60 点。C01 的英雄数值、目标距离 `2.0`、无随机结算和 60Hz 行动规则均以[跨职业白盒战斗夹具](12-跨职业白盒战斗夹具.md)为准。

其输入优先级固定为：绝技满值时先开绝技；随后依次为“战势至少 80 时的断岳裁”、“战势至少 40 时的贯心式”、“叠锋三破”、“开锋式”和普通攻击。静态目标不产生受击或位移需求，因此不主动施放踏虚行或回锋照影；每 tick 最多一个动作，冷却、资源、前后摇和命中均按破妄现有技能契约结算。任何一方改动上述等级、槽位、站位、输入顺序或目标夹具，必须提升 fixture 版本并重新生成两方三次逐 tick 一致日志，不能混用旧基准。

| 指标 | 计算方式 | C04 通过条件 |
|---|---|---|
| `D90` | `0 <= sync_tick < 90s` 的全部已确认 `final_damage` 之和，包含合法逐痕 tick | 破妄同夹具 `D90` 的 `93%-96%` |
| `D10_peak` | 同一份 D90 日志中 `max(s=0..4800) sum(final_damage[s,s+600))`；`s` 为整数 sync tick，并列取最早窗口，包含绝技与周期伤害 | 不高于破妄同夹具 `D10_peak` 的 `88%` |
| 首绝技 | 首次合法 U01 起手的同步时间 | `68.87-80s`；早于 `68.87s` 或晚于 `90s` 失败 |

三项必须同时通过；`D90` 的远程站位价值不能用超额 `D10_peak` 交换。此处只定义离线日志口径，真实地图日志仍是后续门禁。

## 三、固定被动与资源循环

### 3.1 固定职业被动：逐痕猎诀 `C04_F01`

| 衰减 | 同一目标连续 `6` 秒未被本巡猎的合格直接命中刷新时，开始每 `1` 秒失去 `1` 层猎印；完全失去后清理该目标的私有追踪状态 |
| 目标级清理 | 敌对目标死亡/离场时，只清该 `(actor_id, target_id)` 的猎印、关联效果、预留与延迟回调；不清施法者绝技值或全局 `16.0` 秒回收资格窗口 |
| 角色/挑战级清理 | 正式副本/团本挑战开始、角色死亡、挑战失败、跨层、角色销毁与重连时，清该施法者全部临时猎印、追踪效果、绝技值、`combat_epoch_start`、`first_recovery_earliest_tick`、**未提交**回收候选/预留、临时 HUD 和延迟回调；已提交的 `recovery_next_eligible_tick` 是角色持久绝对时钟，绝不在这些路径被清除、提前或推进。私有教学会话不调用这一整套正式挑战清理：它只隔离/清理本会话状态，并按试炼规则恢复入场前的普通绝技值 |

猎印只会在资源已启用后由本巡猎的合格直接命中产生。普通攻击每个 `(actor_id, target_id)` 最多每 `2.2` 秒产生 `1` 层；A01、A02 每次施法对每个有效目标至多各产生 `1` 层。`Lv1-Lv7` 的 A01/A02 只造成其基础伤害，不生成隐藏猎印。无效目标、零实际伤害、周期伤害、反射伤害、召唤物、宠物、法宝、队友伤害、旧生命周期事件和已经离场单位均不能产生或刷新猎印。

**Lv15 绝技阶级门禁。** 角色首次达到 Lv15 时，等级系统为当前 `actor_id` 写入永久引导键 `C04_U01_TRIAL_ELIGIBLE:<actor_id>`；它不是 U01 阶级，也不占技能点或主动槽。资格键允许公开回收预演和 Lv15 私有试炼读取猎印/绝技值，但在试炼成功前 `u01_tier=0`，常规地图拒绝 U01 施法。Lv15 试炼仅在会话覆盖层内临时赋予 `u01_tier=1` 与绝技值 `100`；成功后才将永久 `u01_tier` 写为 `1`，失败、离开或死亡始终恢复入场前的 `u01_tier=0` 与普通绝技值。Lv35/Lv55 同理必须先有对应试炼资格，不能用尚未获得的阶级反向充当入口条件。

| 来源 | 猎印 | 限制 |
|---|---:|---|
| 普通攻击合格命中 | `+1` | 每目标 `2.2` 秒一次；只认本巡猎本人实际命中 |
| A01 追痕矢主击 | `+1` | 每次施放至多一次，仅锁定主目标 |
| A02 散月矢命中 | `+1` | 每次施放、每目标至多一次；最多记录 5 个被选目标 |

- 产印源（普通攻击、A01、A02）的合格直接命中只会落入三种明确结果：`added`（未满 5 印，增加 1 印并重置 6 秒衰减）、`refresh_only_at_cap`（已满 5 印，不改层数但重置 6 秒衰减）或 `rejected`（无效、旧生命周期、超出追踪上限或不匹配快照，完全不改状态）。满层刷新绝不转化为伤害、治疗、绝技值或其他资源。
- `C04_M03 逐痕` 只在 `added` 后目标达到至少 3 印时创建/刷新；`refresh_only_at_cap` 仅能刷新一个已经存在的 M03，不能凭满层命中重新创建。逐痕基础持续 `3.0` 秒、每秒造成 `物攻 × 0.12`，同源只刷新不叠层；仅当本次刷新来源为 A01 五级且命中时目标已有 `3+` 印时，持续时间额外 `+1.0` 秒。创建后首跳固定为 `effect_create_tick + 1.00s`；3 秒持续恰有第 `1/2/3` 跳，4 秒持续恰有第 `1/2/3/4` 跳。到期 tick 采用 `tick-before-expiry`：先处理该 tick 已排序的周期命中，再物理删除效果。刷新保持同一 `effect_instance_id`，但令 `effect_revision += 1`、重置完整持续时间和节拍，刷新后的首跳固定为 `refresh_tick + 1.00s`；旧 revision 的待执行 tick 一律静默失效。周期伤害本身绝不生成猎印、绝技值或其他资源。
- `C04_M03` 创建时固定写入 `effect_instance_id=C04_M03:<actor_id>:<lifecycle_id>:<combat_scope>:<scope_token>:<target_id>:<creation_sequence>`，其中 `scope_token=public` 或当前非空 `session_instance_id`；`creation_sequence` 在该施法者生命周期内单调递增，刷新不更换实例 ID。每个周期跳必须建立独立 `PeriodicTickSnapshot`：`cast_id=C04_M03_TICK:<effect_instance_id>:<tick_index>`、`phase=periodic`、`scheduled_tick=close_tick`、`hit_key=<effect_instance_id>:<tick_index>:hit`、`component_key=dot`、来源 actor/lifecycle/source Unit/引用、目标与目标生命周期、`combat_scope/session_instance_id/session_epoch`、`effect_instance_id/effect_revision` 和本 tick 冻结的 `encounter_snapshot`。只有当前效果 revision、生命周期、会话、目标与到期语义全部匹配时，`PeriodicHitEvent` 才被接受；刷新、离场、会话退出、挑战清理或来源失效后任何旧 tick 均静默。其已确认周期伤害命中遭遇侧已确认 BOSS 时，只能作为一次合规的普通伤害 `final_damage` 上报：固定 `skill_key=C04_F01`，`event_id=<effect_instance_id>:<tick_index>`，并附只供审计的 `origin_skill_key=C04_BASIC/C04_A01/C04_A02`。它绝不自行生成 `encounter_action`、破韧、保护、净化或额外参与贡献；旧生命周期、零伤害、重复事件、跨阶段复用事件 ID 或缺字段均静默拒绝。
- 多名巡猎可以标记同一目标，但 `C04_M01/C04_M02/C04_M03/C04_M04/C04_M08/C04_M10` 均按目标 ID、效果键与施法者 ID 隔离；任何巡猎都不能消费、刷新、清除或替换另一名巡猎的猎印。
- 单名巡猎最多维持 `8` 个未清理的目标追踪记录。达到上限后，对新目标的产印失败并反馈 `追踪上限`；已有目标仍可生成、消费和衰减。死亡、离场或完整清理立即释放记录位，不以静默淘汰改写玩家的目标判断。

### 3.2 消费、定猎回收与绝技值

| 技能 | 猎印消费 | 消费时机 | 成立条件 | 定猎回收资格 |
|---|---:|---|---|---:|
| A03 贯日猎矢 | 固定 `2` | 主击确认命中后 | 当前锁定主目标至少 2 个可用印 | 是，若预留时已定猎 |
| A04 风行折步的追风箭 | 固定 `1` | 追风箭确认命中后 | 折步窗口内宿主攻击的主目标至少 1 个可用印 | 是，若该主目标预留时已定猎 |
| A05 缚影钉初击 | 每个目标 `1`，最多 3 目标 | 初击逐目标确认后 | 该目标有本人可用猎印；不依赖脉冲 | 是，逐目标竞争同一次资格 |
| A06 断痕裁星 | 当前全部 `1-5` | 主击确认命中后 | 当前锁定主目标至少 1 个可用印 | 是；五印时另为完整裁决 |
| A07 逐风连弦 | 每次命中最多 `1`，最多 3 印 | 每支箭独立确认后 | 当前锁定主目标仍有本人可用猎印 | 是，首个确认正伤害且完成消费的阶段即可竞争 |
| A08 罗网猎场 | 每个目标固定 `2`，最多 3 目标 | 初击逐目标确认后 | 该目标至少 3 个可用印；脉冲不再消费 | 是，逐目标竞争同一次资格 |

`定猎回收` 是指某个目标在本次资源预留前恰有 `C04_M02 定猎`（5 层本人猎印），且 A03-A08 的一次已预留消费在正实际伤害确认后使其低于 5 层。该命中先产生无副作用的 `RecoveryCandidate`：固定 `candidate_id/recovery_event_id`、actor/lifecycle、目标/目标生命周期、来源 `cast_id + hit_key`、`accepted_tick` 与本次资格快照；只有候选通过资格校验并完成唯一提交，才成为“已接受回收”。Lv15 后，每次已接受回收且不处于绝技状态时获得 `20` 点绝技值；五次合格回收填满绝技值。普通遭遇直接在资源事务中提交；`C04-LV15-RECOVERY-INTRO` 必须把候选交给一次性领取事务，不能先发 `+20` 再补写进度。每次已接受回收原子写入 `recovery_next_eligible_tick = accepted_tick + 960`（`16.0` 秒），不受任何技能冷却、攻速、装备、宠物、法宝、目标数量或未来资源词条缩短。

- 每个角色进入一次 `combat_epoch` 时，以脱战后首个**已提交且拥有有效主目标/生命周期上下文的直接伤害 `begin_cast`** 写入 `combat_epoch_start`，不等待命中确认；未命中、被取消或伤害为零只能延后实际资源，不能重置或伪造该时钟。随后写入 `first_recovery_earliest_tick = combat_epoch_start + 252`。候选回收的唯一谓词为 `sync_tick >= max(first_recovery_earliest_tick, recovery_next_eligible_tick)`；在此之前，即使完成五印到低于五印的真实消费，也只结算伤害、印层和技能自身效果，不获得绝技值、不排队补发。`recovery_next_eligible_tick` 是角色级绝对时钟：初始为 `0`，一旦写入就跨脱战、死亡、挑战开始/失败、私有会话进入/退出、跨层、重注册和临时覆盖层保持；这些事件只清 `combat_epoch_start`、`first_recovery_earliest_tick`、未提交候选/预留、猎印/效果/回调，绝不把资格提前。例：首个合法脚本在 tick `292` 提交回收并写入 `1252` 后，即使角色死亡、跨层并在新 combat epoch 重注册，下一次回收仍不得早于 tick `1252`。私有试炼的临时 U01 和训练资源不读取、重置或推进该时钟。`252` 是从 `combat_epoch_start` 起算的持续 tick 数，不是固定绝对 tick；在 `C04-BAL-001` 中，首发 A01 的 `begin_cast=15`，故首个资格窗口实际从 tick `267 / 4.45 秒` 开始。普通攻击每目标 `2.2` 秒产印限制和冻结输入脚本仍使首个可消费五印落在 tick `292`，因此首绝技真值仍为 `68.87s = 4.87 + 4 × 16.0`。它不允许被攻速、冷却、装备、宠物或多目标压缩。公共野外 BOSS 不等同“挑战开始”，不会强制清除已存在的猎印或绝技；`C04-BAL-001/002/003` 另行明确从零资源起算。

- 定猎回收只认每次 5 层到低于 5 层的第一笔已确认消费。A05/A08 的 `CastSnapshot` 可带一个施法时冻结的 `recovery_candidate_target_id`：它必须属于本次初击 `selected`、预留时带本人 M02 且通过正伤害/生命周期校验；满足时由该点选/锁定目标优先获得本次回收候选。未声明、声明目标不合法或声明目标未形成可接受候选时，才按首次有效命中时间、距离、Unit ID 稳定回退选一名。其余目标照常消费和受伤，但不排队、不补发绝技值；施放后改变主目标或 UI 选中态不能改写这个快照。
- 预留后取消、目标不存在、实际伤害不大于 `0`、命中事件来自旧生命周期、目标不再匹配快照或资格窗口未就绪时，不得结算绝技值。资格窗口未就绪时，已命中的消费仍可造成技能效果，但 UI 必须显示剩余资格时间。
- A06 的 `完整裁决` 仍指预留时恰有 5 印、确认后完整消费 5 印；它获得最高单体倍率和 P03/P04 兑现，但不再独占绝技充能。A04/A07 保持位移连射路线，A05/A08 保持区域收网路线，三条分支均可通过自己已装配的消费技能完成定猎回收。
- 绝技开启后，`C04_U01` 持续期间的定猎回收仍可造成伤害与触发绝技内效果，但不获得绝技值。绝技值不得在绝技窗口内自充。

### 3.3 `C04-BAL-001` 的 90 秒循环草案

前提：Lv60 裸装、持续可攻击的单目标、无外部增益、已学习一条核心分支和其消费技能；普通攻击、A01/A02 为实际命中。所有 A03-A08 只在 5 印定猎被真实消费后竞争一次全局回收资格，不能由多目标或低层空放伪装为资源来源。

| `tick 132 / 2.20 秒` | 普攻起手并同 tick 确认 | 猎印 `3`；该目标下一次普通攻击**可产印**不得早于 tick `264`，普通攻击本身仍可按攻击间隔造成伤害 |

| `tick 265 / 4.42 秒` | A03 起手 | tick `292 / 4.87 秒` 确认消费；第一次定猎回收，绝技值 `20`；写 `recovery_next_eligible_tick=1252` |

### 3.4 关键倍率与取整口径

所有下列系数先以浮点完整结算，只有进入最终伤害桥接时才按项目统一规则取整，禁止在每印、每脉冲或每个被动层级提前截断。

- **A06 断痕裁星：**令 `n` 为实际确认消费的本人猎印数，`B` 为当前等级主击系数，`C` 为当前等级每印系数，`p04` 为当前等级 P04 的每印主击百分比。基础系数固定为 `B + n × C`；主击倍率固定为 `1 + n × p04`。只有目标仍带本人 `C04_M04 贯痕` 时，该倍率再加 `0.15 + p03`，其中 `p03` 为当前等级 P03 的主击增伤；没有贯痕时 P03 不生效。最终系数为 `(B + n × C) × (1 + n × p04 + has_M04 × (0.15 + p03))`。五印 A06 且 P04 五级因此固定获得 `30%` P04 主击倍率，不再存在“只加基础段”或“额外乘一次”的解释空间。
- **A08 罗网猎场：**令 `n` 为某一目标本次初击实际消费的本人猎印数，`B` 为初击系数，`C` 为当前等级低层收网每印追加，`p08` 为当前等级 P08 每印追加。该目标初击系数固定为 `B + n × (C + p08)`；没有实际消费时 `n=0`。最后一脉冲仅在该目标仍带同源 `C04_M10 绞猎` 时，追加 `0.18 + p08_master`，其中 `p08_master=0.35` 仅在 P08 五级时成立。绞猎、P08 和脉冲不再二次按印结算。

#### 4.1.1 动作、命中与截止事务时钟

所有时序以 `60Hz sync_tick` 表示；`start_tick` 只可在前一动作后摇结束且本 tick 没有其他动作提交时创建，冷却从 `start_tick` 开始计。除 A02 这类明确声明飞行候选期的技能外，直接伤害主动的 `begin_cast_tick=start_tick+前摇` 且 `close_tick=begin_cast_tick`：桥接先完整收集该 close tick 的边界桶，再按 `impact_sequence -> hit_key` 稳定排序、接受匹配命中并 `finalize_cast`；更晚事件只能释放预留或静默。后摇结束 tick 是下一次主动可提交的最早 tick。唯一例外是 `post_resolution_U01`：仅当已收口的定猎回收使绝技首次达到 `100` 时，才可在其 close tick 覆盖该**来源动作**的剩余后摇，并写入 `action_lock_override_source_cast_id`；来源事务不得被取消、回滚或重开，该 tick 也不得提交第三个动作。

### 4.2 关键施法、命中与失败路径

#### `C04_A01` 追痕矢

- `primary` 指向，施法提交时锁定 `primary_target_id`；缺失主目标拒绝施放，不从扇形候选替代。
- 仅当前生命周期、正实际伤害且命中锁定主目标的事件才造成一层猎印并刷新追踪；命中落空不生成。
- A01 是单目标稳定入口，不承担范围清怪或异常爆发。

#### `C04_A02` 散月矢

- 使用同步施法朝向的扇形几何；前摇结束的 `begin_cast` tick 即为 `launch_tick`，固定 `close_tick = launch_tick + 1.20s`。首次有效命中记录先存入候选池；`sync_tick < close_tick` 的候选按常规收集，`sync_tick == close_tick` 的候选进入边界桶并按首次命中时间、路径距离、Unit ID 排序，桶处理完立即 `finalize_cast`；更晚事件静默丢弃。`finalize_cast` 才按同一排序取最多 5 名作为本次不可变 `selected` 快照。
- 只有该最终 `selected` 快照内的每名目标获得一层猎印；同一目标不会因为多支箭、晚到回调或回调重放得到多层猎印，结算后到达的命中静默丢弃。
- 目标越多只增加可被追踪的对象数，不增加单目标猎印上限、完整裁决资格或绝技充能速度。

#### `C04_A03` 贯日猎矢

- 仅对施法时锁定的 `primary` 结算。命中前在快照中预留两印，只有确认正实际伤害后才真正消费。
- 少于两印、目标死亡、目标替换、旧生命周期或落空均不扣印、不添加贯痕、不产生替代目标。
- 确认命中后创建或刷新本人 `C04_M04 贯痕`：基础持续 `5.0` 秒，P03 在此基础上增加 `0.5-2.5` 秒；同一来源重施只重置为当前完整持续时间，不叠层、不把剩余时间相加。A06 在施法快照中记录 `has_own_M04` 与到期 tick；命中时仅当该同源贯痕仍有效才兑现 M04/P03 加成，施法后才新增或刷新的贯痕不得回填本次 A06。
- 贯痕是本人私有的单体收益；它不能改写目标对队友的防御、易伤或破韧状态。

#### `C04_A04` 风行折步

- 需要同步施法方向与项目级安全落点结果；方向或合法落点缺失时不移动、不创建风行窗口。
- 成功折步后 4 秒内，风行窗口本身不绑定目标。本人的下一次普通攻击或 A01 已确认命中后，追风箭继承该宿主攻击自身的 `primary_target_id`；若该主目标至少一枚可用印，追风箭才预留并消费 1 印、追加伤害。
- 追风箭不生成猎印；若宿主攻击的主目标在预留前已定猎，它可按 3.2 节竞争一次回收资格。窗口到期、角色死亡、挑战失败、跨层或来源失效即清理。
- M05 创建时写入唯一 `window_id`。普通攻击与 A01 的 `begin_cast` 只可快照当时仍存活的 `m05_window_id`；每个候选宿主命中只能尝试自己快照中的窗口，绝不能在命中时读取或抢占重施后的新 M05。候选先通过常规正伤害确认，再原子调用 `claim_wind_window(m05_window_id, hit_key)`；同一同步 tick 的候选按 `cast_sequence -> phase -> sync_tick -> impact_sequence -> hit_key` 排序。首个合法候选把 `consumed_by_hit_key` 固定为自己的 `hit_key` 并立即清理 M05：有可用印时结算追风箭，无可用印时只结束窗口；同 tick 或更晚的候选看到已消费、过期或非当前快照窗口后只保留自身常规伤害，绝不再追加或消费。零伤害、旧生命周期、非宿主主目标和重复 `hit_key` 均不能抢占窗口。

#### `C04_A05` 缚影钉

- 需要权威 `cast_point`；缺失、过期或不可用点位时拒绝本次结算，绝不回退到施法者脚下。
- 初击在施法点建立本次最多 5 名目标的 `selected` 快照，并为每名候选冻结 `has_own_M08_pre_hit`。其中按“本人猎印层数降序、距离、Unit ID”排序后的前三名已带本人猎印目标各预留一印；确认命中后才消费并获得本人私有猎网。P07 的“命中本人猎网目标”只读取该 `has_own_M08_pre_hit=true` 快照，A05 本次新建/刷新 M08 不得反向满足 P07。后续三次脉冲严格按 `t=0.60 / 1.20 / 1.80` 秒重新调用 `resolve_pulse_targets` 并最多处理 5 名目标，没有 Hook 或空集合则命中空集合；重施必先取消旧场，不能把剩余脉冲叠入新场。
- 每个确认命中的初击目标创建或刷新本人 `C04_M08 猎网`：基础持续 `4.0` 秒，P07 在此基础上增加 `0.5-2.5` 秒；同一来源重施只重置完整持续时间，不叠层、不累计。A08 只读取其施法快照中已存在、且命中时仍有效的同源 M08；A05 在 A08 施法后才建立的猎网不得回填本次 A08，A08 本身不消费或刷新 M08。
- 只有 A05 **初击**的 `normal/elite` 确认命中可创建或刷新软限制 `C04_M07`；后三次脉冲只造成伤害与 M08 分支互动，绝不创建、刷新或延长 M07。`boss` 与 `unknown` 只承受通用伤害和允许的本人私有标记，不得到减速、控制或破韧转换。

#### `C04_A06` 断痕裁星

- 仅消耗当前锁定主目标的本人猎印；提交时保存可用层数、目标和定猎状态，确认命中时按快照层数一次性消费。
- 五印完整裁决保留最高单体伤害与自身被动兑现。它与 A03/A04/A05/A07/A08 一样，只在目标预留时已定猎且全局资格窗口可用时推进一次绝技；资格窗口未就绪不影响本次伤害。
- 目标 rank 不改变 A06 的伤害或绝技逻辑；该技能不创建 BOSS 破韧、团队易伤或公共奖励捷径。

#### `C04_A07` 逐风连弦

- 施法时锁定主目标，依次发出三支箭；每支箭都有独立 `phase`、命中、预留、`hit_key` 与 `phase_close_tick`。相位 `1/2/3` 分别在 `t=0.35 / 0.80 / 1.25` 发射，权威 `phase_close_tick` 分别为本相位发射 tick 后 `1.20` 秒；因此整次 A07 的最终 `close_tick` 为施法起点后 `2.45` 秒。
- 提交时按可用猎印预留最多三枚并依序分配给三段。每段最多消费一印，任何一段落空或超过本相位截止只释放该段预留，不让后续命中回退到其他目标；首个确认正伤害、且以定猎状态完成消费的阶段可竞争一次回收资格，因此第一段落空、第二或第三段有效命中时仍可按同一规则竞争。
- 每个 `phase_close_tick` 必须调用 `finalize_phase(cast_id, phase, phase_close_tick)`：`sync_tick < phase_close_tick` 的合法事件按常规接受；`sync_tick == phase_close_tick` 的匹配事件先进入边界桶，按 `impact_sequence -> hit_key` 完整排序并逐个接受，再关闭本相位；`sync_tick > phase_close_tick` 一律迟到拒绝。收口只释放本相位未确认预留，不能终止其他两段。最终相位关闭后再 `finalize_cast` 并删除 M06。延迟箭矢必须校验 `actor_id + lifecycle_id + cast_id + phase`；角色死亡、挑战失败、跨层、重注册或移除后旧箭矢静默失效。

#### `C04_A08` 罗网猎场

- 需要权威 `cast_point`；初击的 `selected` 快照按距离、Unit ID 稳定排序，最多处理 6 名目标，其中最多三名满足至少三枚可用印的目标各预留两印。预留时为五印定猎且确认命中的目标获得本人 `C04_M10 绞猎` 4 秒；绞猎目标的最后一脉冲额外造成 `0.18 + p08_master` 系数，其中 `p08_master=0.35` 仅在 P08 五级时成立。
- 本次初击的 M08 分支条件以 `begin_cast` 的 `has_own_M08` 快照为准，并在命中时校验同源 M08 尚未到期；施法后新增/刷新、另一名巡猎的 M08 或已到期状态均不得参与本次结算。
- A08 **初击**的 `normal/elite` 确认命中可创建或刷新自己的 C04_M07 来源记录；`boss/unknown` 永不创建。四次脉冲严格按 `t=0.70 / 1.40 / 2.10 / 2.80` 秒每次重新生成最多 6 名目标的 `selected` 快照，仅造成伤害与已成立猎网/绞猎的分支互动；脉冲不得消费猎印、不得生成猎印、不得推进绝技，也不得创建、刷新或延长 M07。重施或来源失效后，所有旧脉冲静默丢弃。
- A08 没有硬控、BOSS 破韧、团队增益或净化语义。它的价值是多目标节奏与本人私有收网，而不是替代镇界或持明。

#### Lv15 回收预演只读 UI 契约

公开的承命回照石只在 Lv15 获得 `C04_U01_TRIAL_ELIGIBLE:<actor_id>`、且任一核心主动至少 1 级后提供一次低压、无奖励的真实回收预演；它不要求 `u01_tier`。回照靶固定逻辑键为 `C04_PRACTICE_TARGET`，是对技能筛选显式可攻击的**被动敌对 normal 训练靶**：`normal` 仅用于技能筛选，不能产生公共控制、破韧、伤害贡献或原生生命变化；它没有主动攻击、仇恨、公共碰撞、掉落或贡献，稳定 Unit 生命周期不可死亡。它为至多四名玩家提供按 `actor_id` 分离的虚拟受击量与猎印视图，任何人的命中都不减少他人的可用性。“真实回收”只表示同一套施法、命中、五印预留、消费和资格状态机被权威逐项验证，不表示改写公共靶的生命或向公共账本上报伤害。HUD 固定显示 `5印 0/5 -> 消费 -> 回收 +20 -> 绝技试炼 0/1`；只有该回照靶上已接受的回收能写入 `C04_REAL_RECOVERY_INTRO:<actor_id>`，完成后显示 `真实回收已完成：前往道统石台` 并给出入口方向。它不能提供经验、掉落、材料、可重复绝技值或公共 Boss 贡献；已完成的角色只看到方向提示，不再从该节点获得资源。

**公开回照领取事务。** 每个角色的回照进度只允许 `unclaimed -> pending(claim_id) -> claimed`：`confirm_practice_hit` 先创建尚未发奖的 `RecoveryCandidate`，`candidate_id=C04_RECOVERY_CANDIDATE:<actor_id>:<lifecycle_id>:<cast_id>:<phase>:<hit_key>`，并令 `claim_id=C04_RECOVERY_CLAIM:<actor_id>:<candidate_id>`。候选必须来自同一角色当前生命周期、`combat_scope=public/session_instance_id=nil/session_epoch=nil`、`target_logic_id=C04_PRACTICE_TARGET`、正数权威训练伤害、五印降层、资格时钟可用且不在 U01 的一次接受命中；候选创建本身**尚未**获得 `+20`、M12、进度或资格时钟。权威 Compare-And-Set 先写 `pending`，随后在同一幂等事务中一次提交：正常定猎回收 `+20`、`recovery_next_eligible_tick=accepted_tick+960`、`C04_REAL_RECOVERY_INTRO:<actor_id>`、可用时的 M12 结算和该角色对回照靶的 `claimed_read_only` 封存。重复命中、旧生命周期、第二个同 tick 候选或已 claimed 角色均不再产生印、回收、治疗、冷却改变或进度。`pending` 生命周期失效、来源不匹配或提交前被拒绝时回滚为 `unclaimed`，不写资源或资格时钟，并只向发起者显示 `回照未记录，请重新完成`；已提交的 `claim_id` 仅可幂等重读，绝不二次发放。完成文字只对发起者可见，其他人只保留中性石台回响。

**`C04_PRACTICE_HIT_V1`。** 回照靶的原生生命不接受伤害写入；有效技能命中由遭遇权威拦截并为该 `actor_id` 的虚拟靶状态生成 `PracticeHitEvent`，再由唯一的 `confirm_practice_hit` 桥接进入 C04 资源状态机。事件必须含 `actor_id`、`character_profile_id=actor_id`、`lifecycle_id`、`source_unit_id/引用`、`cast_id`、`phase`、`hit_key`、`sync_tick`、`target_logic_id=C04_PRACTICE_TARGET`、稳定 `target_unit_id/target_lifecycle_id`、`target_rank=normal`、`rank_policy=skill_filter_only_no_public_control_break_or_contribution`、`combat_scope=public`、`session_instance_id=nil/session_epoch=nil`、`event_category=public_training_noncombat`、正数 `practice_damage_dealt`、`native_health_delta=0` 和 `virtual_vitality_revision`。普通 `confirm_hit` 不接受该事件，练习桥接也绝不生成 `final_damage`。它不得写公共生命、仇恨、掉落、普通怪死亡、公共控制、破韧、Boss 贡献或公共奖励。四名玩家的虚拟生命、猎印、候选、领取和完成读写均以 `actor_id` 隔离。

`public_training_noncombat` 只允许来自当前稳定的 `C04_PRACTICE_TARGET`，不启动或刷新 `public_combat_lock`。在 `C04_PUBLIC_COMBAT_IDLE_GATE` 中，它只能作为**同 tick 的待结算排除项**：仅当 `entry_tick == PracticeHitEvent.sync_tick`，且门禁以 `(actor_id,lifecycle_id,hit_key)` 回查到已接受的 `C04_PRACTICE_HIT_V1`，再同时核验 `character_profile_id=actor_id`、`source_unit_id/source_unit_ref`、`target_logic_id=C04_PRACTICE_TARGET`、目标 Unit/生命周期、`combat_scope=public`、空 session 与 `event_category=public_training_noncombat` 后，才可让该**同一事件**不触发 `pending_public_hit_projectile_or_periodic` 拒绝；该排除只服务 `C04_TUT_LV15_U01`，不写通行状态、不跨 tick 保存，也不能掩盖公共仇恨、Boss 参与、公共投射/周期、非练习公共伤害或公共受伤。后续 tick 本就按普通 idle 门禁处理，因为练习事件不产生公共战斗锁。该例外不适用于任何普通怪、精英、残响、Boss、私有目标或未来训练靶。

**起手与二阶段回弦事务。** 起手主击和两枚开场回弦分别建立 `cast_id=C04_U01_OPEN:<u01_cast_id>:main|rebound_<ordinal>`、`phase=opening_main|opening_rebound`、`close_tick=min(u01_close_tick, u01_start_tick+0.80s)` 的独立事务；`opening_main` 只接受锁定快照主目标，`opening_rebound_<ordinal>` 只接受同 ordinal 的冻结 `opening_rebound_selected` 目标，二者都不能改向当前主目标或重新筛选。每个命中以各自 `hit_key + component_key` 生成普通 `C04_DMG` 贡献。二阶段只在 `sync_tick < u01_close_tick`、M11 属于当前 `actor_id + lifecycle_id`、锁定主目标引用仍存在、存活且距离不超过 `7.5` 身位时处理。桥接在每个 tick 先收集 A01-A08 的首个已接受直接命中候选，再按 `sync_tick -> impact_sequence -> hit_key -> skill_key` 排序；前四个不同技能键原子占用 `stage2_reacted_skill_keys`，第五个及以后键静默不触发。某键一旦被首个候选占用，即使锁定目标在该时刻失效也不得由第二组件或晚到事件补发。每个成功候选建立 `reaction_cast_id=C04_U01_R2:<u01_cast_id>:<reaction_sequence>`、`reaction_key=C04_U01:<u01_cast_id>:<trigger_hit_key>:<component_key>`、`phase=stage2_reaction`、`close_tick=min(u01_close_tick, trigger_tick+0.80s)` 的单目标事务；只允许命中 U01 锁定对象，命中事件再按完整 `C04_DMG` 键上报。目标死亡、离场、超距、U01 到期、旧生命周期、重复键或当前主目标变化时静默失败且绝不改向新主目标。

**三阶段回弦事务。** 每次已确认的定猎回收必须生成唯一 `recovery_event_id=C04_RECOVERY:<actor_id>:<lifecycle_id>:<cast_id>:<phase>:<hit_key>:<target_id>`。M11 在同 tick 内按 `sync_tick -> cast_sequence -> phase -> impact_sequence -> hit_key -> target_id` 排序回收事件，前 3 个未使用 `recovery_event_id` 各占用一次三阶额度；没有目标筛选 Hook 时额度仍被占用但命中空集合。每个额度建立 `reverb_cast_id=C04_U01_R3:<u01_cast_id>:<recovery_event_id>`，以该回收目标确认时位置为中心重新生成最多 4 名敌对 `selected` 目标（包含中心目标，按距离、Unit ID 排序），`phase=stage3_reverb`，`close_tick=min(u01_close_tick, recovery_tick+0.60s)`。每个目标都必须独立确认命中并使用 `component_key=stage3_reverb_<ordinal>` 的完整 `C04_DMG` 事件；三阶回弦不生成或消费猎印、绝技值、控制、破韧或团队收益。M11 到期、死亡、挑战失败、跨层、重注册或销毁时，所有未完成的 opening、reaction、reverb 事务均按生命周期静默失效。

**冻结倒计时同 tick 规则。** U01 期间所有 M01 生成、满层刷新、消费与清理事件先按 `sync_tick -> cast_sequence -> phase -> impact_sequence -> hit_key -> target_id` 排序后逐项执行；每次生成/刷新立即更新该目标的 `frozen_decay_by_target`，随后的消费只改变猎印层数。绝技结束时只写回该排序后的最终 `remaining_tick`，不复活已删除记录。这样“同 tick 刷新后消费”与“消费后刷新”都有唯一结果，也不会让刷新后的 6 秒在 U01 结束时被旧快照覆盖。

绝技结束时不清空仍存在的猎印；被冻结的衰减计时器按原剩余时间继续，定猎回收资格与绝技值从真实状态继续。角色死亡、挑战失败、跨层、重注册和销毁时立即失效绝技、回弦计数和所有延迟箭矢。

### 9.1.1 施法快照、预留与幂等事务

`begin_cast(snapshot)` 只能建立待结算记录。投递索引固定为 `cast_registry_key=(actor_id, lifecycle_id, cast_id)`；`cast_id` 只要求在该角色生命周期内唯一，桥接不得把裸 `cast_id` 当作全局键。普通攻击也必须先建立 `cast_id=C04_BASIC:<actor_id>:<lifecycle_id>:<attack_sequence>`、`phase=basic` 的快照。每个 `CastSnapshot` 固定保存：`actor_id`、`lifecycle_id`、`combat_scope`、`session_instance_id`、`session_epoch`、当前 `source_unit_id` 与对象引用、`cast_id`、`cast_sequence`、`skill_key`、`phase`、`primary_target_id`、`target_refs_by_id`、目标生命周期映射、`team_id`、`team_target_ids`、`cast_point`、`direction`、`selected_target_ids`、A05/A08 的 `recovery_candidate_target_id`（施法时点选/锁定的有效五印目标或空）、稳定排序元数据、逐目标猎印快照、逐目标预留数量、接受过的命中键、`close_tick`、A07 专用 `phase_close_ticks[1..3]` 与 `finalized` 标记。public 快照的 session 字段必须为空，private 快照必须等于当前角色获得授权的非空 session ID/epoch；二者不能互相转写。U01 额外保存 `u01_cast_id`、锁定主目标 ID/引用/生命周期、`u01_start_tick`、`u01_close_tick`、阶段二技能键占用集与反应键集。C04 没有 `team` 目标技能，仍必须保留该上下文以满足公共快照契约；其唯一合法行为是完全不读取团队成员来产生效果。`HitEvent` 固定包含：`actor_id`、`lifecycle_id`、`combat_scope`、`session_instance_id`、`session_epoch`、`source_unit_id`、来源对象引用、`cast_id`、`phase`、`target_id`、目标生命周期、唯一 `hit_key`、本次伤害组件唯一 `component_key`、`impact_sequence`、`sync_tick`、`damage_dealt`、`hit_time`、`path_distance`、`target_rank`、`target_rank_epoch`、`alive` 与生命周期令牌；对已确认 Boss 命中，桥接在接受时追加不可变 `encounter_snapshot={boss_instance_id, phase_id, target_id, target_lifecycle_id}`。周期效果使用同样来源、目标和会话字段的 `PeriodicTickSnapshot/PeriodicHitEvent`，但不借用任一已关闭的施法事务。

1. 预留只从同一 `(actor_id, target_id)` 的**可用猎印**中扣出，仍不改变已结算层数。并发施法按 `cast_sequence -> phase -> sync_tick -> impact_sequence -> hit_key` 裁决；先成功预留者占用，后来者收到 `猎印预留中` 且不得偷用同一层。
2. `confirm_hit(event)` 先用 `(actor_id, lifecycle_id, cast_id)` 定位事务，并核验 event 的 actor、生命周期、`combat_scope/session_instance_id/session_epoch`、`source_unit_id` 与来源对象引用仍等于 `CastSnapshot` 和当前角色上下文；随后才接受当前生命周期、当前会话、未 final、匹配 cast/phase、目标/目标生命周期仍匹配、`damage_dealt > 0`、非空 `component_key` 且未接受过的 `hit_key`。若命中 BOSS，权威遭遇侧必须在这一刻绑定 `encounter_snapshot`；确认后的资源、派生伤害与 `final_damage` 都只能引用该快照，不能在延迟回调或事件上报时读取“当前阶段”。A07 对 `sync_tick < phase_close_tick` 按常规处理；`sync_tick == phase_close_tick` 必须先由桥接收集同相位边界桶，按 `impact_sequence -> hit_key` 排序后逐项处理，再调用 `finalize_phase`；`sync_tick > phase_close_tick` 绝不接受。该事件才把对应预留变成真实消费，并按 3.2 节决定定猎回收、效果和合规最终伤害。
3. `confirm_practice_hit(event)` 只服务 `C04_PRACTICE_TARGET`：它重用 `confirm_hit` 的 actor、来源 Unit/引用、cast、phase、目标生命周期、唯一 `hit_key`、会话和 close tick 校验，但必须额外满足 `event_category=public_training_noncombat`、`target_logic_id=C04_PRACTICE_TARGET`、`practice_damage_dealt>0`、`native_health_delta=0` 与当前 `virtual_vitality_revision`。通过后可将预留变成真实消费并按 3.2 节创建 `RecoveryCandidate`；它绝不创建 `final_damage`、公共仇恨、掉落或 Boss 贡献，且只能走 5.2 的 CAS 提交路径。
4. `finalize_phase(cast_id, phase, phase_close_tick)` 是 A07 的必经收口：只有本相位的 `< close_tick` 已接受事件和完成排序的 `== close_tick` 边界桶可提交，随后只释放该相位未确认预留；任何迟到、取消、落空、目标死亡、重复事件、缺字段或过期生命周期均静默，不得影响另两段。
5. `finalize_cast(cast_id, close_tick, source)` 固定本次结算截止 tick 与来源；只接受 `sync_tick < close_tick` 的事件，边界 `sync_tick == close_tick` 按 `impact_sequence -> hit_key` 接收后再 finalize。A01/A02/A03/A05/A06/A08 的直接段与 A04 landing 均使用该收口，A05/A08 的逐目标预留在各自初击确认后独立提交，所有脉冲又各自建立新事务；A07 必须在三次 `finalize_phase` 后以第三段截止收口。之后的事件只释放/静默，不补发资源。
6. A02 的 `selected` 在带 `close_tick` 的 finalize 时从候选首次有效命中生成；A05/A08 的初击 `selected` 在施法点提交时生成；A05/A08 的后续脉冲每次重新生成 selected。所有效果、伤害、清理与任何未来控制命令必须显式写明 `target_scope`，禁止依赖 `context.targets`。
7. 每个由已接受 `HitEvent` 产生的直接或派生伤害组件都必须有自己的 `cast_id`、`phase`、`close_tick`、`hit_key` 与唯一 `component_key`，并只可生成 `event_id=C04_DMG:<actor_id>:<lifecycle_id>:<cast_id>:<phase>:<hit_key>:<component_key>`；普通攻击使用上述单调 `C04_BASIC` cast ID。`event_origin_index[event_id]` 固定写入已接受事件的 `(combat_scope, session_instance_id, session_epoch, boss_instance_id, phase_id, target_id, target_lifecycle_id)`；同一完整事件 ID 试图写入另一会话、Boss 阶段、目标生命周期或第二次时均静默拒绝。M03 周期 tick 只使用其独立的 `<effect_instance_id>:<tick_index>` 格式并同样写入这个索引。公共 BOSS `final_damage` 只能由 `combat_scope=public/session_instance_id=nil` 的 accepted hit 或 tick 上报；private session 不得写入公共 Boss 账本。没有已接受命中、缺任一字段或复用完整事件 ID 时不得上报 `final_damage`。

### 9.2 公共 BOSS 贡献边界

巡猎只上报遭遇侧在命中接受瞬间冻结的 `final_damage`。公共 Boss 事件强制 `combat_scope=public`、`session_instance_id=nil`、`session_epoch=nil`，并至少包含 `kind`、`event_id`、`actor_id`、`lifecycle_id`、`boss_instance_id`、`phase_id`、`target_id`、`target_lifecycle_id`、合法 `skill_key` 与正数 `value`；其中 Boss/阶段/目标字段必须逐项等于该 accepted hit 或 accepted periodic tick 的 `encounter_snapshot`，不能由上报端重新查询。遭遇层先按 `(boss_instance_id, phase_id, event_id)` 去重，并维护全局 `event_origin_index[event_id]`；相同 ID 若随后带不同会话、boss、阶段、目标或目标生命周期，一律作为跨会话/跨阶段/跨目标重放静默拒绝。普通攻击使用 `C04_BASIC`，主动使用各自 `C04_A01-A08/C04_U01`，逐痕 tick 唯一使用 `C04_F01`；所有直接伤害必须采用 `C04_DMG:<actor_id>:<lifecycle_id>:<cast_id>:<phase>:<hit_key>:<component_key>`，M03 只能采用 `<effect_instance_id>:<tick_index>`。其他键、零值、缺字段、旧生命周期、私有会话、跨阶段复用或重复事件均静默拒绝。猎印层数、定猎、空放、未命中、周期状态存在本身或 UI 预测均不得被伪装为贡献。

`C04_M03` 只有确认命中 BOSS 的单个 tick 可以写入普通伤害贡献，事件键固定为 `<effect_instance_id>:<tick_index>`，其中 `effect_instance_id` 已含效果键、actor、生命周期、scope/session、目标与创建序号；它不会产生 `encounter_action`、破韧、保护、净化或额外参与资格。花果山公共 Boss 的 `encounter_action_key` 由地图侧的公共行为矩阵上报，巡猎只消费结果，绝不自行记账或补发。
公共行为的窗口、半径、读条、并发、失败重试、协同确认和事件载荷以[花果山公共行为执行矩阵](../../08-花果山篇野外怪物与BOSS设计.md#公共行为执行矩阵)为唯一来源；C04 不得复制、改写或绕开该矩阵。

花果山公共 BOSS、龙宫单人本和火焰山团本都可以接受巡猎的合规最终伤害；公共 BOSS 的主归属、同队 DPS 大于 10% 同步击杀、个人有效参与通关和稀有掉落资格仍由项目级规则决定。对主线、篇章入口、保证性收集和角色首次通关，`个人有效参与通关` 的唯一门槛是本阶段完成一次权威 `encounter_action_key` 且在该事件时处于有效 Boss 战斗范围/生命周期，或达到至少 `3%` 有效伤害；二者均可写角色个人进度，队长、最高 DPS、同队成员或全服状态不得代领。同步击杀只保留队伍战绩、公告、称号或非关键记录，稀有掉落/保底另依资源表结算。巡猎没有专属必经 BOSS 机制，避免让第四职业变成团本门票。
