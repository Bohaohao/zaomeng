## 一、适用边界与固定骨架

每个首发职业必须独立完成主线、单人本与通天塔。团队保护、净化、控制、护盾、破韧或减伤只能提高队伍效率，不能成为唯一通关钥匙。

固定结构：

1. 1 个固定职业被动。
2. 8 个可学习主动：2 个基础、3 个核心分支、3 个进阶分支。
3. 8 个可学习被动：2 个共同、三个分支各 2 个。
4. 1 个三阶职业绝技。
5. 5 个可装配主动槽，以及独立绝技、闪避、法宝槽。

主动与学习型被动均为 5 级；绝技在 Lv15、Lv35、Lv55 通过道统试炼升至 3 阶。技能树容量、自由技能点、前置关系和五槽规则沿用上位基线。

## 二、职业设计必填项

| 项目 | 必填内容 | 验收要点 |
|---|---|---|
| 战斗身份 | 武器、攻击距离、三分支、单人价值、团队价值与明确短板 | 不与已存在职业重复核心循环；团队收益先保证自身收益 |
| 资源与绝技 | 上限、来源、消耗、阈值、衰减、死亡/入本/跨层清理、首绝技目标 | 可写出 60-90 秒循环表，且无自伤、周期伤害、无敌目标刷资源 |
| 前期闭环 | Lv1-Lv20 的首级解锁、教学场景、五槽更替和阈值提示规则 | 每个可见阈值在可使用时已有至少一个可学习的消费或兑现手段 |
| 玩家反馈与公平兼容 | 生成、刷新、预留、消费、拒绝、追迹中断、冷却和高压预警的可读反馈；商业字段允许/禁止/待实验表与零付费基线 | 结果不靠颜色单独表达；高压攻击有可复核的预警、方向/落点和安全线；零付费 Lv60 基线可通过本职业 BAL 测试 |

| 构筑 | 清怪、BOSS/塔、团队三套 Lv60 示例 | 至少两种轮换差异明确，且每套都遵守五槽规则 |

### 2.1 前期阈值邻接门禁

1. 对每个派生阈值列出：显示等级、首次达到时的意义、最早消费技能、最早可学习等级、技能槽内推荐替换。
2. 最早消费等级不得晚于阈值会向玩家显示“可兑现”的等级；否则阈值必须隐藏、降级为纯数值状态，或补入低等级兑现手段。
3. 前 20 级需要写清第一次命中、第一次资源消费、第一次防御或控制、第一次构筑替换分别由何处教学。
4. 不把“可学习”误写成“自动拥有”；自由技能点和五槽限制必须仍然生效。
5. 任意限时教学或副本通行门禁必须声明角色私有的倒计时、临期预警、成功、每种失败原因、回入口/重试行为，以及未通过时的 `0/1` 门禁进度；公共目标、队友或叙事结果不得让玩家在无反馈下被阻断或代完成。
6. 私有教学必须区分 `preview_trigger=first_enter` 与 `entry_trigger=explicit_interact`；入口必须声明等级、已学技能、路线/前置进度、拒绝原因和会话开始条件。临时教学资源只能在权威门禁全部通过后发放，预览、拒绝或误入均不得创建尝试序号或改变资源。
7. 自动装配、赠送或预分配的技能等级必须明确是否占用技能等级预算；职业的 Lv60 点数表、技能树 UI 和构筑样本必须采用同一答案。
8. 道统试炼若产出永久技能或绝技阶级，必须拆分“等级解锁的试炼资格键”“会话内临时阶级”和“成功后永久阶级”。入口和公开前导只能检查资格键与必要进度，绝不能要求本次试炼要授予的永久阶级；成功、失败、退出分别写入或恢复的状态必须唯一。
9. 任何会反复发放资源、治疗或进度的时间窗口都必须声明角色级 `next_eligible_tick`（或等价绝对时钟）、严格比较谓词和边界 tick；该绝对时钟必须使用项目级、权威、单调递增的 `60Hz sync_tick`，不得改用地图、层、私有会话或客户端本地 tick。脱战、死亡、会话退出、跨层、重注册或临时覆盖层不得将该时钟提前，除非职业规格明确且白盒验证允许；若同一时间源不可用或 epoch 不匹配，必须拒绝本次资源/进度提交，不能换算、重置或猜测时钟。
10. `actor_id` 必须等于玩家当前选定角色存档的稳定 `character_profile_id`，不得使用 Unit ID、玩家槽位、客户端连接或临时队伍序号；Unit ID 可随注册变化，`lifecycle_id` 必须随注册递增。断线、跨层、重注册和同存档回归保持同一 `actor_id`，切换角色存档必须产生不同 `actor_id`，且角色键不得在不同存档间复用。
11. 公开教学若以角色私有虚拟生命、猎印或进度模拟可攻击目标，必须在提交资源前声明稳定逻辑目标 ID、逻辑生命周期、命中桥接事件、原生生命/伤害拦截策略、每角色状态表、无仇恨/掉落/贡献边界与失败反馈；“完成同一技能循环”不能用共享血量、客户端计时或按钮直发进度代替。

## 三、运行时与遭遇契约

### 3.1 目标、输入与事件

**身份规范化。** 本模板中的 `actor_id` 是选定角色存档的稳定 `character_profile_id`，而不是当前英雄 Unit ID。`source_unit_id`、目标 Unit ID 和连接状态均可随地图、死亡或重连变化；运行时必须用 `(actor_id, lifecycle_id, unit_id)` 共同定位当次实体，所有存档、路线、一次性领取和绝对时钟只以 `actor_id` 为键。

所有目标范围使用以下唯一语义：

| 范围 | 唯一含义 |
|---|---|
| self | 当前施法者单位 |
| primary | 当前技能的主目标 |
| selected | 本次几何筛选得到的目标集合 |
| team | 其他队友，不包含施法者 |
| explicit | 指令明确提供的稳定单位 ID 和/或对象引用 |

| 使用场景 | 必须提供的权威输入 | 缺失时行为 | 最低离线验收 |
|---|---|---|---|
| 自身、主目标、筛选目标、队友 | 稳定 Unit ID；上下文保存 ID 到 Unit 引用 | 不允许退回为任意目标列表 | 自身 Buff 不转移；清理只影响绑定对象；team 排除施法者 |
| 命中确认技能 | 施法快照含 actor、生命周期、当前来源 Unit ID/引用、cast、技能、主目标、ID 到 Unit/目标生命周期映射、点位和队伍 ID；命中事件重复 actor/来源 Unit、目标生命周期、正数实际伤害、`hit_key`、`impact_sequence`、`sync_tick`；结束含 `close_tick` | 不提交资源、控制、破韧或贡献 | 只以 `(actor_id,lifecycle_id,cast_id)` 定位事务；来源/目标身份不匹配、重复/旧命中静默丢弃；边界 tick 的顺序可重放 |
| 动作时钟 | 每个动作保存 `start_tick`、`begin_cast_tick`、`close_tick`、前后摇与冷却开始时点；派生、脉冲、周期和普通攻击均有独立事务 | 不接受未声明收口的命中或延迟回调 | 直接动作、边界桶、周期 tick、派生伤害和取消路径可按同一脚本逐 tick 重放 |
| 点目标技能 | 同步施法点 target_point | 拒绝本次结算，不得改在施法者脚下 | 点位固定；空放不产出不该有的资源或标记 |
| 向量或朝向技能 | 明确的施法方向；若设计为面向前方，须明确使用施法时朝向 | 不得从异步本地输入猜测 | 同一帧多目标几何筛选一致 |
| 品级分支 | 每个被影响目标的 normal/elite/boss 元数据 | 拒绝品级专属结算，或只执行设计允许的通用部分 | 混合目标时 BOSS 只转破韧，精英按独立规则结算 |
| 队伍收益 | 当前队伍成员和半径过滤结果 | 空集合，不从盟友/召唤物/跨队玩家推断 | team 永远排除施法者，净化结果与提交快照求交 |
| 私有试炼、微相位或叠层会话 | `combat_scope=public|private_session`；私有时非空 `session_instance_id`、会话尝试/epoch、活动会话排斥、入场授权、显式入口门禁、成功/失败回传点与离场保护；每个回传点还须声明安全半径、刷怪锚排除半径、公共仇恨/地面危险策略和保护秒数，私有矩形内不得保留公共刷怪锚；入口还要有权威 `public_combat_lock`，并在同 tick 公共事件结算后才可判断；公共时运行时 `session_instance_id=nil/session_epoch=nil`，布局中的 `session_context=none` 仅是元数据，不得原样写入事件 | 公共战斗、公共投射/周期、公共仇恨、Boss 参与或脱战冷却未清时拒绝创建会话、递增尝试或发临时资源 | 私有/公共目标、伤害、触发、掉落、贡献和延迟回调互不相通；退出会话后旧回调静默；私有角色还须明确公共普通单位、公共交互物与公共 Boss 的选中/碰撞/仇恨/奖励/视觉隔离 |
| 公开教学前导靶或一次性回收节点 | 可攻击资格、目标品级、稳定逻辑目标 ID/Unit 生命周期、并发人数、每 actor 私有资源/完成归属、`PracticeHitEvent` 或等价权威命中桥接、原生生命/伤害拦截策略、未提交 `RecoveryCandidate`、原子 `unclaimed -> pending -> claimed` 领取事务、原子资源/资格时钟写入、完成后交互封存与可见范围 | 缺任一项不得产印、消费、回收、治疗或写进度 | 角色私有虚拟受击量不等于共享血量竞争；候选不得在 CAS 提交前发资源或推进绝对时钟；拦截后的练习伤害不得上报 `final_damage`、仇恨、掉落或 Boss 贡献；目标不可被击杀/换 Unit ID，其他玩家不能抢占、重放或重复领取；公开节点不因此变成私有会话、残响或 Boss 贡献 |
| 受击反应、格挡、护守 | 项目遭遇分类器给出的资格与实际结算结果 | 默认为不触发 | 周期伤害、自伤、无敌吞伤、多段连刷均不能产资源 |
| 延迟/派生/周期命中、落空、位移完成 | 当前角色生命周期与会话上下文、独立 `cast_id`、`phase`、`scheduled_tick`、`close_tick`、`hit_key`、`component_key`、周期效果 revision 与事件幂等键 | 静默丢弃 | 同 actor_id 重注册或退出私有会话后旧回调不能影响新角色；每个派生/周期伤害都有独立事务，不能借用已关闭原施法或复用组件 |
| 追迹暂停、转换与残响 | `event_id`、`pause_id`、实例/阶段/单位生命周期、同步 tick；`trace_bearing` 显式布尔值；公开残响还须有载体/交互锚关联、激活状态、碰撞/刷怪缓冲、状态持续与重置叙事 | 缺失时正常衰减或清理，绝不猜测 | `trace_bearing=true` 必含非空 resolution、成功/失败结果和可见范围；刷新锚、交互点与交互区必须同样自描述；暂停不可叠成无限时长 |
| 公共 BOSS 贡献 | 已接受命中或周期 tick 冻结的 `boss_instance_id/phase_id/target_id/target_lifecycle_id` 快照，以及遭遇侧伤害、机制、破韧、有效保护或无职业门槛的 `encounter_action_key` 事件 | 不由职业自行记账，也不得在上报时重新查询当前 Boss 阶段 | 不替代全局击杀归属、DPS 和参与奖励规则；同一事件 ID 跨 Boss/阶段/目标生命周期重放必须拒绝 |

所有魔法效果、控制、破韧和清理命令必须显式声明 target_scope；禁止从 `context.targets` 作隐式回退。延迟脉冲每次必须产生新的 selected 快照，缺少目标 Hook 即命中空集合。任何由延迟命中、追迹、公共行为或场地脉冲驱动的状态，都必须有可去重的事件键与明确的结束 tick；不得依赖回调到达顺序猜测先后关系。Boss 命中在被接受时必须冻结遭遇快照；贡献层维护 `event_origin_index[event_id]`，同一 ID 在不同 Boss 实例、阶段、目标或目标生命周期中出现时静默拒绝。私有会话的每个 cast、hit、periodic tick、效果、派生伤害和贡献事件都必须携带同一会话上下文；公共贡献禁止带私有会话 ID。受品级影响的效果必须读取权威 `target_rank_epoch`：同一 tick 先按 `rank_change_sequence` 应用品级变化，旧 epoch 的命中不得创建或刷新品级专属状态。

教学临时生命、冷却、绝技或其他资源必须置于命名的会话覆盖层：入场时保存普通状态快照，声明会话内的精确值或补足公式，成功、失败、离场和生命周期失效时都只清覆盖层并精确恢复入场前普通状态。消耗品、货币、耐久、死亡成本、公共生命和公共冷却不得被教学会话写入或借此恢复。若一项公开前导交互是私有试炼的必要门槛，它必须有具名地图点/区域、一次性角色键、失败重试、无奖励边界和明确引导，不能只留在职业文字中。

所有私有会话入口均先按 `sync_tick -> public_event_sequence` 结算当前及更早的公共事件，再检查 `public_combat_lock`；被拒绝不得生成会话、吞掉同 tick 伤害或借微相位解除公共仇恨。每个入口必须按以下唯一优先级只展示当前最高阻断原因，并在每次交互时重新计算：`active_boss_participation` -> `请离开首领战斗范围`（无倒计时）；`active_public_aggro` -> `请脱离公共战斗范围`（无倒计时）；`pending_public_hit_projectile_or_periodic` -> `等待投射物或持续伤害结算：剩余 X.X 秒`（以最晚 pending 结束 tick 计算）；`public_damage_within_lock` -> `脱战冷却：剩余 X.X 秒`（以 `last_public_damage_tick + lock_duration_ticks` 计算）。若允许公开教学的非战斗练习事件不触发该锁，必须限定为命名逻辑靶、`event_category=public_training_noncombat`、无仇恨/投射/周期/Boss 参与的已确认事件；同一 5 秒窗口出现任何其他公开事件即失去例外。`trace_bearing=true` 的刷新锚、交互点、交互区和布局资源必须完整复写处置键、成功/失败结果、文字/世界状态可见范围、状态持续/重置叙事与职业奖励边界，不能只在职业正文保留这些字段。

### 3.2 效果、护盾与减伤

每个效果必须有如下台账字段：

| 字段 | 说明 |
|---|---|
| 目标范围 | self、primary、selected、team 或 explicit |
| 状态归属 | actor、目标、目标加施法者、或项目遭遇 |
| 叠加策略 | source_refresh、shared_highest、same_source_shield_refresh、source_bound、derived 等 |
| 持续时间与重施 | 基础持续时间、每级修正、重施时刷新/延长/覆盖/拒绝的唯一语义，以及命中快照的读取时点 |
| 呈现来源 | Lua 状态如何映射为真实 Buff、属性、护盾、控制或视觉 |
| 回退与清理 | 到期、驱散、死亡、挑战失败、跨层、角色移除、来源失效时的行为 |

- shared_highest 只呈现一个完整的最高来源；最高来源到期后必须物理回退到下一有效来源，禁止逐字段拼接多个来源。
- source_bound 按“目标 ID + 施法者 ID”隔离；same_source_shield_refresh 只能刷新同一来源的护盾。
- 减伤必须先在职业定义的类别内取最高，再跨类别乘算，并设置职业或全局总上限。禁止把多个受伤减免直接相加。
- 护盾、减伤、格挡等“有效保护”只能由遭遇侧实际吸收或实际减伤结果确认，不能仅因 Buff 存在而结算资源。

### 3.3 生命周期与清理

1. 注册记录按 actor_id 保存单位、全部 Trigger、循环计时器、延迟计时器与递增生命周期令牌。
2. 注册时先写入 actor 到单位的映射，再进行可能同步英雄属性的运行时初始化。
3. 目标死亡或离场只能执行目标级清理：清除该 `(actor_id, target_id)` 的私有效果、预留、定时回调和追踪记录，不得清施法者绝技值、全局资格窗口或其他目标状态。
4. 角色死亡、挑战失败、跨层、重复注册和 remove 都先失效旧生命周期，再取消该来源计时器和控制租约、清理角色级瞬态状态；未提交的资源候选、预留和 `pending` 一次性领取必须随旧生命周期取消，角色级已提交 `next_eligible_tick` 不得被该清理重置或提前；remove 随后撤销注册可见性、停止循环计时器、注销 Trigger、删除单位映射。
5. 外部命中确认、落空确认、位移结束和效果到期回调必须校验令牌与当前会话上下文；旧单位事件、退出私有会话后的延迟回调不得影响同 ID 的新注册角色或公共账本。

### 3.4 数值与遭遇基准

- 所有职业至少声明：Lv60 裸装、同等级、无外部增益、90 秒持续可攻击目标、10 秒爆发、首绝技窗口、单人高压容错。
- 团队职业还要声明：自身收益、对队友的可替代收益、无该职业队伍仍可通关的条件。
- 每个涉及 BOSS 转破韧、格挡、机制贡献或硬控的职业，必须列出最小遭遇标签契约；标签由地图侧提供，职业侧只消费。
- 公共 BOSS 的主归属、同队击杀、非稀有参与奖励和稀有掉落资格属于项目级规则。职业只能上报合规贡献，不能绕过这些规则。
- 每条公共 BOSS 贡献至少含 `kind/event_id/actor_id/lifecycle_id/boss_instance_id/phase_id/target_id/target_lifecycle_id`，并且与已接受命中的冻结遭遇快照完全一致；按 BOSS 实例、阶段、事件 ID 去重，同时用 `event_origin_index` 拒绝跨实例、跨阶段、跨目标生命周期重放。数值类另要求技能键与正数值，净化类另要求机制键与替代解。
- 可复现的跨职业夹具还必须冻结：普通攻击系数及前后摇、每个周期效果的首跳/末跳与刷新 revision、绝技阶级、行动输入脚本、目标坐标/防御/碰撞和逐 tick 伤害日志字段；任何缺项都只能标为待执行，不能宣称数值预算通过。
- 离线预算不是实机平衡结论；跨职业比较必须在同一地图、同一装备白名单与同一日志口径下完成。

### 3.5 玩家可读性与商业公平

- 每个职业必须建立玩家可见结果表，至少覆盖资源生成、满层刷新、预留、真实消费、释放、拒绝、追迹暂停/中断、资源冷却和绝技资格；同一结果不得只以颜色区分。
- 高压遭遇必须为每段伤害注明预警时长、形状、方向或落点、非颜色单独的声音类别、安全线与命中后原因反馈，并在对应 BAL 高压脚本中验收。职业不能以伤害补偿替代不可读攻击。
- 商业内容必须先有字段允许/禁止表。禁止改变自由技能点、技能等级上限、五主动槽位、职业主资源上限/生成/消费/绝技充能、BOSS 进入与公共遭遇资格、伤害/机制贡献口径、稀有掉落资格或保底进度。
- 每个职业均须保留零付费、常规游玩、同装备白名单的 Lv60 基线，并通过自身命名的 BAL 测试；付费外观、账号便利或后续获批的非战力便利不得覆盖、放宽或替代该通关和数值验收条件。

#### 3.5.1 商业字段政策表

下表是未进入价格、礼包、商城或数值配置前的项目级边界，不等于已经批准任何商业内容：

| 字段族 | 当前政策 | 不可触碰的边界 |
|---|---|---|
| 外观、表情、个人主页与赛季展示 | 政策可讨论（未批准商品字段） | 不带属性、资源、掉率、资格、战斗可见性优势或强制社交门槛 |
| 角色存档槽、仓储整理与外观预设 | 政策可讨论（未批准商品字段） | 不增加角色强度、材料产量、掉落次数、保底速度、公共 BOSS 资格或战斗中换装能力 |
| 非战斗便利传送、交易与跨服服务 | 待经济/地图实验（未批准商品字段） | 必须先证明不缩短副本冷却、复活惩罚、Boss 重生、掉落保底或关键任务等待；交易还须有独立经济、反刷与追赶规则 |

## 四、物编与离线 Lua 分层

### A 层：物编稳定字段

- 英雄：基础属性、成长、攻速、攻击间隔、移速、普攻类型、射程、技能绑定。
- 技能：等级、施法类型、前后摇、指示器、冷却、零基础伤害/蓝耗/血耗、学习等级。
- 效果：稳定分类、正负面、层数、死亡消失、UI 显示和通用护盾类型。

### B 层：同步运行时规则

- 属性倍率、资源、动态伤害、护盾数值、格挡、位移、命中确认、控制、破韧、效果覆盖、挑战清理和多人隔离。
- 有来源差异的资源必须声明容量、来源、消费优先级、哪些来源可充能以及满层新增的失败行为；UI 只能读取汇总与来源摘要，不能重写资源真值。
- 目标、点位、方向、品级、伤害分类、实际保护结果和生命周期输入必须在职业集成契约中逐项声明。
- 职业核心不直接调用 Y3；桥接层只使用固定 API 基线，并由项目映射注入真实技能/效果 ID、距离尺度、遭遇标签和筛选器。

## 五、固定交付物与延期边界

每个职业包必须有：

1. 正式职业子基线、英雄属性规格、技能与效果物编规格。
2. 预施工清单、对象命令构建器、预检、纯 Lua 测试、Y3 API 基线检查。
3. 职业集成契约或等价的 Y3 接入文档，列出运行时输入、真实 ID、地图钩子和失败行为。
4. feature-based execution gates：实际使用点目标、受击反应、延迟回调、目标品级或遭遇贡献时，清单必须分别记录对应钩子是否已绑定。
5. 项目级延期接入契约：存档、技能树 UI、五槽装配和多人会话只能通过职业控制器调用，不得直接改职业运行时状态表。

生产 ID、图标、模型、距离尺度、脚本根、编辑器对象回读和多人实机均属于 execution gate；离线通过不得标记为 verified。

## 七、状态术语与施工顺序

| 状态 | 含义 |
|---|---|
| planned | 只有设计意图，尚未形成可校验规格 |
| reviewed | 规格完成审阅，但未必有离线实现 |
| official-subbaseline | 用户已采纳的 `reviewed` 职业设计基线；技能、数值和设计契约冻结为当前有效口径，后续测试只能提出修订建议。它不等于离线施工、真实地图或实机验证通过 |
| offline-stage-accepted | 已通过当期离线范围；若模板升级，仍需进行兼容反查 |
| construction-ready | 真实地图、ID、资源、脚本根与必要钩子已就绪，可生成生产物编命令 |
| verified | 编辑器对象回读、真实 Lua 运行和多人验收均通过 |

推荐顺序：

1. 完成职业资源循环、前期闭环、完整技能组和效果台账。
2. 写出输入/事件/生命周期/遭遇集成契约，再建立英雄、技能与效果物编规格。
3. 建立预施工清单、纯 Lua 状态机、桥接与白盒矩阵。
4. 离线验收通过后，接入真实 ID、编辑器对象、地图脚本根与遭遇钩子。
5. 用真实地图日志完成跨职业预算、四人联机、死亡、重连、入本清理和对象回读，最后才可标记 verified。
