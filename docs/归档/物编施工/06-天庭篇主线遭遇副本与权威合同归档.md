## 已冻结的设计事实

- 天庭章节精确覆盖 `Lv41–60`，首发等级上限仍为 `Lv60`；通天塔仍是唯一全局塔，`Lv55` 逐人准入不被本包改写。
- 入章建立三个角色级逻辑进度：`TT_SPEC_PROGRESS_CHAPTER_ENTERED`、`TT_SPEC_PROGRESS_CELESTIAL_OBSERVATORY_OPEN`、`TT_SPEC_PROGRESS_MAINLINE_CLEARED`。三者均为 `TT_SPEC_*` 逻辑身份，运行时键均为 `null`，并按 `(actor_id, event_id)` 幂等复用完成收据语义。
- 入章只能由权威端确认的 `Lv41` 同角色成员取得，且须验证源自 `DF_E_YANLUO_HALL` 成功事件的不透明交接证明。天庭不读取、不写入、也不注册为 `DF_PROGRESS_YANLUO_HALL_CLEARED` 的消费者；地府完成键不被当作天庭运行时输入。
- 常规主线终局“凌霄外庭·裂律观台”为私有 `1–4` 人会话。所有入场成员逐人验证已入章，只有权威确认的有效参与者能获得常规主线完成；队长、旁观者、伪造成员与未授权队友不能代领。
- 七星单人本以“周天观台已开启”为最低门槛，使用 owner、生命周期、实例、epoch、revision 与 cleanup token 身份骨架；死亡、超时、断线或生命周期失效都会进入失败清理，清理确认前不得重入。
- 二十八星宿普通与噩梦团队本均冻结 `1–4` 人权威成员快照，并逐人要求天庭常规主线完成。死亡成员仅按离线合同回当前篇章初始出生点并锁至清理确认；断线成员变为 `left`，不能重连或领奖，剩余 `active` 成员可以继续。
- 星宿轮换固定依据服务器 `Asia/Shanghai` 自然时辰；首次成功创建团队本时冻结不可变 `rotation_snapshot`。客户端时钟、客户端方位与重试重算宿位都不得参与决定。
- 噩梦资格为逐角色、同方位的不透明资格凭证；每名入场者均须通过 `normal_clear.quadrant == credential.quadrant == nightmare.rotation_snapshot.quadrant` 比较。凭证的物品形态、消耗、掉落、数量和收据仍交由经济裁决包决定。
- 三类会话统一只允许 `active → cleanup_pending → closed`。清理确认必须匹配实例身份、`session_epoch`、`revision` 与 `cleanup_token`；已确认的正常完成不会因后续清理确认失败而回滚。
