## 已归档的结论

- 普通团本每一方位固定为 `双宿 → 双宿 → 双宿 → 单宿`，即严格 `2+2+2+1`。二十八名星官均有独立的“读线 → 提交 → 反制 → 可见结果 → 失败/恢复”卡；单次读线只允许一个主 P0，附属压力不得伪装成第二个同步主反制。
- 四圣噩梦固定复用本次轮换方位，按同方位 `2+2+2+1` 七链推进；净宿援护集合只能增加，核心回正只能在规定链序后出现。恢复留在当前语义段，不能跳段、倒退、重建或重复终局候选。
- 每次未来转场必须绑定既有 raid/boss/epoch/phase/revision、冻结轮换快照、方位、难度，以及每名成员的 `actor_id`、`actor_lifecycle_id`、`membership_snapshot_id`、`member_status` 权威元组。客户端死亡/断线报告、本地时钟、UI、伤害飘字和本地计时均不能推进遭遇。
- 普通本完成四段、噩梦完成七链/净宿/核心回正时，只能形成只读“遭遇终局事实候选”。它们不写进度、资格、夜巡钥、称号、材料、奖励、收据或 economy-v2 输入；真实会话完成仍由既有权威会话合同唯一裁决。
- `phase_id`、`revision` 与 `cleanup_token` 保持既有会话控制面身份，绝不被重定义为战斗阶段字段或机制动作输入。成员死亡、`left`、超时、生命周期失效和清理的处理继续复用既有会话合同。
- 本轮只细化离线语义图，不创建 Lua、Y3 对象、地图、计时器、AI、同步、状态机、运行时事件、数值、资源 ID、掉落或经济账本。
