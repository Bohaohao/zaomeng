# 花果山 96x72 白盒拆分

## 文档定位

本文件把花果山从旧 `360x260` 候选局部图压缩为首发工作基线 `96x72 terrain cell`，用于进入白盒施工和实机验证。

当前方案不代表最终美术，也不修改六层世界拓扑。龙宫四份挑战房和牛魔正式战场不再占用花果山本体空间。

## 坐标口径

局部白盒使用 Y3 左下角原点坐标：

```text
local x: [0,96)
local z: [0,72)
```

映射到 `docs/13` 的人界中心坐标：

```text
world x = local x - 48
world z = 36 - local z
```

因此花果山仍对应：

```text
world x[-48,48), z[-36,36)
```

## 总体排布

```text
北
              [猕猴王瀑布台]   [鹏魔高崖]       [蛟魔潮汐湾]
                       \          /                  /
[主城] -> [山道] -> [水帘溪谷] -> [副本枢纽] => [桃林] => [七星洞] -> [东海前缘] -> [海眼]
                                      \      => [蝙蝠窟] => /          \
                     [龙宫暗口]         \                         [鲨之涡流]
                                                             \        /
                                                       [熔脉裂口团本前哨]
南
```

设计意图：

- 西侧 `0-43` 是新手与探索段，中部 `43-78` 是分路与战力检查，东侧 `78-96` 是东海边界和篇章压轴。
- 猕猴王、蛟魔王、鲨魔王全部位于主路外侧，刷新或战斗期间不封锁日常通行。
- 桃林和蝙蝠窟在副本枢纽处分开，在七星洞汇合，形成一次短分路选择。
- 鲨魔王首通后才开启向西回折的熔脉裂口；该入口只传送到梦墟层牛魔旧战场，不表示花果山与火焰山地理相邻。
- 龙宫暗口只负责发现与分配，四份独立挑战房位于四海层 `80x64` 总格。

## 三传送点与复活闭环

| 节点 | 坐标 | 解锁建议 | 失败与回程职责 |
|---|---:|---|---|
| 传送点一：主城 | `(10,36)` | 默认解锁 | 普通死亡、主动回城的花果山主落点 |
| 传送点二：副本枢纽 | `(48,36)` | 首次抵达后解锁 | 桃林、蝙蝠窟、水帘溪谷和东海段的中途折返点 |
| 传送点三：团本入口 | `(59,11)` | 鲨魔王首通后解锁 | 团灭、超时后从牛魔旧战场回退的集结点 |

龙宫单人本死亡、超时或退出时，优先回到传送点二；牛魔团本失败时回到传送点三；公共野外普通死亡回到传送点一或最近已激活安全点，最终规则在 Lua 规格阶段锁定。

## 道路与战斗口袋

| 类型 | 当前候选 | 用法 |
|---|---:|---|
| 公共主路 | `8 cell` | 主城至副本枢纽、七星洞至东海前缘 |
| 普通支路 | `6 cell` | 桃林、蝙蝠窟、龙宫暗路、鹏魔高崖 |
| BOSS 入口 | `10 cell` | 猕猴、蛟魔、鲨魔三处进退口 |
| 猕猴王口袋 | `24x18` | 轻阶段公共 BOSS；分身期间真身持续可攻击，并预留无职业门槛的 `stabilize_wind_eye` 残风眼与 4 个 actor 并发交互位 |
| 蛟魔王口袋 | `23x21` | 一阶段水柱、甩尾和固定 `3.0` 秒短潜入；预留 `drain_tide_eye` 潮眼与 4 个 actor 并发交互位 |
| 鲨魔王口袋 | `23x21` | 一阶段直线撕咬、涡流牵引和低血狂暴；预留 `stabilize_vortex_anchor` 涡流锚点与 4 个 actor 并发交互位 |
| 团本前哨 | `16x16` | 四人站位、确认、补给和跨层传送 |

三处公共 BOSS 口袋均小于通用 `32x32` 基线。这不是已定数值，而是 `96x72` 约束下需要优先验证的压缩候选。若四人测试拥堵，调整顺序为：扩大口袋到空白边界、压缩装饰缓冲、最后才扩大花果山总尺寸。

狮驼王虽承担东海前的战力检查，也不得把已解锁玩家锁死在主路上。其战圈固定收至七星洞北侧 `x[66,77) z[26,37)`；`8 cell` 主路改走南侧 `x[65,78) z[38,46)`，桃林与蝙蝠窟均从这条绕行带汇入东海。这样 Lv20 猎首仍可在首领口袋使用微相位，但公共玩家、死亡回传和东海通行不依赖 Boss 当前状态。

为让“教学不占主路”可机械检查，干跑布局额外固定三段 `8 cell` 主路白盒带：`area_hg_main_route_waterfall=x[27,43) z[33,41)`、`area_hg_main_route_sevenstar=x[65,78) z[38,46)`、`area_hg_main_route_east_sea=x[78,93) z[32,40)`。教学区域只允许与其边界相接，不允许有面积重叠；真正路径曲线、碰撞和装饰仍待编辑器白盒验证。

三个口袋的公共交互锚点已作为干跑逻辑资源固定：猕猴王使用 `pt_hg_wind_eye_slot + area_hg_wind_eye_interact`，蛟魔王使用 `pt_hg_tide_eye_slot + area_hg_tide_eye_interact`，鲨魔王使用 `pt_hg_vortex_anchor_slot + area_hg_vortex_anchor_interact`。点位位于各自战斗圈的边缘、避开主路和 BOSS 中心；三个圆区半径均为 `3 cell`，供公共行为矩阵的四人并发读条使用。鲨魔王锚点还必须位于 `area_hg_shark_anchor_safe_line` 内、`area_hg_shark_vortex_core` 外，不能以视觉估计代替该逻辑约束。上述均为干跑资源，不代表已写入 Y3 地图。

### 巡猎教学与分支口袋卡（布局预留）

六张分支卡、一处 Lv15 公开回收预演与一处 Lv15 绝技试炼只定义位置、首波、可读安全线和撤退方向，不在本轮锁定刷新数值、掉落或真实单位配置。Lv8 玩家先在道统石台从三条路线中显式选择一条；若对应核心尚未学习，选择事务原子消耗 `1` 点自由技能点、将其升至 1 级并写入选择键，已学核心只写选择键。随后只进入该分支的一张 `60` 秒路线试炼；另两张保持预览或后续复训入口。首次卡成功前路线选择可改，但不会自动洗点或退点；只有三枚明确路线通过键才冻结本轮教学路线。巡猎完成所选卡后，水帘溪谷中的龙宫线索可完整交互；其他职业沿用自己的等价核心路线门禁。所有私有目标的世界内身份统一为“道统回照/弓痕试影”，不是公共区域中重复生成的真实怪物，也不等同 `trace_bearing=true` 的残响载体。

### 教学卡通行与并发契约

- 首次进入卡片范围只触发 `preview_trigger=first_enter`，展示试炼名称、目标和缺失条件；只有在 `entry_interact_point_id` 显式交互、全部 `entry_requirements` 通过后才触发 `entry_trigger=explicit_interact`。预览、拒绝或路过均不得创建 `session_instance_id`、增加 `attempt_sequence`、生成私有目标或发放临时资源。
- 每名角色以 `actor_id` 独立保存选路键与路线通过键。Lv8 道统石台始终展示猎首/逐风/缚影与各自核心等级；交互对未学核心原子执行“检查 Lv8、未冻结与 1 点自由技能点 -> 扣点 -> 核心升至 1 级 -> 写入 `C04_ROUTE_LV8_SELECTION:<actor_id>=hunt|wind|bind`”，对已学核心只写选择键。任一前置失败均不写任何部分结果。未写入时三张卡均拒绝并反馈 `请选择本次猎路 0/1`；已选而核心不足 1 级则反馈对应核心缺失。固定通过映射为 `猎首 -> C04_ROUTE_LV8_hunt`、`逐风 -> C04_ROUTE_LV8_wind`、`缚影 -> C04_ROUTE_LV8_bind`，仅在已选卡的 `60` 秒内完成该分支核心动作与卡片成功条件时写入。首张卡成功后仅当任一 `C04_ROUTE_LV8_hunt/wind/bind` 已写入时冻结选择；`C04_ROUTE_LV8_SELECTION:<actor_id>` 明确不是冻结条件。成功前选择键本身可免费改写，但改到未学核心仍按正常技能树花费且绝不自动退点。猎路碑固定有 `2 cell` 安全半径、`4 cell` 公共刷怪锚排除与“选择区内无地面危险”约束。队友可旁观，但旁观者只见试炼界线、承命者残影和完成/失败波纹；不见私有目标、血条、伤害、仇恨、掉落或个人进度，且不能替另一名角色完成、消耗、击杀或阻断其教学目标。
- 每名角色同时最多存在一个 C04 私有会话；每次进入私有卡都生成 `session_instance_id=c04:<actor_id>:<lifecycle_id>:<area_id>:<attempt_sequence>`，并令 `session_epoch=attempt_sequence`。共享的是地形和行走空间；私有的是教学目标、仇恨、伤害、技能目标筛选、掉落、事件与奖励。私有角色对卡片内误入的公共普通怪、公共 Boss 和公共交互物统一看到非交互轮廓：不能选中、碰撞、受击、仇恨、得奖或驱动遭遇；公共玩家的世界不因此暂停。每张卡还声明 `public_spawn_anchor_overlap=forbidden`，公共刷怪锚点不得落在私有矩形内。所有私有战斗/触发事件必须携带并匹配同一个 `combat_scope=private_session + session_instance_id + session_epoch`；公共区事件固定 `combat_scope=public` 且空 session，二者互相不可选中、不可伤害、不可贡献也不可驱动对方触发器。
- `C04-LV15-RECOVERY-INTRO` 是不创建会话的公开前导点：入口为 `pt_hg_c04_recovery_prelude`，区域为 `area_hg_c04_recovery_prelude`。它放置稳定逻辑键 `C04_PRACTICE_TARGET`：对技能筛选可攻击，但不进入普通公共伤害/仇恨/掉落/击杀账本；原生生命不被写入，权威端只接受 `C04_PRACTICE_HIT_V1` 的 `PracticeHitEvent`。事件固定含 `actor_id`、`character_profile_id=actor_id`、`lifecycle_id`、`source_unit_id/source_unit_ref`、`cast_id`、`phase`、`hit_key`、`sync_tick`、逻辑/Unit/生命周期目标、品级/会话字段、`event_category=public_training_noncombat`、正数 `practice_damage_dealt`、`native_health_delta=0` 与 `virtual_vitality_revision`；为至多四名玩家分别生成虚拟命中、猎印和回收候选，互不抢层、抢血或改写目标生命周期。候选先写入 `C04_RECOVERY_CANDIDATE:<actor_id>:<lifecycle_id>:<cast_id>:<phase>:<hit_key>`，再用 `unclaimed -> pending(claim_id) -> claimed` 比较交换；只有仍有效且尚未发奖的候选能以同一幂等事务写入正常 `+20`、`recovery_next_eligible_tick=accepted_tick+960`、进度键与可用 M12。失败 pending 必须反馈 `回照未记录，请重新完成`。完成后该角色视角改为只读展示，不能再产印、回收、治疗或改变冷却；未完成前可免费反复挑战。石台 `2 cell` 内禁止公共刷怪锚点和地面危险，外缘显示中性安全线。该点不使用 `trace_resolution`，也不创建 `session_instance_id` 或 `attempt_sequence`；成功文字仅发起者可见，其他人只见中性石台回响。
- 角色到达 Lv15 时由等级系统写入 `C04_U01_TRIAL_ELIGIBLE:<actor_id>`。它只代表可以进行公开回收预演和一阶绝技试炼，不等同 `u01_tier=1`；公开回照石检查资格键与任一核心 1 级，Lv15 私有试炼再检查资格键、`C04_REAL_RECOVERY_INTRO:<actor_id>` 与 `u01_tier=0`。试炼会话内临时授予一阶，成功才写永久一阶，失败/退出不改变永久阶级。
- 本布局的 `sync_tick` 与 `entry_tick` 固定读取项目级、权威、单调递增的 `60Hz` 时钟；跨地图、跨层、私有会话、死亡、重连和重注册均不得归零或替换为局部 epoch。时间源缺失或事件 epoch 不匹配时，资源/进度提交与会话入口必须拒绝，不能用布局局部 tick 换算或猜测。
- 任一私有教学入口均先结算 `sync_tick <= entry_tick` 的公共伤害、仇恨、投射物、周期和 Boss 参与事件，再检查权威 `public_combat_lock`。存在多项阻断时只显示最高优先级并在每次交互重新计算：`active_boss_participation -> 请离开首领战斗范围`、`active_public_aggro -> 请脱离公共战斗范围`、`pending_public_hit_projectile_or_periodic -> 等待投射物或持续伤害结算：剩余 X.X 秒`（取最晚 pending 结束 tick）、`public_damage_within_lock -> 脱战冷却：剩余 X.X 秒`（以 `last_public_damage_tick + 300` 计算）。前两项没有假倒计时；后两项必须展示可重试的权威剩余时间。被拒绝时不得创建会话、增加尝试序号、发放覆盖层资源或吞掉同 tick 伤害；只有公共状态完全 idle 才允许显式进入。唯一窄排除只用于 `C04-LV15-U01` 的同 tick 入场：`entry_tick` 必须等于已接受 `C04_PRACTICE_HIT_V1.sync_tick`，门禁按 `(actor_id,lifecycle_id,hit_key)` 回查同一 `C04_PRACTICE_TARGET` 的空会话 `public_training_noncombat` 事件，并只排除该事件本身的 pending 分类；它不持久化、不跨 tick、不能遮蔽任何其他公共状态，也不能用于公共怪、Boss、投射物或其他交互物。这同样适用于 Lv20 微相位，不能以私有隔离规避公共 Boss。
- 计时只从显式进入成功、生成私有教学目标后开始。私有卡使用训练战斗覆盖层：进入时精确保存普通生命、冷却和绝技快照，覆盖层中生命满值、训练冷却就绪，消耗品、货币、耐久和死亡成本均不写入公共角色。超时、死亡、主动离开有效区或目标生命周期失效均视为本次失败：立即失效本会话 epoch、清除本会话的临时目标、资源预留、M03/M09/M11 与延迟回调，清除覆盖层并精确恢复入场前普通状态，将该角色送回 layout 中声明的 `failure_return_point_id`，附 `2` 秒非战斗保护，并允许无限次免费重试；每个回传点必须有 `2 cell` 安全半径、`4 cell` 公共刷怪锚点排除、公共仇恨清空和明确地面危险处理，不允许只因名称含“安全点”而默认安全。成功同样清覆盖层，改送 `success_return_point_id`；主动退出、失败、成功和跨层同样失效旧会话回调；只保留已正式写入的路线键。
