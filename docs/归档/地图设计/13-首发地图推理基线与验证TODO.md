# 首发地图推理基线与验证 TODO

## 文档定位

本文件采用“扩容机制按预期可用”的工作假设，先给出能够继续策划和白盒施工的合理参数。

这些数值分为两类：

- **工作基线**：后续设计直接使用，不等待验证。
- **待验证参数**：先按基线推进，验证后只修正相关参数，不推翻六层拓扑。

## 已采用的工作假设

1. `resize_terrain` 修改地形画布，不等比例拉伸已有内容。
2. 扩容以地图中心为锚，宽度变化分配到东西两侧，高度变化分配到南北两侧。
3. 扩容后已有世界坐标和资源 ID 原则上保持，但必须通过测试确认。
4. 地图只保存逻辑地点 ID，不把玩家裸坐标作为跨版本存档依据。
5. 六层世界现在锁定锚点和相邻关系，不锁定终局地理面积。

## 首发地图尺寸基线

首发地图暂定为：

```text
384 x 320 terrain cell
长宽比：6:5
预计 get_map_info 格点值：385 x 321
```

选择理由：

- 足够容纳首发三篇、龙宫、通天塔、牛魔旧战场和六层锚点。
- 只约等于旧 `640x512` 终局容量草案的 37.5%，不会提前铺设大量空地形。
- 宽高均为 32 的倍数，后续适合按 64 cell 为一个扩容批次。
- 六层均能在首发图中获得固定方向，不会因为以后扩图而互换位置。

`640x512` 不再是首发目标，只保留为远期容量参考。

## 坐标约定

策划阶段使用“以地图中心为原点的 terrain cell 坐标”：

```text
x：向东为正
z：向南为正，向北为负
地图范围：x [-192,192)，z [-160,160)
```

正式施工时再通过 `get_map_info` 换算为 Y3 格点和世界坐标。

## 花果山节奏基线

- 主城出生点至第一场战斗：`15-25 秒`。
- 任意连续无交互移动段：不超过 `45 秒`。
- 主城至副本枢纽：`2-3 分钟`。
- 首次完整主线单程：`6-8 分钟`，不含 BOSS 战斗时间。
- 三个传送点分别覆盖主城、副本枢纽和团本入口，解锁后不要求重复长跑。

## 扩容策略基线

默认扩容单位：

```text
饱和轴 +64 terrain cell
```

例如：

```text
384x320
→ 横向不足：448x320
→ 纵向不足：384x384
→ 两轴同时不足：448x384
```

按照中心扩容假设，单轴增加 `64 cell` 等于对应两侧各增加约 `32 cell`。

扩容触发条件：

1. 某个方向未来两个版本的内容已经确定，现有空间无法容纳。
2. 当前可施工空间达到约 `65%` 时进入扩容排期。
3. 达到 `75%` 后不再把新大型内容塞入现有边界，必须先扩容。
4. 扩容必须批量进行，不为单个副本频繁调整地图尺寸。

## 验证后的修改边界

- 战斗尺度不通过：只调整场景与板块尺寸，不修改六层方向。
- `384x320` 不足：按 64 cell 批次扩大首发图，不回到一次性终局画布。
- 扩容位置发生偏移：调整坐标转换和锚点策略，存档仍使用地点 ID。
- MCP 扩容不可靠：才重新评估是否首发直接建立更大画布。
