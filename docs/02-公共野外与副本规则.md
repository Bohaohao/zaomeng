# 公共野外与副本规则

## 公共野外

公共野外是所有玩家共享的世界区域，用来提供 MMORPG 感。

| 内容 | 规则 |
|---|---|
| 普通小怪 | 所有玩家可见、可攻击、共享刷新 |
| 野外精英 | 固定点或巡逻刷新，建议有参与奖励 |
| 野外 BOSS | 公共资源，所有玩家可见，建议有刷新倒计时 |
| 材料点 | 可做共享刷新或个人拾取 |
| 复活点 | 每个主城野外应有就近回城/复活逻辑 |

公共野外不加副本状态锁。

公共野外需要解决：

- 个人掉落、队伍掉落与保底奖励的结算方式。
- 怪物刷新频率。
- 高等级玩家抢低级怪的问题。
- 野外 BOSS 被单人垄断的问题。
- 低等级玩家误入高级区域的问题。

### 公共 BOSS 击杀归属

公共 BOSS 的击杀归属不按尾刀判定，统一按本次战斗中的有效伤害贡献计算。

规则：

- BOSS 进入战斗后，记录每名玩家对该 BOSS 造成的有效伤害。
- 有效伤害占比 = 玩家对 BOSS 的有效伤害 / BOSS 本次战斗收到的总有效伤害。
- 有效伤害贡献最高的玩家获得主要击杀归属。
- 与主要击杀玩家处于同一队伍的成员，有效伤害占比严格大于 10% 时，同步计入本次击杀。
- 有效伤害占比等于 10% 时不计入同步击杀。
- 同步击杀可推进击杀任务、首次击杀记录、收集项和其他明确要求“击杀 BOSS”的个人进度。
- 击杀计数不直接等同于装备或材料掉落资格；公共 BOSS 掉落池和保底规则在地图分布定稿后的资源吞吐设计表中确定。
- BOSS 脱战并完全重置、挑战失败或本次战斗结束时，清空本轮伤害记录。

### 公共 BOSS 有效遭遇参与

不改变上面的 DPS 主归属和大于 10% 同步击杀规则，额外建立一个不能靠挂机取得的参与层：

- 玩家满足至少 `3%` 的有效 BOSS 伤害，**或**完成至少一项由遭遇明确记录的贡献：命中本阶段破韧阈值、在标记直击中产生实际护盾吸收/减伤，或完成 BOSS 指定的机制目标，即可写入 `progression_participation`。它只用于个人主线、保证性收集、角色首通或明确声明的非稀有进度。
- 机制目标必须要求存活、处于明确交互范围、完成完整读条且事件生命周期匹配；不能用路过、站位或客户端 UI 点击替代权威事件。
- 个人参与箱不是上述 OR 条件的自动结果。已采纳的 `P1_PUBLIC_CHEST_BALANCED_CONTRIBUTION` 规定：若本次公共遭遇开启了合格行为窗口，玩家须同时完成有效公共行为，且满足至少 `3%` 伤害／合格破韧／实际护守之一；若未开启窗口，才仅检查后三者之一。参与箱、公共首通和公共稀有必须绑定同一权威资格快照与已提交收据。
- 有效遭遇参与不替代“击杀 BOSS”记录，不改变最高 DPS 主归属，也不绕过稀有装备的伤害资格；参与箱、稀有和保底分别按 [经济裁决包](物编/成长数值与经济裁决包/README.md) 的当前版本判定，不能从 `progression_participation`、`primary/assist` 或荣誉自动推导。
- 每类非 DPS 贡献都必须有单场上限和遭遇日志，防止职业仅靠重复控制或站桩承伤刷资格。具体阈值进入后续资源吞吐表。

这样承伤、破韧和机制职业可以获得可见的公共世界回报，同时保留公共 BOSS 的核心击杀和高价值掉落由实际战斗投入决定的规则。

## 单人本

单人本的每个独立挑战区域同时只能由一个玩家开启。进入后为该挑战区域添加独立状态锁，直到挑战结束。

状态机：

```text
空闲 -> 挑战中 -> 成功/失败 -> 清理待确认 -> 空闲
```

| 项目 | 规则 |
|---|---|
| 开启条件 | 只有 1 名玩家可开启 |
| 锁类型 | 挑战区域独立锁，只锁定本次使用的副本区域 |
| 进入限制 | 其他玩家不能进入已占用区域；存在空闲副本区域时可以开启新的单人挑战 |
| 挑战时长 | 有最大挑战时长 |
| 死亡规则 | 挑战者死亡立即失败 |
| 超时规则 | 倒计时结束立即失败 |
| 成功条件 | 击杀副本目标或 BOSS |
| 失败处理 | 权威端发出带实例身份与清理令牌的传送/清理命令；收到匹配清理确认后才释放当前挑战区域 |
| 清理内容 | 清怪、清临时掉落、清计时器、清挑战状态、解锁副本 |

同一个单人本可以配置多份内容相同、状态独立的挑战区域。入口负责选择空闲区域，怪物、计时器、临时掉落、挑战者和清理状态不得跨区域共享。

花果山篇龙宫首发配置 4 份独立挑战区域，最多支持 4 名玩家同时分别进行单人挑战。

## 团队本

团队本支持最多 4 人。开启时，以副本 NPC 周围一定范围内的玩家作为本次挑战成员。

开启流程：

```text
玩家点击开启
-> 检测 NPC 周围范围内玩家
-> 生成本次挑战成员列表
-> 锁定团队本
-> 传送成员进入副本区
-> 开始倒计时与刷怪
```

| 项目 | 规则 |
|---|---|
| 纳入成员 | 开启瞬间 NPC 周围范围内的玩家 |
| 人数上限 | 4 人 |
| 锁类型 | 副本全局锁 + 成员列表锁 |
| 进入限制 | 非本次成员不可进入 |
| 开启限制 | 挑战中不可重复开启 |
| 死亡规则 | 成员死亡经权威端确认后立即回当前篇章初始出生点；该成员在本次团队会话中保持 `dead`，不得重入，直至匹配清理确认释放成员锁 |
| 失败条件 | 全员均已进入本次会话的 `dead` 状态 |
| 超时条件 | 倒计时结束 |
| 成功条件 | 击杀团队 BOSS 或完成目标 |
| 失败处理 | 全灭时不重复回传已死亡成员；超时仅将当时仍 `active` 的成员送回当前篇章初始出生点，再清理实例 |
| 清理内容 | 清怪、清临时掉落、清计时器、清成员表、清状态锁 |

## 副本锁数据

每个副本需要维护一份运行状态。

| 字段 | 用途 |
|---|---|
| dungeonId | 副本 ID |
| type | 单人本或团队本 |
| state | 空闲、挑战中、清理中 |
| participants | 本次成员 |
| owner | 单人本挑战者或团队本发起者 |
| areaId | 副本区域 |
| respawnPoint | 失败或结束返回点 |
| deadline | 挑战结束时间 |
| spawnedUnits | 本次刷出的怪物 |
| lockReason | 锁定原因，用于 UI 提示 |

## 同步边界

Y3 地图是多人环境，需要把本地 UI 和共享玩法状态分开。

安全原则：

- UI 可以用于显示、选择和提示。
- UI 选择不能直接改变共享玩法状态。
- 传送、刷怪、倒计时、死亡判定、奖励发放、状态锁必须走同步玩法逻辑。
- 随机掉落和随机刷怪不能由各客户端各自计算。
- 本地计时器只能用于表现，不用于权威失败判定。
- 团队成员虽然已回到出生点，其死亡态和本次成员锁仍由实例持有；只有携带同一实例身份的清理确认可以释放，不能以重生或重新点击入口绕过。
