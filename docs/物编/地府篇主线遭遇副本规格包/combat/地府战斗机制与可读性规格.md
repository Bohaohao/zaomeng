# 地府战斗机制与可读性规格

> **定位**：本文件只把既有地府节点的遭遇主题细化为可验收的纯离线战斗语法。它不创建 Lua、Y3 对象、地图、物编记录、实际进度、存档、奖励、材料、货币、掉落、资格、收据或数值。
>
> **状态**：`offline-design-spec / production-gate-closed`。时长、生命、伤害、地图、对象、奖励与全部运行时绑定均为 `null/deferred`；本文件不可据此直接施工或结算。

## 1. 章节战斗身份与来源边界

地府的核心循环是：

`识别命册或魂印中的可验证证据 → 在压力中选择裁决次序 → 以可见方式回正被错置的轮回秩序 → 用失败复盘补足下一轮判断`

它与另外两篇明确区分：

| 篇章 | 主要战斗语法 | 地府不复制的部分 |
|---|---|---|
| 花果山 | 公共行为、追踪、破绽与首领阶段压力。 | 不以公共贡献、追击结果或纯输出抢占作为裁决依据。 |
| 地府 | **命册证据 → 裁决 → 回正**；玩家先看清身份、记录与因果，再决定谁应被接引、暂缓、校勘或驳回。 | 不把识别结果缩减为单一伤害检查，也不让错误裁决静默发生。 |
| 天庭 | 错令、星位、连线与顺序编排。 | 不把固定星象、时辰轮换或队伍同步顺序当作地府的核心解法。 |

本规格只消费下列既有事实：

- `mainline-route.md`：常规路径止于阎罗殿；白骨秘境为可选并行单人内容；转轮殿为独立团队内容。
- `difu-mainline-encounter-contract.json`：`DF_E_YANLUO_HALL` 是唯一常规完成生产者，`DF_E_ZHUANLUN_HALL` 永不写入 `DF_PROGRESS_YANLUO_HALL_CLEARED`。
- `地府篇前置接口包/cross-chapter-interface.json`：团队死亡、回到章节初始出生点与清理确认边界。

战斗层只说明“玩家看到了什么、作出了什么判断、为什么失败、如何复盘”。它不得替代既有准入、成员快照、完成、断线、重放、清理或跨篇交接合同。

## 2. 统一可读性与无障碍规则

每个机制必须同时提供下列信息层；颜色永远不能是唯一载体：

| 信息层 | 必须让玩家理解 | 至少两条独立通道 |
|---|---|---|
| 预警 | 哪一份记录、魂印、目标或路线正在失序，以及其影响方向。 | 轮廓、地面投影、姿态、图形标记之一；再加音效、语音、UI 文本/图标、震动或状态变化之一。 |
| 决策 | 此刻应核验、暂缓、护送、分流、驳回、回正还是撤离。 | 可见的证据状态与可达路线；再加可读的目标优先级或交互状态。 |
| 结算 | 裁决正确或错误后，秩序、压力、可通行性或下一段证据如何变化。 | 场地/目标形态变化；再加音效、UI 状态或叙事反馈。 |
| 复盘 | 本次错在误认身份、错置优先级、遗漏证据，还是未在回正窗口行动。 | 失败摘要；再加场上最后一次关键证据的图标/文字回放。 |

### 1–4 人适配总则

- 每项机制都必须允许 1–4 名有效玩家完成；多人可并行观察、护送或分担压力，但不能让“必须同时有第五人”成为唯一解。
- 单人时，多目标必须有可顺序处理、可暂缓或可安全回看的路径；多人时，分工只能缩短决策链，不能改变裁决事实。
- 实际成员资格、死亡、离场、重连、清理和回归仍以既有权威合同为准。本规格不创建这些状态。

## 3. 遭遇机制卡

### 3.1 无常巷：双目标优先级

**主题**：黑白无常分别牵引不同归属的亡魂记录；危险不在于“先打谁”，而在于是否能区分“正在误引的魂”和“正被伪造记录遮蔽的魂”。

| 要素 | 规格 |
|---|---|
| 预警 | 两个目标拥有不同轮廓与魂印状态；错误牵引方向以路线投影和独立音/UI 提示同时表达。 |
| 玩家决策 | 先核验哪一条魂印、哪一侧压力可暂缓、何时把已确认目标交回接引链。 |
| 正确回正 | 被证实的伪引被驳回，正确目标获得可见接引通路，另一侧压力不再被静默放大。 |
| 失败含义 | 玩家把“看起来更危险”的目标误当作应优先裁决的证据，或未保留另一份记录的核验机会。 |
| 复盘 | 标记误认的魂印、被忽略的优先级线索和可在下次先后处理的动作。 |
| 1–4 人适配 | 1 人按“核验→暂缓→交回”顺序处理；2–4 人可分工观察/护送，但每份裁决仍须可由一人完成。 |
| 无障碍双通道 | 轮廓/路线投影 + 方位音或 UI 优先级图标；不以黑白颜色差异单独传达身份。 |

### 3.2 鬼门关：通行与守门压力

**主题**：门关失序把“通行”伪装成唯一目标；玩家必须判断应先维持哪条合法通路、何时拦住错误押送，而非只冲破守卫。

| 要素 | 规格 |
|---|---|
| 预警 | 受阻通路、错误押送方向与守门压力分别可见；关门动作、路径封锁和守卫集结有独立提示。 |
| 玩家决策 | 选择护持合法通行、截断错误押送、暂时绕行，或先回收可验证的关牒证据。 |
| 正确回正 | 合法通路重新可读，错误押送失去通行依据，守门压力转为可处理而非无尽堆叠。 |
| 失败含义 | 玩家只追逐守卫或只抢门，导致错置通路继续吞没需要接引的目标。 |
| 复盘 | 摘要显示哪条通路被误判、哪一次封锁未被处理，以及下一次应保留的撤离/回看路线。 |
| 1–4 人适配 | 1 人可在通路间依次验证并通过暂缓维持压力；多人可分别护持与拦截，不要求同时占据超过现有人数的点位。 |
| 无障碍双通道 | 门扉姿态/地面通路 + 守门号令或 UI 通行状态；禁止只用门色区分真伪。 |

### 3.3 接引院：魂印识别

**主题**：接引流程面对的是身份错配，不是数量清空。玩家要辨认魂印、出处与归属是否相符，避免把受害亡魂当成扰乱者。

| 要素 | 规格 |
|---|---|
| 预警 | 魂印的来源、缺失或冲突关系以形状/记录片段和语音/UI 描述表达。 |
| 玩家决策 | 选择先比对哪一份魂印、将哪一位亡魂暂存、何时提交接引，或何时拒绝伪造归属。 |
| 正确回正 | 相符魂印得到正确接引，冲突记录被留置校勘，流程压力明确下降。 |
| 失败含义 | 玩家以外观、距离或攻击威胁替代身份核验，造成错误接引或把问题转交到后续节点。 |
| 复盘 | 显示缺失的比对证据、被错误提交的归属与可在下一轮先核验的来源。 |
| 1–4 人适配 | 单人按可复核顺序提交；多人可共同观察或分流待核验对象，但同一魂印的最终判断不依赖多人同时确认。 |
| 无障碍双通道 | 魂印图形/轮廓 + 语音、UI 文字或状态提示；不得仅靠透明度、颜色或细小纹理。 |

### 3.4 判官殿：命册校勘

**主题**：命册可被权力改写。玩家必须从冲突条目中找出可验证的因果链，决定保留、驳回或回正哪一页，而不是简单净化负面状态。

| 要素 | 规格 |
|---|---|
| 预警 | 被改写条目、相互矛盾的证据与即将被强制执行的判定，均有页面形态/连线和独立音/UI 提示。 |
| 玩家决策 | 选择先校勘哪条因果、暂缓哪项判定、何时提交已验证条目并保护尚未被改写的记录。 |
| 正确回正 | 错误条目失去约束力，正确因果链在场上留下可回看的记录，下一段裁决得到更清晰的依据。 |
| 失败含义 | 玩家在未完成校勘前确认了伪造条目，或忽略了会被后续裁决吞没的关键证据。 |
| 复盘 | 标示误采信的条目、遗漏的矛盾来源与下次可采用的校勘顺序。 |
| 1–4 人适配 | 单人以逐页核验与安全暂缓完成；多人可分读不同条目并共享可见结果，但不能以同时点击作为唯一正确行为。 |
| 无障碍双通道 | 条目形态/因果连线 + 书页声、判词语音或 UI 证据摘要；禁止以单一文字大小或色彩表达关键真伪。 |

### 3.5 白骨秘境：单人多形态识别

**主题**：白骨秘境以同一敌意在不同形态中伪装为不同问题。玩家必须识别持续存在的魂印/行为证据，并在正确时机回正；它不是主线门槛。

| 要素 | 规格 |
|---|---|
| 预警 | 形态变化前保留同源魂印、移动/施法习惯或场地残留；并以独立音/UI 提示变化正在发生。 |
| 玩家决策 | 判断当前形态是在遮蔽、诱导还是暴露证据；选择观察、规避、打断、保留证据或在回正窗口提交。 |
| 正确回正 | 同源证据被连续识别，伪装不再重置玩家的判断进度，场地给出下一形态的可见线索。 |
| 失败含义 | 玩家把形态变化误作新目标而丢失证据链，或在伪装期盲目提交裁决。 |
| 复盘 | 以形态序列列出已识别/漏识别的同源线索，并说明下一次应保留的观察点。 |
| 1–4 人适配 | 固定为单人内容；不存在外部援护、多人站位、组队代判或队伍规模缩放要求。 |
| 无障碍双通道 | 形态轮廓/同源标记 + 语音、音型或 UI 形态序列；不能只凭视觉色相识别。 |

白骨秘境是 `DF_SIDE_BAIGU_SECRET_REALM` 的可选并行单人职责：不写入、不读取或替代 `DF_PROGRESS_YANLUO_HALL_CLEARED`，也不构成常规主线或转轮殿的入场前置。

### 3.6 阎罗殿：证据与裁决的常规最终多阶段

**主题**：阎罗殿让玩家对“哪一份命册能被信任、谁在滥用审判、如何在压力中回正”作出连续判断。它是常规篇章高潮，而非团队本的前导。

| 阶段 | 预警与读法 | 玩家决策 | 正确回正 | 失败含义与复盘 |
|---|---|---|---|---|
| 证据保全 | 多份命册条目开始互相覆盖，关键来源与被篡改路径均可见。 | 先保护可验证条目，还是先暂缓正在强制执行的伪判。 | 真正的证据保持可访问，错误覆盖不再遮蔽后续判断。 | 复盘指出哪份证据被放弃、哪条覆盖链未被截断。 |
| 裁决交锋 | 审判压力要求玩家快速站队，但仍保留可读的矛盾证据。 | 选择驳回、暂缓、校验或承受哪一侧短期压力。 | 已验证裁决使错误判定失效，并打开下一段回正通路。 | 复盘说明错误不在“输出不足”，而在误采信、误排序或错过校验。 |
| 命册回正 | 旧记录试图把先前纠正过的因果重新改写。 | 依据已保全证据确认应保留的记录，并拒绝伪造的最终归档。 | 可见的命册秩序回正，常规叙事冲突得到收束。 | 复盘回放最后一次真伪分歧与未完成的回正动作。 |

**1–4 人适配**：单人必须能依序完成“保全→校验→回正”；多人可分担观察、护持和短时压力，但任何决定不得依赖超过四人的同时操作。

**无障碍双通道**：命册页序/因果连线/场地状态 + 判词、钟声、UI 裁决摘要或触觉提示。关键真伪、优先级与回正窗口不得只以颜色、字体尺寸或瞬间闪烁表达。

阎罗殿战斗成功本身不在本文件中写进度；既有权威成功事件 `DF_E_YANLUO_HALL` 才是唯一可写入 `DF_PROGRESS_YANLUO_HALL_CLEARED` 的生产者。

### 3.7 转轮殿：记忆与轮回协作

**主题**：转轮一系把“抹除记忆、重置轮回”包装为效率。团队必须保留、互证并按可见因果回正记忆链，证明恢复秩序不等于抹平个体。

| 要素 | 规格 |
|---|---|
| 预警 | 即将被重置的记忆链、被错误归类的成员状态与轮回推进方向均以场地投影/形态和音/UI 提示表达。 |
| 玩家决策 | 分配观察、护持、回收记忆证据与回正轮回链的职责；决定何时聚合证据、何时让一段链暂缓。 |
| 正确回正 | 被互证的记忆链不再被重置，错误轮回推进失去依据，团队获得下一段可读的协作关系。 |
| 失败含义 | 团队以“速度优先”跳过证据互证，导致记忆链被误判为可抹除，或错把一段暂缓当作永久放弃。 |
| 复盘 | 按成员/职责显示遗漏的证据、过早提交的回正和可在下一次建立的协作顺序；不把失败归因给不可见的后台状态。 |
| 1–4 人适配 | 1 人可用顺序保全与回看完成；2–4 人可并行持有不同证据并进行显式交接，但没有必须由第五人承担的固定岗位。 |
| 无障碍双通道 | 记忆链形态/路线 + 可区分音型、语音或 UI 责任状态；成员身份与接力顺序不能仅依赖颜色。 |

转轮殿为既有 `DF_E_ZHUANLUN_HALL` 团队内容。它复用既有团队死亡、回到章节初始出生点与清理确认合同；战斗机制不改写成员状态、清理令牌或重连规则。它**永不写入** `DF_PROGRESS_YANLUO_HALL_CLEARED`，也不替代阎罗殿的常规完成职责；转轮殿不是主线入场前置。

## 5. 验收清单

1. 七项机制卡都包含预警、玩家决策、正确回正、失败含义、复盘、1–4 人适配与双通道无障碍表达。
2. 无常巷、鬼门关、接引院、判官殿、白骨秘境、阎罗殿、转轮殿的内容顺序与既有地府主线职责一致。
3. 白骨秘境仅是单人可选并行内容；白骨与转轮均不能成为常规主线入场前置。
4. 阎罗殿的完成键语义保持唯一；转轮殿永不写入阎罗完成键。
5. 所有时长、生命、伤害、地图、对象、奖励、资格、收据和运行时字段在机器合同中均为 `null/deferred`。
6. 本文可被后续专项施工阅读，但不等同于对象、地图、Lua、多人实机或经济已完成。
