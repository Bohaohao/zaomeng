# 职业物编与离线施工模板 v1.1

## 文档状态

- 状态：**reviewed / v1.1**，适用于 C01-C04 及后续职业施工包。
- 上位设计模板：[职业设计与离线施工模板](../归档/职业设计/03-职业设计与离线施工模板.md)。
- 基础字段模板：[物编模板与执行规范](00-物编模板与执行规范.md)。
- 本模板规定可生产的资产结构、A/B 层边界、集成门禁和验收证据，不分配生产 ID。

## 一、职业包固定资产

| 对象 | 数量 | 规则 |
|---|---:|---|
| 英雄单位 | 1 | Cxx_HERO；近战或远程模板由职业决定 |
| 技能 | 18 | 固定被动 1、主动 8、学习被动 8、绝技 1 |
| 效果 | 8-14 | 按真实机制创建，不以凑数为目的 |
| 投射物 | 0+ | 只有弹道本身是独立玩法载体时创建 |

每个职业包至少包含：

1. preconstruction-manifest.json，使用稳定 record_key，绝不将其当作生产 Y3 数值 ID。
2. config、core、skills、effects、runtime、Y3 adapter、controller 的职责分层。
3. 预检、命令构建器、纯 Lua 白盒测试、桥接测试和 API 基线检查。
4. integration-contract.md 或等价的 Y3 接入文档，写清地图输入、ID 映射、失败行为和测试责任。
5. 与当前职业模板版本对应的反查或验收记录。

## 二、A/B 层施工规则

### A 层：物编稳定字段

- 主动与绝技使用 ability_cast_type 2；固定和学习被动使用 ability_cast_type 3。
- 主动技能 ability_max_level 为 5，学习等级数组长度为 5；绝技数组长度为 3。
- 普通蓝耗、血耗和 ability_damage 保持零数组，避免与 Lua 属性倍率重复结算。
- 效果只写稳定分类、层数、显示、死亡消失和通用护盾字段。

### B 层：同步 Lua

- 资源、倍率、多段命中、动态护盾、格挡、移动、控制、破韧、效果覆盖、团队筛选、挑战清理和多人隔离。
- 任何效果、控制、破韧、清理命令都必须显式声明 target_scope；team 固定排除施法者。
- shared_highest 只保留完整最高来源，并在其到期后真实回退；source_bound 按目标加施法者隔离。
- 减伤必须在类别内取最高、类别间乘算，并使用职业或全局上限；不得直接叠加受伤减免属性。
- 点目标、伤害资格、实际吸收、异步命中和外部回调没有权威数据时必须拒绝或静默丢弃，不能使用施法者位置或旧 actor 状态猜测。

### 2.1 运行时输入清单

每个使用下列能力的技能或效果，都要在集成契约和预施工清单中登记：

| 特性 | 必填 gate | 离线默认 |
|---|---|---|
| 点目标 | cast_point_resolver_bound | 缺点位拒绝结算 |
| 方向目标 | direction_resolver_bound，或明确使用同步施法朝向 | 缺权威方向拒绝定向分支 |
| 受击反应/格挡/护守 | damage_classifier_bound | 默认不触发 |
| 读取护盾吸收或实际减伤 | protection_result_bound | 默认不产出资源 |
| 延迟命中/落空/位移结束 | lifecycle_callback_contract_bound | 旧令牌静默丢弃 |
| 按普通/精英/BOSS 分支 | target_rank_resolver_bound | 缺品级不执行专属分支 |
| 公共 BOSS 贡献 | encounter_contribution_hook_bound | 不自行发奖或改写击杀归属 |

不使用某项能力时，在清单中写不适用及理由，而不是把 gate 省略。

## 三、公共 Lua 边界

implementation/profession_common/lua/ 仅承载已由多职业验证的：

- profession_target_contract.lua：目标范围、稳定 Unit ID 与 ID 到对象引用。
- profession_effect_store.lua：来源绑定、共享最高值、物理回退、刷新与清理。
- profession_control_ledger.lua：按目标与控制类型的控制租约。
- profession_adapter_contract.lua：适配器命令分发与方法校验。

职业专属资源、技能状态机、数值、几何、遭遇语义和表现映射不得为了复用而过早放入公共层。

## 四、预施工清单与生产门禁

preconstruction-manifest.json 必须包含：

| 项目 | 规则 |
|---|---|
| 资产计数 | 1 英雄、18 技能、实际效果数、投射物数与稳定键唯一性 |
| A/B 边界 | object_fields 只存稳定物编字段；运行时规则不混入 A 层 |
| 来源 | 正式职业基线、技能规格、英雄规格、接入契约和对应模板版本 |
| 执行门禁 | 地图路径、脚本根、编辑器连接、生产 ID、图标、模型、距离、模板与 feature-based hooks |
| 状态 | reviewed、offline-stage-accepted、construction-ready、verified 的事实边界 |

只有全部生产门禁和职业实际使用的 feature gate 已解锁后，命令构建器才可输出“效果 -> 技能 -> 英雄”的生产命令。任意未解锁门禁必须拒绝输出，不能生成半成品。

## 五、施工验收

1. 预检验证资产数量、稳定键、等级数组、依赖、A/B 层和 feature gate 完整性。
2. 命令构建器使用合成数据验证顺序与字段；真实清单未就绪时验证拒绝路径。
3. 纯 Lua 覆盖资源、技能、效果、死亡、挑战与多实例隔离。
4. 桥接测试覆盖显式目标、共享效果回退、控制租约、每目标品级、伤害资格、减伤与生命周期。
5. 桥接层只使用固定公开 API，不出现 GameAPI、GlobalAPI 或 CAPI 直调。
6. 离线通过只能标为 reviewed 或 offline-stage-accepted；必须完成对象回读、脚本根加载和真实多人测试后才可标为 verified。
