## 三、下一次施工的推荐顺序

1. 将 `economy-v2` 基表、`economy-v3` 路线选择与三篇成长谱系合同编译为地府／天庭的具体 XP `source_profile`、次数与舍入表；天庭只能在既有零价值完成/会话输入交接基础上显式分配，不能从副本名、凭证或材料候选自动推导。装备、法宝、宠物数值继续另包裁决。
2. 将已验收的 `economy-v2` 离线合同移交为生产架构规格：独立受审计编译/哈希链、持久化账本、真实 proof-to-owner/快照/roll 服务、跨进程锁与重连对账；不得复用 `implementation/growth/` 的 `f6h-v1` 夹具或内存参考充当实现。
3. 用 `y3-object-config` 生成装备、法宝、材料、宠物对象的可审阅配置；真实 ID 与资源查询后才可落地命令。
4. 在上述实现方案通过审查后，用 `y3-lua-api` 实现经验授予、等级全量重算、技能点事务、存档迁移、掉落资格与保底权威结算。
5. 用官方 `y3-ui-pipeline` 制作等级/经验、技能树、构筑、背包装备、强化法宝、收集、通天塔和结算界面。
6. 恢复 Y3 编辑器接入后，按“对象回读 -> 单人断线/重连 -> 四人公共 BOSS -> 副本/通天塔 -> 零付费样本”执行实机验收。

## 四、离线验证边界

独立成长系统本轮可验证的只有规格包的 JSON 结构、完整性评分、Markdown 链接和文本一致性；它们证明的是“规格可交接”，不证明经验、路线试炼、存档、装备、掉落或完整成长逻辑已经可运行。既有花果山旧潮入口另有一项定向离线边界：受信任进度查询会携带当前职业的 Lv8 路线要求，`test_instances.lua` 以 297 条断言验证缺失/交叉/错误选中路线与调用方伪造均被拒绝。该证据只证明入口门槛转发，不代表已实现路线试炼或成长存档。

未来独立预检至少要覆盖：稳定键唯一性、`economy-v2` 基表与 `economy-v3` 覆盖层的哈希/版本精确绑定、鹏魔王／裂口恰选、桃林／蝙蝠窟必经公共语义与历史收据不重算、Lv20/Lv41 同角色交接、经验表连续性、等级/技能点守恒、属性全量重算幂等、装备与材料引用闭合、花果山 profile 设计引用、资格字段分层、proof-to-owner 映射、来源身份/指纹冲突、公共稀有-参与箱绑定、周桶/余额封顶、重复事件/重连/版本迁移负例，以及商业字段拒绝路径。

## 五、当前风险

- 项目具有长期存档 ORPG 特征，必须把公共地图与副本/塔层拆成可重复、权威结算的 Y3 会话，不能把无限持久在线世界当作实现前提。
- `economy-v2` 已冻结但尚未接入；若将 `f6h-v1` 或白盒字段替代它，会造成版本漂移和迁移债务。
- 花果山候选参与字段不是正式 P1；若实现把 `effective_participant_ids` 或 public action 直接当参与箱/稀有输入，会破坏已冻结资格分层。
- 现有直接物化器尚不支持 `item`；物品对象施工应作为独立工程任务，不能绕过受信任边界。
