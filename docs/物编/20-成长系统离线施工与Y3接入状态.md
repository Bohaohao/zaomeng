# 成长系统离线施工与 Y3 接入状态

## 状态摘要

- 版本：`v1.0-spec`。
- 建立日期：`2026-07-17`。
- 设计规格：已完成归一化，见 [18-成长系统进度、掉落与长期目标契约](18-成长系统进度、掉落与长期目标契约.md) 与 [19-装备、法宝、宠物与材料物编规格](19-装备、法宝、宠物与材料物编规格.md)。

- 真实 Y3 接入：未开始；无真实地图工程、对象 ID、资源映射、编辑器查询/热更/保存或实机验证证据。

- 阶段归档：[成长系统规格整包归档](../归档/物编施工/02-成长系统规格整包归档.md)；当前详细来源仍以 18-20 与规格包为准。
- 规格验证：`design-spec.json` 已通过结构验证；完整性评分 `100/100 (ready)`，另有 9 项明确待决。项目级目标会话时长尚未提供，因此结构校验保留一条时长缺失警告。该证据只证明规格可交接。

## 一、当前已具备的证据

| 范围 | 现状 | 证据边界 |
|---|---|---|
| 四职业等级基础层 | 已有四份白盒属性公式与关键等级表 | 仅职业裸装成长与离线验证；不是统一装备平衡或实机数值 |
| 花果山对象与遭遇 | 已有离线预施工包、公共遭遇逻辑和回归 | 真实对象、地图脚本根、内部地图绑定和实机仍未完成 |
| 花果山奖励 profile | `HG_DROP_*`、参与/破韧等稳定键已存在 | 所有掉落 profile 仍为 `deferred`，未配置物品、概率、保底或货币 |

本轮不会把花果山 `reward_exp` 白盒候选、`effective_participant_ids`、`HG_DROP_*` 名称或旧文档示例视为生产数据。尤其不得将公共 BOSS 有效参与直接解释为参与箱、稀有掉落或保底资格。

## 三、下一次施工的推荐顺序

1. 完成经验、货币、装备部位、掉落/保底与参与箱资格的数值/政策决策。
2. 基于 18/19 建立独立 `implementation/growth/` 离线数据包与预检；不得复用花果山的硬编码预检或物化器充当成长系统验证。
3. 用 `y3-object-config` 生成装备、法宝、材料、宠物对象的可审阅配置；真实 ID 与资源查询后才可落地命令。
4. 用 `y3-lua-api` 实现经验授予、等级全量重算、技能点事务、存档迁移、掉落资格与保底权威结算。
5. 用官方 `y3-ui-pipeline` 制作等级/经验、技能树、构筑、背包装备、强化法宝、收集、通天塔和结算界面。
6. 恢复 Y3 编辑器接入后，按“对象回读 -> 单人断线/重连 -> 四人公共 BOSS -> 副本/通天塔 -> 零付费样本”执行实机验收。

## 四、离线验证边界

独立成长系统本轮可验证的只有规格包的 JSON 结构、完整性评分、Markdown 链接和文本一致性；它们证明的是“规格可交接”，不证明经验、路线试炼、存档、装备、掉落或完整成长逻辑已经可运行。既有花果山旧潮入口另有一项定向离线边界：受信任进度查询会携带当前职业的 Lv8 路线要求，`test_instances.lua` 以 297 条断言验证缺失/交叉/错误选中路线与调用方伪造均被拒绝。该证据只证明入口门槛转发，不代表已实现路线试炼或成长存档。

未来独立预检至少要覆盖：稳定键唯一性、经验表连续性、等级/技能点守恒、属性全量重算幂等、装备与材料引用闭合、掉落 profile 不再是 `deferred`、资格字段分层、重复事件/重连/版本迁移负例，以及商业字段拒绝路径。

## 五、当前风险

- 项目具有长期存档 ORPG 特征，必须把公共地图与副本/塔层拆成可重复、权威结算的 Y3 会话，不能把无限持久在线世界当作实现前提。
- 经验、经济和掉落数值尚未定；现在进入实现会导致多份临时公式和迁移债务。
- 花果山参与箱口径存在 P1 冲突；在解决前只能记录证据，不应授予奖励。
- 现有直接物化器尚不支持 `item`；物品对象施工应作为独立工程任务，不能绕过受信任边界。
