# 装备、法宝、宠物与材料物编规格

## 文档状态

- 版本：`v1.0-spec`。
- 状态：`normalized / review-ready / no-y3-id-assigned`。
- 建立日期：`2026-07-17`。
- 上位契约：[18-成长系统进度、掉落与长期目标契约](18-成长系统进度、掉落与长期目标契约.md)。
- 执行边界：[00-物编模板与执行规范](00-物编模板与执行规范.md)。

本文件建立装备、法宝、宠物、材料、货币和掉落 profile 的统一记录方式。它把内容严格拆为 `item_asset`、`pet_unit + pet_ability`、`currency_ledger` 与 `drop_policy` 四类；只定义已知的分类、字段责任和待决门禁，不分配 Y3 ID、图标、模型、物品数值、配方、概率或保底。

花果山的逻辑奖励键、材料键和收据语义仍以 `economy-v2` 基表为准；`economy-v3` 只覆盖未来花果山首通 XP 路线及 `XP_PEACH`／`XP_CAVE` 的必经公共主线语义，不能被误读为装备、法宝、材料、掉落或配方表。

## 一、已锁定的内容边界

| 系统 | 已锁定方向 | 未锁定内容 |
|---|---|---|
| 装备 | 普通/精良/稀有/史诗/传说五品质；金币+强化石强化；低阶装备可保留来源与前序状态地进入进阶／替换链；2/4 件套；三城装备阶级。花果山已采纳逻辑奖励键的阶段位置见成长谱系合同。 | 部位、职业限制、基础数值、词条池、强化/进阶公式、套装数值 |
| 法宝 | v1 一个活动法宝槽；可拥有多个法宝但不得默认同时启用。`ART_HG_TIDE_SEAL` 与 `ART_HG_FLAME_CORE` 分别是可选早期／可选稀有横向法宝；词条、洗炼、追加、升阶仍须审计。 | 具体词条、配方、数值、绑定与保底 |
| 宠物 | 宠物本体将走单位+技能而不是物品；龙蛋孵化的成长型宠物龙与白牛目前都只是未来候选，尚未进入首发已采纳资产或宠物链。 | 正式接入阶段、槽位、相性、成长率、技能槽、孵化材料与数值 |
| 材料 | `MAT_STRENGTHEN_SHARD`、`MAT_ADVANCE_HG`、`MAT_ARTIFACT_DUST` 已由当前经济表冻结为角色绑定材料键；强化／进阶／法宝用途族与跨篇保留边界见成长谱系合同。 | 具体配方、消耗数量、Difu／天庭材料键、资源吞吐与物品对象字段 |
| 货币 | `CUR_GOLD`、`CUR_RAID_MARK`、`CUR_TOWER_TOKEN` 已由当前经济表冻结为角色余额键。 | 具体消耗、兑换目录、服务、UI 与运行时账本 |
| 掉落 | 花果山的 `HG_DROP_*` profile、资格、首通、概率和保底由当前经济表冻结；其逻辑奖励键不是 Y3 物编 ID。 | Difu／天庭掉落、实际 Y3 资产、roll 服务、持久化与运行时结算 |

## 二、资产与系统记录头

装备、法宝、材料和龙蛋等可携带资产才使用下列 `object_type: item` 记录头：

```yaml
record_key: planned_unique_key
object_type: item
status: planned
operation: create
y3_id: 待查询分配
name: 待定
chapter: 花果山篇/地府篇/天庭篇/跨篇
design_role: 成长用途
source_doc: docs/物编/19-装备、法宝、宠物与材料物编规格.md
dependencies: []
model_id: 待查询
icon_id: 待查询
y3_fields: {}
runtime_fields: {}
acceptance: []
notes: []
```

宠物本体使用 `object_type: unit`，其技能使用 `object_type: ability`，分别沿用既有单位/技能记录头，并以稳定 `pet_key`、`pet_ability_keys`、`growth_profile`、`storage_rule` 与孵化来源建立关联。货币账本和掉落 profile 是系统数据：它们有稳定键、版本、来源、消耗或资格字段，但不声明 `object_type`、不分配 Y3 物编 ID，也不进入物品创建命令。

| 层级 | 可以记录 | 不可以伪装为已落地 |
|---|---|---|
| A 层：Y3 物品/单位/技能资产 | 物品的 `name`、`description`、`icon`、`model`、`level`、堆叠/充能、可丢弃、`attached_*`；宠物单位和宠物技能各自可表达的基础字段 | 真实 ID、资源 ID、未确认的字段枚举、随机词条和复杂成长逻辑 |
| B 层：成长系统规则 | 物品的部位、品质、职业限制、词条、强化、进阶、洗炼、追加、合成、绑定、存档；宠物的相性、成长、孵化、技能槽；系统的货币账本、掉落 profile、保底与资格 | 不能仅因写在 B 层就声称已有 Lua、Y3 对象或实机验证 |

所有未来稳定键需在同类资产内唯一。真实 `y3_id` 只能在查询现有工程、确认 ID 台账和资源映射后写入；本项目当前没有可用的真实地图工程或编辑器回读，不得猜测。

## 三、装备数据契约

```yaml
runtime_fields:
  item_category: equipment
  equipment_slot: pending
  quality: common | fine | rare | epic | legendary
  profession_limit: pending
  level_requirement: pending
  base_stat_profile: pending
  fixed_affixes: []
  random_affix_pool: pending
  random_affix_count: pending
  strengthen_rule: pending
  advance_rule: pending
  set_key: pending
  set_piece_index: pending
  bind_rule: pending
  storage_rule: character_persistent
  drop_profile: pending
```

规则：

1. 同一装备的强化、进阶和套装状态属于长期角色状态，不能在重连或构筑切换时重复叠加。
2. “低阶装备可进阶”意味着进阶链必须保留来源、前序状态和材料消耗审计；不允许把原装备直接无记录替换为不可追踪的新物品。
3. 2 件与 4 件套只定义为已确认的触发数量；具体套装部位、效果与强度仍为待决项。
4. 装备品质不是稀有掉落资格。掉落资格、保底和物品品质必须由不同字段与日志表达。

```yaml
  active_ability_key: pending

  random_affix_count: pending
  refine_rule: pending
  append_rule: pending
  advance_rule: pending
  synthesis_recipe: pending

```

首发已知链路以[三篇成长谱系合同](成长数值与经济裁决包/three-chapter-growth-lineage-contract.json)为准：`ART_HG_TIDE_SEAL` 仅对完成可选龙宫旧潮首通的角色保证，`ART_HG_FLAME_CORE` 是牛魔旧战场的可选稀有横向法宝，二者在一个活动法宝槽中切换而不默认叠加。旧“龙王一阶段五件装备→一阶法宝、二阶段装备→二阶、牛魔号角”只保留为未来候选，不得充当当前首法宝、主线或经济消耗规则。法宝词条数量随阶级增加仍只是方向性结论，具体条数、主动技能数值与第二效果均不得提前填写。

```yaml
  currency_key: pending
```

- 龙蛋不是宠物本体；它必须匹配相性材料完成孵化，孵化后的宠物数据与材料消耗都需独立记录。
- 白牛是成长型宠物方向，不等于已经创建的宠物单位或已配置掉落。
- 当前经济表已冻结 `CUR_GOLD`、`CUR_RAID_MARK` 与 `CUR_TOWER_TOKEN` 的逻辑账本键和角色所有者；真实余额、兑换、商城、产出结算和 Y3 对象仍不得由本文件创建。

## 六、掉落 profile 与资格接口

现有花果山资产已使用 `drop_profile`、`reward_exp`、`reward_official_res_1`、`level_band`、`participation_profile` 和 `break_profile` 等字段。本规格规定：

1. 花果山 `HG_DROP_*` 的具体来源、资格、奖励、概率、保底和收据以当前经济表为唯一基线；同名旧 manifest 只保留为候选遭遇证据，不能覆盖该表。
2. `reward_exp` 白盒值不可反推出经验曲线；`reward_official_res_1=0` 不可解释为已设置或未设置金币。
3. 掉落结算至少携带 `source_profile`、`encounter_instance_id`、`actor_id`、`qualification_snapshot_id`、`drop_roll_id` 和 `resource_table_version`；字段名称可随实现载体调整，语义不得缺失。
4. `progression_participation`、参与箱、稀有资格、保底进度、DPS 荣誉与掉落 roll 必须是独立决策。现有公共 BOSS 的 `effective_participant_ids` 只能作为一份资格证据。
5. 新增装备、法宝、材料和龙蛋使用 `planned item_asset`；宠物使用 `planned pet_unit + pet_ability`；货币与掉落 profile 使用 `planned` 系统记录。花果山已采纳的逻辑资源键仍须在来源、消耗、资格、概率／确定性进度和回收路径确认后才能进入物编施工。
6. 未来保底和发奖状态必须独立保存 `pity_progress`、`drop_receipt_ledger`、权威 `event_id`、`resource_table_version`、`schema_version` 与 `owner_scope`。具体按角色、账号、队伍、赛季或其他主体归属仍待决，但在确定前不得实现或迁移任何余额、保底或收据。

## 七、商业与公平门禁

任何物品设计不得改变自由技能点、技能等级上限、五主动槽位、职业资源、伤害/生存、装备/法宝/宠物强度或养成速度、公共 BOSS 资格、稀有资格、保底进度和通天塔门槛。未登记字段默认禁止进入商业设计；尚未批准商品、价格、概率、礼包、SKU 或便利倍率。

## 八、对象施工验收与待决项

### 8.1 进入物编前必须满足

- [ ] 每个物品资产、宠物单位/技能和系统记录都有唯一稳定键、类别、来源、依赖与正确的施工归属。
- [ ] 每个装备/法宝/宠物/材料都有已确认的长期存档与迁移责任；货币账本和掉落 profile 有独立版本与审计责任。
- [ ] 所有引用的掉落 profile 已有独立资源表和资格规则，未再使用 `deferred` 占位。
- [ ] 真实 Y3 ID、模型、图标、字段枚举、物品模板和宠物单位/技能模板均已查询回读；货币账本和掉落 profile 不要求 Y3 物编 ID。
- [ ] 强化、进阶、词条、合成和保底都具备幂等事务与重复请求保护。
- [ ] 零付费路径已经通过成长与公共 BOSS 门禁验证。

### 8.2 仍待用户/数值阶段决定

1. 装备部位、职业限制、所有属性与词条表、强化/进阶/套装公式。
2. 除 v1 单一活动法宝槽外，法宝和宠物的槽位、词条池、配方、相性、成长和绑定。
3. 每种材料与货币的稳定键、堆叠、来源、消耗、上限和回收。
4. 所有掉落、保底、分配、重复收益衰减与资源吞吐数值。
5. 花果山旧 manifest 与正文对当前 `economy-v2` P1 收据语义的持续一致性回归；不得重新打开已采纳的参与箱规则。
