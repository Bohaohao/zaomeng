# 三篇成长路线离线合同

本组文件只解决“设计路线是否连续”的审计问题，不是 Y3 物编、Lua、存档、奖励表或经济执行输入。

- `tables/economy-v3-resource-table.json` 是对 `economy-v2` 的显式未来路线覆盖层。它用“鹏魔王”与“裂口发现”的二选一，修复可选 Boss 被误计入硬性升级路线的问题；同时把 `XP_PEACH`／`XP_CAVE` 仅在未来路线中绑定为桃林／蝙蝠窟必经公共主线语义。总 XP、Lv19/Lv20 锚点、55 分钟锚点与既有收据均不变。
- `three-chapter-growth-lineage-contract.json` 冻结 Lv20→地府→Lv41 + 阎罗殿交接证明→天庭→Lv60 的设计级连续关系，及装备、法宝、材料、货币的当前边界。
- 合同中的 `design_route_node_map` 明确地府常规顺序“花果山证明/Lv20 → 鬼城首段（既有 1250 XP 跨 Lv21 门槛）→ 无常巷 → 鬼门关 → 接引院 → 判官殿 → 阎罗殿”，以及天庭常规顺序“Lv41 + 阎罗殿证明 → 裂云南天门 → 断虹阵 → 四门失衡 → 周天观台 → 凌霄外庭”。节点仅标记既有主线/公共/单人预算类，`actual_source_profile` 与具体奖励均保持 `null`。
- 白骨秘境、转轮殿、七星、二十八星宿和稀有路径只能作为非阻塞的等额替代候选；全局通天塔固定为零 XP，均不得倒灌成主线前置。
- 地府、天庭仍没有实际 XP `source_profile` 分配；预算只是防止以后分配时超出总量或把团队、稀有、可选内容变成主线硬门槛。
- 花果山现有两件法宝均为可选横向选择。地府与天庭的具体资产、属性、配方、替换与升级规则保持 `null/deferred`。

运行以下命令进行离线自检：

```powershell
& '.\validate-three-chapter-growth-continuity.ps1'
```

校验器会锁定 v2 的 SHA-256、v3 的分支数学/反双领/两项未来公共主线语义、两篇主线节点顺序、Lv20–60 预算、零塔 XP、装备/法宝非强制边界，以及所有运行时和经济执行门禁。
