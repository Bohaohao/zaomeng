# 成长数值与经济标定候选

## 定位

这是成长数值与经济裁决包的采纳前工作台：它把可引用的结构事实、带 SHA-256 的来源文件、花果山白盒观测、必须公开的假设和等待实测的输出分开。它不新增当前基线，不改变 `decision-register.json` 中任何既有决策的状态，也不解除 `implementation/growth` 门禁。

唯一机器可读入口是 [calibration-candidates.json](calibration-candidates.json)。它由父目录的 [语义校验器](../validate-growth-economy-decision-package.ps1) 一并读取和验证。

## 四个候选场景

| 场景 | 当前仅做什么 | 明确不做什么 |
|---|---|---|
| `CAL-XP-HG-LV1-20-001` | 用 Lv1-20、Lv8 路线和花果山内容密度定义经验实测样本 | 不填写正式经验曲线或组队分配。 |
| `CAL-THROUGHPUT-HG-PUBLIC-001` | 采样公共 BOSS 的资格证据、重放和断线边界 | 不发参与箱、不激活掉落、不定义概率或保底。 |
| `CAL-ECON-SINK-RELATIVE-001` | 比较成长来源族与消耗族需要收集的证据 | 不定义货币、物品键、价格、余额、配方或交易。 |
| `CAL-OX-RETRY-TIME-PRESSURE-001` | 分开记录牛魔失败循环的战斗压力与未来奖励政策 | 不从 `+5% / 5 分钟`推导任何奖励补偿。 |

## 使用规则

- `reward_exp`、`reward_official_res_1`、刷新字段和 `HG_DROP_*` 只可作为观测或来源标签；不能变成生产经验、金币、概率、保底或吞吐。
- 花果山的 10-15 分钟 Lv8 路线窗口、约 55 分钟重复循环仅是首日内容密度参考，绝不是项目级会话时长承诺。
- 每个未来数值都需要来源文件哈希或白盒快照、明确单位、假设、实测方法、收据/版本策略和用户明确采纳；缺一项即保持空值。当前 `candidate_value` 的每个字段都必须为 JSON `null`。
- 候选 JSON 是封闭字段结构：未知字段、空/无效来源、无关快照，以及没有精确绑定自身白盒来源的场景，都会被语义校验器拒绝。
- `ECO-P1-001` 仍是 conflict。在唯一 `final_policy_id` 获采纳前，公共 BOSS 只能采样资格证据，不能产生任何参与箱、稀有资格或保底结论。

## 采纳后才可发生的事

只有在经验、物品/货币、掉落/保底、P1 和通天塔的 implementation-critical 决策均被明确采纳，并且本候选包的实测证据通过审阅后，才可以建立独立 `implementation/growth/` 数据包。届时仍需重新验证资源表版本、所有者范围、收据幂等、迁移、零付费 30/60/90 分钟路径和真实 Y3 接入。
