## 四、恢复真实接入与验证后的执行顺序

1. 确认脚本根是 `maps/EntryMap/script` 或 `global_script/map`。
2. 查询现有自定义单位、技能、魔法效果和官方资源。
3. 为 1 个英雄、18 个技能和 12 个效果建立不冲突 ID 台账。
4. 回读近战英雄模板、被动技能模板和距离尺度；只有项目内置库冲突时才重新核对 `ability_cast_type`。
5. 更新预施工清单的全部 execution gates，并运行强制就绪预检。
6. 按“12 效果 -> 18 技能 -> 1 英雄”的顺序创建对象。
7. 一批对象只热更一次，等待 3 秒后保存并回读字段。
8. 将离线模块和现有 Y3 桥接复制到正确脚本根，填入 ID 映射和目标筛选器；若项目 `y3/` 版本不同，重新执行 API 对照。
9. 启动游戏，执行单人、四名同职业、死亡、重连、入本清理和 90 秒循环测试。
10. 只有对象回读和运行时验收全部通过后，才把状态提升为 `verified`。
