# 物编模板与执行规范

## 文档定位

本文件依据 `y3-obj-edit v5.0` 的技能说明、五份 `reference` 文档和当前 `y3_obj_edit.py` 脚本建立，是本项目后续物编设计、审核和执行的统一模板。

当前只确认模板口径，不分配真实 Y3 物编 ID，不创建或修改任何物编。

## 核心结论

`y3-obj-edit` 当前稳定支持五类物编：

| 对象类型 | `-type` | 创建基础模板 | 适用内容 |
|---|---|---|---|
| 单位 | `unit` | 按单位类型选择单位模板 | 英雄、普通怪、精英、BOSS、NPC、建筑 |
| 技能 | `ability` | `jn.json` | 主动技能、被动技能的基础物编 |
| 魔法效果 | `modifier` | `mfxg.json` | Buff、Debuff、护盾、光环 |
| 投射物 | `projectile` | `tsw.json` | 弹道和飞行特效载体 |
| 物品 | `item` | `wp.json` | 装备、材料、消耗品、法宝本体 |

必须遵守：

1. 查询已有物编使用 `y3editor` MCP。
2. 创建和修改使用 `y3_obj_edit.py`，不直接读取或编辑生成的物编 JSON。
3. 创建前查询现有 ID，禁止猜测或直接占用 ID。
4. 模型、头像、图标和特效 ID 必须从项目资源或官方资源查询结果中选择。
5. 一批物编全部处理完成后，只执行一次热更、等待 3 秒、保存。
6. 复杂玩法字段必须与基础物编字段分层记录，不能伪装成脚本已经支持的参数。

## 两层模板结构

本项目物编记录统一拆成两层。

### A 层：Y3 基础物编

只填写 `y3_obj_edit.py` 已明确支持、能够通过脚本创建或修改的字段。

### B 层：系统与运行时规则

记录脚本当前不能直接实现，但项目玩法需要的字段。后续根据性质交给 Lua、数据表、掉落系统、存档系统或专用物编扩展处理。

典型 B 层字段：

- 怪物 AI 状态机、巡逻和仇恨规则。
- 技能伤害公式、属性倍率、命中判定和多阶段逻辑。
- BOSS 转阶段、召唤时机、团灭和狂暴规则。
- 装备部位、职业限制、品质、随机词条和套装。
- 强化、进阶、洗炼、追加、合成和保底。
- 法宝成长、宠物相性、成长率、孵化和技能槽。
- 掉落池、归属、个人奖励、DPS 参与判定和副本锁。

## 统一记录头

每个物编对象先填写以下记录头，再进入对应类型字段。

| 字段 | 必填 | 说明 |
|---|---|---|
| `record_key` | 是 | 策划侧稳定键，例如 `hg_unit_mountain_monkey`；不等于 Y3 ID |
| `object_type` | 是 | `unit / ability / modifier / projectile / item` |
| `status` | 是 | `draft / reviewed / id-assigned / implemented / verified` |
| `operation` | 是 | `create / edit` |
| `y3_id` | 执行前必填 | 默认写 `待查询分配`，必须查询现有物编后确定 |
| `name` | 是 | 游戏内名称 |
| `chapter` | 是 | 所属篇章或系统，例如 `花果山篇` |
| `design_role` | 是 | 战斗、成长或叙事定位 |
| `source_doc` | 是 | 需求来源文档 |
| `dependencies` | 否 | 依赖的技能、效果、投射物、物品或单位 `record_key` |
| `model_id` | 按类型 | 单位模型或掉落模型；执行前必须查询 |
| `icon_id` | 按类型 | 头像、技能图标、效果图标或物品图标；执行前必须查询 |
| `y3_fields` | 是 | A 层字段，只使用脚本支持的参数 |
| `runtime_fields` | 否 | B 层系统与 Lua 字段 |
| `acceptance` | 是 | 可验证的验收条件 |
| `notes` | 否 | 风险、待定项和资源替代方案 |

推荐记录骨架：

```yaml
record_key: hg_unit_example
object_type: unit
status: draft
operation: create
y3_id: 待查询分配
name: 待定
chapter: 花果山篇
design_role: 待定
source_doc: docs/08-花果山篇野外怪物与BOSS设计.md
dependencies: []
model_id: 待查询
icon_id: 待查询
y3_fields: {}
runtime_fields: {}
acceptance: []
notes: []
```

## 单位模板

### 创建必填字段

```text
-create "单位ID,名称,单位类型,模型ID,头像ID"
```

脚本接受的单位类型：

| 单位类型 | 底层模板 | 项目用途 |
|---|---|---|
| `近战小怪` | `jzxg.json` | 近战普通怪 |
| `远程小怪` | `ycxg.json` | 远程普通怪 |
| `近战精英` | `jzboss.json` | 近战精英和大精英 |
| `远程精英` | `ycboss.json` | 远程精英和大精英 |
| `近战boss` | `jzboss.json` | 近战 BOSS |
| `远程boss` | `ycboss.json` | 远程 BOSS |
| `近战英雄` | `jzyx.json` | 近战玩家角色 |
| `远程英雄` | `ycyx.json` | 远程玩家角色 |
| `建筑` | `jz.json` | 固定单位和建筑载体 |

`近战精英` 与 `近战boss` 共用底层模板，远程类型同理。精英和 BOSS 的差异仍需通过数值、技能、AI、奖励和运行时规则表达。

### A 层字段

| 分类 | 脚本参数 |
|---|---|
| 基础信息 | `name`、`description`、`model`、`icon` |
| 生存 | `hp_max`、`hp_max_grow`、`mp_max`、`mp_max_grow` |
| 攻击 | `attack_phy`、`attack_phy_grow`、`attack_mag`、`attack_speed`、`attack_interval`、`common_atk_type` |
| 防御 | `defense_phy`、`defense_mag` |
| 移动感知 | `ori_speed`、`turn_speed`、`sight_range` |
| 射程 | `attack_range`、`common_atk_range` |
| 奖励 | `reward_exp`、`reward_official_res_1` |
| 技能绑定 | `hero_ability_list`、`common_ability_list` |

### 单位填写规则

- 实际普攻射程统一使用 `common_atk_range`；它会同步根级和 `simple_common_atk.attack_range`。
- 当前脚本的 `create_unit` 没有应用 `common_atk_range`，只有 `edit_unit` 会处理该参数。执行时必须先创建单位，再补一条最小 `-edit` 命令设置实际普攻射程；或者先修复并验证脚本，不能假设创建命令已经生效。
- `ori_speed` 使用引擎坐标/秒，不是厘米/秒。普通怪可从 `2.0` 附近测试，英雄通常为 `3.0-5.0`。
- 技能列表按 `技能ID:初始等级` 填写，不使用只有技能 ID 的单元素写法。
- 当前脚本没有开放魔法攻击成长、防御成长、仇恨、碰撞体积、AI 和掉落池字段。

### B 层补充字段

```yaml
runtime_fields:
  rank: 普通怪/精英/大精英/区域BOSS/副本BOSS/团本BOSS
  zone: 所属区域
  faction: 阵营
  aggro_rule: 仇恨与脱战
  ai_pattern: 行为状态机
  leash_range: 追击边界
  collision_scale: 碰撞候选
  phase_rule: 阶段规则
  drop_profile: 掉落表稳定键
  participation_rule: 击杀与参与归属
```

## 技能模板

### 创建必填字段

```text
-create "技能ID,名称,图标ID"
```

### A 层字段

| 分类 | 脚本参数 |
|---|---|
| 基础 | `name`、`description`、`ability_icon`、`ability_max_level` |
| 释放 | `ability_cast_type`、`ability_cast_point`、`ability_bw_point`、`is_immediate`、`is_meele` |
| 指示器 | `sight_type`、`circle_radius`、`sector_radius`、`sector_angle`、`arrow_length`、`arrow_width` |
| 等级数值 | `cold_down_time`、`ability_cost`、`ability_hp_cost`、`ability_damage`、`ability_damage_range`、`ability_cast_range` |
| 学习 | `required_level` |

`sight_type` 稳定取值：

| 值 | 指示器 |
|---:|---|
| `0` | 无指示器 |
| `1` | 扇形 |
| `2` | 箭头 |
| `3` | 圆形选点 |
| `4` | 目标单位/物品/可破坏物 |
| `5` | 单位或地点 |
| `6` | 建造 |
| `7` | 多段或向量 |

### 技能填写规则

- 所有等级数组长度必须与 `ability_max_level` 一致。
- `ability_cast_type` 的具体枚举不能猜测，执行前从现有技能或完整 Y3 字段文档确认。
- `ability_damage` 只适合简单固定数值。属性倍率、多段伤害、条件增伤和阶段逻辑放入 B 层。
- 技能机制涉及单位创建、位移、计时器、伤害计算或状态清理时，后续交给 Lua 流程实现。

### B 层补充字段

```yaml
runtime_fields:
  trigger: 触发时机
  target_filter: 目标筛选
  damage_formula: 伤害公式
  hit_count: 命中段数
  movement_rule: 位移与击退
  summon_rule: 召唤规则
  applied_modifiers: 效果record_key列表
  projectile: 投射物record_key
  phase_interaction: BOSS阶段交互
  cleanup_rule: 中断、死亡和离场清理
```

## 魔法效果模板

### 创建必填字段

```text
-create "效果ID,名称,图标ID"
```

### A 层字段

| 分类 | 脚本参数 |
|---|---|
| 基础 | `name`、`description`、`modifier_icon` |
| 分类 | `modifier_type`、`modifier_effect` |
| 层数与显示 | `layer_max`、`disappear_when_dead`、`show_on_ui` |
| 护盾 | `shield_value`、`shield_type` |
| 光环 | `influence_rng`、`is_influence_self` |
| 表现 | `material_color` |

稳定枚举：

- `modifier_type`：`1` 正常、`2` 光环、`3` 光环效果、`4` 护盾。
- `modifier_effect`：`1` 正常、`2` 正面、`3` 负面。
- `shield_type`：`0` 物理、`1` 法术、`2` 通用。

### B 层补充字段

当前脚本没有开放持续时间、周期触发、属性修改、控制状态、驱散规则和覆盖优先级等关键字段，统一记录为：

```yaml
runtime_fields:
  duration: 持续时间
  refresh_rule: 刷新规则
  stack_rule: 叠层规则
  dispel_rule: 驱散规则
  periodic_interval: 周期
  periodic_effect: 周期效果
  stat_changes: 属性修改
  control_flags: 控制状态
  source_binding: 来源绑定
  cleanup_rule: 清理规则
```

## 投射物模板

### 创建必填字段

```text
-create "投射物ID,名称,图标ID"
```

### A 层稳定字段

| 分类 | 脚本参数 |
|---|---|
| 基础 | `name`、`description`、`icon` |
| 生命周期 | `max_duration` |
| 移动通道 | `move_channel`、`move_limitation` |
| 表现 | `sfx_loop`、`effect_foes`、`effect_friend` |

`move_channel`：`0` 地面，`1` 空中。

`move_limitation` 为位掩码。地面通道使用 `1` 陆地、`2` 物件、`4` 海洋、`8` 悬崖；空中通道使用 `1`。

### 脚本与文档差异

当前脚本还注册了 `effect_fly`，但 `reference/projectile.md` 没有把它列入稳定参数表。项目模板暂将其标记为实验字段，必须经过一次创建、热更和回读验证后才能升为稳定字段。

### B 层补充字段

```yaml
runtime_fields:
  speed: 飞行速度
  acceleration: 加速度
  trajectory: 直线/追踪/抛物线/回旋
  collision_rule: 碰撞规则
  hit_limit: 命中上限
  pierce_count: 穿透次数
  bounce_rule: 弹射规则
  impact_effect: 命中效果
  expire_effect: 到期效果
```

## 物品模板

### 创建必填字段

```text
-create "物品ID,名称,图标ID"
```

| 分类 | 脚本参数 |
|---|---|
| 基础 | `name`、`description`、`icon`、`model`、`level` |
| 堆叠充能 | `maximum_stacking`、`maximum_charging`、`cur_stack`、`cur_charge`、`use_consume` |
| 行为 | `auto_use`、`discard_enable`、`discard_when_dead`、`delete_on_discard`、`sale_enable` |
| 地面掉落 | `drop_stay_time`、`hp_max` |
| 生存属性 | `attached_hp_max`、`attached_hp_rec`、`attached_mp_max`、`attached_mp_rec` |
| 攻击防御 | `attached_attack_phy`、`attached_attack_mag`、`attached_defense_phy`、`attached_defense_mag` |
| 主属性 | `attached_strength`、`attached_agility`、`attached_intelligence` |

所有 `attached_*` 属性按五元素数组记录：

```text

```

```yaml

  item_category: 消耗品/装备/材料/法宝/任务物品/特殊道具
  equipment_slot: 装备部位
  quality: 品质
  profession_limit: 职业限制
  level_requirement: 使用等级
  fixed_affixes: 固定词条
  random_affix_pool: 随机词条池
  random_affix_count: 随机词条数
  strengthen_rule: 强化规则
  advance_rule: 进阶规则
  refine_rule: 洗炼规则
  append_rule: 追加词条规则
  synthesis_recipe: 合成配方
  bind_rule: 绑定规则
  storage_rule: 存档规则
  drop_profile: 掉落表稳定键
```

物品基础模板本身不能完成随机词条、强化、进阶、洗炼和合成，这些必须由项目系统层实现。

## 项目系统到物编类型的映射

| 项目内容 | Y3 基础物编 | 系统层补充 |
|---|---|---|
| 普通怪、精英、BOSS | 单位 + 技能 + 效果 + 投射物 | AI、阶段、掉落、参与归属 |
| 装备 | 物品 | 部位、职业、品质、词条、强化、进阶 |
| 法宝 | 物品 + 主动/被动技能 | 随机词条、洗炼、追加、合成、升阶 |
| 宠物 | 单位 + 技能 | 相性、成长率、孵化、技能槽、存档 |
| 候选龙髓、逆鳞、龙蛋 | 尚未确定（若采纳可能为物品） | `candidate_only`；稳定键、配方、孵化、用途与施工状态均为 `deferred` |
| 牛气冲天（牛魔旧战场有限失败机制） | 已登记的离线 modifier／可见状态 `HG_M_OX_ARROGANCE`；真实 Y3 ID 未分配 | 状态机、有限层数、属性变化、倒计时、失败续期与清零只以 [花果山遭遇与 BOSS 战斗契约](15-花果山遭遇与BOSS战斗契约.md#hg_e_ox_battlefield牛魔旧战场) 为唯一详细来源；本表不另立数值或奖励规则，掉率补偿仍为 `deferred`，不得宣称无上限叠层或既定掉率补偿 |
| 公共 BOSS 击杀归属 | 无独立物编 | DPS 统计、队友大于 10% 同步计入 |

## ID 与资源分配规则

技能参考文档给出了常用 ID 编排示例，物品参考文档给出了 `5xxxxx` 分类建议，但本项目暂不直接采用这些数值范围。

正式分配流程：

1. 接入真实 Y3 地图工程。
2. 查询五类现有自定义物编 ID。
3. 确认项目是否已有 ID 分段约定。
4. 为本项目建立不冲突的 ID 台账。
5. 查询官方和项目模型、头像、图标、特效资源。
6. 只有进入 `id-assigned` 状态的记录才能生成执行命令。

## 执行流程

```text
策划记录 draft
→ 字段评审 reviewed
→ MCP 查询现有 ID 和资源
→ 分配 ID，状态改为 id-assigned
→ 生成 y3_obj_edit.py 命令
→ 按依赖顺序创建：效果/投射物 → 技能 → 单位/物品
→ 一次性 hotfix_object_editor
→ 等待 3 秒
→ save_editor
→ MCP 回读关键字段
→ 实机验收，状态改为 verified
```

修改已有对象时，必须先用 MCP 查询目标 ID 的当前字段，再生成最小 `-edit` 命令，避免覆盖用户已有配置。

## 当前环境检查

截至 `2026-07-11`：

- 当前工作区只有策划文档，没有 Y3 `maps/EntryMap` 或其他地图工程目录。
- 当前会话没有暴露 `y3editor` MCP 查询、热更和保存工具。
- 系统 Python 为 `3.14.0`，当前环境缺少脚本依赖 `mmh3`。
- 因此现在可以继续编写和评审物编规格，但不能安全分配真实 ID，也不能执行创建、热更或保存。

## 模板确认结果

本项目采用“统一记录头 + 五类 A 层基础物编 + B 层系统规则”的两层模板。

首轮物编规格从破妄法门技能包开始，当前入口为 [01-破妄法门技能物编规格](01-破妄法门技能物编规格.md)。破妄技能与英雄基础战斗尺度完成白盒后，使用同一口径建立其余三个职业，再进入花果山普通怪、精英、BOSS、装备、法宝和宠物。
