# 花果山遭遇运行时与地图逻辑资源绑定

## 状态与边界

当前状态：

```text
reviewed / offline-runtime / public-map-contract-complete / instance-map-contract-pending / editor-unbound
```

本工件固定公共白盒、15 个遭遇、运行时 Lua 和未来地图脚本之间的键绑定；龙宫与牛魔只具备待绑定的实例角色契约，不能被入口与回传点误判为完整实例地图。

- 地形唯一来源：[花果山 96x72 白盒拆分](../归档/地图设计/14-花果山96x72白盒拆分.md) 与其 `layout.json`。
- 单位与遭遇来源：[单位物编规格](14-花果山怪物与BOSS单位物编规格.md)、[战斗契约](15-花果山遭遇与BOSS战斗契约.md)。
- 机器可读绑定来源：[地图逻辑资源绑定清单](../../implementation/huaguoshan/map-logic-binding.json)。
- 当前工作区没有 `maps/EntryMap/script`、`global_script`、真实对象 ID 或 Y3 编辑器连接；`encounter_runtime_bound` 仍为 `false`。

## 已落地链路

```text
layout.json
  -> map-logic-binding.json
  -> huaguoshan_map_binding.lua
  -> huaguoshan_runtime.lua
  -> huaguoshan_y3_controller.lua
  -> huaguoshan_y3_adapter.lua
  -> future verified map root
```

1. 绑定清单为每个公共 `HG_E_*` 记录白盒资源键、来源类别和预期类型：`logic_resource`、`boss_zone` 或 `spawn`，以及 `point`、`rectArea`、`circleArea`、`path`、`boss_zone`、`spawn_anchor`；三个实例遭遇另列为 `pending` 角色契约。
2. 预检要求公共遭遇的 `map_logic_resource_keys` 出现在清单中，并反查 `layout.json` 的真实类型；龙宫和牛魔必须等内部地图资源回读后才能解除独立门禁。
3. `huaguoshan_map_binding.lua` 只接受显式解析器：`resolve_logic_resource(key, source, expected_type) -> { ref, source, type, engine_object_id }`。它以临时表完成 source/type/稳定对象 ID/唯一性校验后原子提交，失败重绑不会留下半更新引用。
4. `huaguoshan_y3_controller.lua` 按 `actor_id + lifecycle_id` 管理角色注册、旧回调失效、读条取消和事件归属；生命周期先封存并注销 Hook/计时器，才允许发出清理命令。每批运行时命令会分配稳定 `delivery_id`；适配器失败时控制器保留该批次，重试时由适配器跳过已执行命令，避免部分成功重放。
5. `huaguoshan_y3_adapter.lua` 分离 `offline_test` 与 `live`：只有严格生产门禁全开时，live 才能启动或执行命令；实例遭遇还逐槽位验证待绑定地图角色的稳定对象 ID 和唯一性，任何 `pending` 实例契约均拒绝启动。
6. `huaguoshan_config.lua` 的完整运行时投影与 `map-logic-binding.json` 做深比较，预检还要求两处实例地图门禁一致；离线包没有任何直接 `y3.*`、`GameAPI`、`GlobalAPI` 或 `CAPI` 调用。实际 Y3 API 只能在未来地图脚本根验证后注入适配器。

## 持明净化接口

`HG_BOSS_WATER_CHAIN` 仍由遭遇层拥有。持明或其他职业不得直接删除状态；地图桥接必须在验证其实际命中、目标、生命周期和机制键后，提交：

```text
kind=mechanic_resolved
mechanic_key=HG_BOSS_WATER_CHAIN
mechanic_resolution=purge_mechanic
authority_source=map_root_authority_provider
```

潮眼读条和离开潮线分别使用 `drain_tide_eye`、`leave_tide_lane`。同一角色同一 BOSS 阶段最多登记一次有效水链处理。

## 离线验收

运行以下入口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\implementation\huaguoshan\tests\run-all.ps1
```

> 补充更正：第 4 条的“重试”仅指**已由权威投递账本确认未执行**后的安全重试。`delivery_id` 结果未知时，适配器必须先调用地图根提供的无副作用 `reconcile_command`；未完成对账不得重放命令。第 5 条中的稳定对象 ID 唯一性按所有 `verified` 实例合同全局校验。龙宫旧潮和逆潮必须共同引用唯一的 `HG_I_DRAGON_FOUR_SEAS` 四槽合同，不能各自声明四份房间。物编命令生成还会同时核验 manifest、`map-logic-binding.json` 与 `huaguoshan_config.lua` 的实例合同，任一方仍为 `pending`、不可读或不一致均不输出命令。

它覆盖：

- 清单与白盒资源引用、类型和刷怪映射反查；
- Lua 配置到 JSON 绑定清单的完整运行时投影深比较；
- 资源类型错配被预检拒绝；
- 三个公共 BOSS 的贡献、破韧、交互、水链、潜入和安全锚点；
- 龙宫四槽隔离、逆潮门禁、超时清理；
- 牛魔双阶段、成员快照、失败顺序与牛气冲天；
- 角色移除、重注册、旧 Hook 静默、适配器命令分发与部分成功后的幂等重试；
- 实例地图门禁与运行时投影的一致性；
- Y3 API 基线负向用例和全离线 Lua 包禁止直调扫描。

## 真实地图接入门禁

1. 在真实 Y3 地图创建并回读清单中的点、区域、路径、战圈和刷怪锚；不得只依赖白盒 JSON。
2. 将回读结果包装成 `resolve_logic_resource`，并验证 `source/type` 与绑定清单一致。
3. 创建并回读单位、能力、效果、投射物和资源 ID；此时才可把实际生成、伤害、移动、效果、传送和触发器实现注入 `huaguoshan_y3_adapter.lua`。
4. 在真实地图脚本根逐项核验 Y3 Lua API、事件名和同步边界；公共资源、实例内部资源、可信进度验证器与生产 ID 全部回读后，才可解除 `map_logic_resources_verified`、`instance_map_contract_verified`、`encounter_runtime_bound` 等生产门禁。
5. 进行单人、4 人、晚入场、断线、Boss 脱战、龙宫四房和牛气冲天实机回归。通过前不得标记为 `implemented` 或 `verified`。
