# 天庭地图口径对齐与白盒前置裁决

> 状态：`offline-preconstruction-decision / production-gate-closed`。本文件只冻结坐标语义、候选拆图和白盒验收门槛；不创建、调整或写入任何 Y3 地图、地形、入口、传送、出生点、碰撞、逻辑资源、地图键或资源 ID。

## 1. 裁决背景与来源

本包此前的公共路线预览使用 `640×416`，而当前有效首发总图基线为 `384×320 terrain cell`，天界预留带为 `224×80`，历史首发规划给天庭公共场景的单场景候选为 `96×64`。

这些值此前都不是运行时地图事实，因此不是已发生的地图冲突；但若把 `640×416` 误当作 terrain cell，便无法在既有首发基线内直接施工。为避免 UI、物编、美术、镜头和地形各自采用不同尺度，本裁决冻结以下语义。

- [全局项目入口](../../../README.md)中的首发总图口径；
- [首发地图推理基线与验证 TODO](../../../归档/地图设计/13-首发地图推理基线与验证TODO.md)；
- [既有天庭候选布局](layout.json)、[战斗可读性规格](../combat/天庭战斗机制与可读性规格.md)与[天庭进度/会话权威合同](../authority/tianting-progression-and-instance-authority-contract.json)。

## 2. 已冻结的口径

| 层级 | 标识 | 尺寸/语义 | 允许的用途 | 明确禁止 |
| --- | --- | --- | --- | --- |
| 总图推理基线 | `GLOBAL_FIRST_RELEASE_CANVAS` | `384×320 terrain cell` | 首发容量与世界层预算。 | 由天庭包直接扩容或改写。 |
| 天界预留带 | `HEAVENLY_BAND_ENVELOPE` | `224×80 terrain cell` | 天界首发公共区的最大候选预算。 | 当作已创建地图或实际世界坐标。 |
| 天庭公共场景包络 | `TT_WB_PUBLIC_SCENE_*` | 两张 `96×64` 候选白盒场景，之间保留 `8 cell` 非可达分隔；总占用 `200×64`，留出外圈缓冲。 | 白盒路线、镜头、站位与加载边界验证。 | 直接创建 Y3 地图或传送。 |
| 既有公共路线图解 | `TT_LAYOUT_CANVAS_640X416` | **diagram-unit**，不是 terrain cell、地图尺寸或世界坐标。 | 叙事关系、区域相邻、路线阅读与空间职责。 | 直接按比例/按坐标落地。 |
| 独立会话图候选尺寸 | `TT_SESSION_CANDIDATE_*` | 机制图解尺寸族，仍为 diagram-unit。 | 为白盒选择场地类型提供输入。 | 当作真实副本地图大小或地图键。 |

### 2.1 选定的映射策略

选定“**图解与白盒分离**”，而非全局扩容或将所有内容硬压进一张地图：

1. `640×416` 保留为章节关系图解；它只表达“先回查南天门、再转入内廷、最后抵达观台/凌霄门面”的因果和相邻关系。
2. 物理白盒先采用两张 `96×64` 候选公共场景：
   - `TT_WB_PUBLIC_SCENE_GATE`：临时天庭、南天门回查与裂云门禁的公共锚点；
   - `TT_WB_PUBLIC_SCENE_INNER`：天宫道、断虹阵、天王殿外缘、周天观台与凌霄前庭门面。
3. 凌霄外庭最终战、七星、普通星宿和噩梦星宿继续只属于独立会话白盒；不会塞入公共图。周天观台的“会话门廊”改为公共 UI/空间提示位，不保留长条实体走廊预算；通天塔只保留非交互视觉门面候选。
4. 不允许把图解坐标作线性缩放后直接施工。每个候选场景都必须按战斗可读性、2.5D 镜头、四人站位、退场与寻路验收后，才可获得真实尺寸、地图键或邻接关系。

### 2.2 白盒场地包络

| 白盒对象 | 默认包络 | 允许的升级条件 | 仍不代表 |
| --- | --- | --- | --- |
| 凌霄外庭私有 1–4 人终局 | `48×36` | 四人同时可读的净化节点、侧向撤离与首领预警无法共存时，才评估 `56×40`。 | 实际会话地图、出生点或逻辑区域。 |
| 七星单人试炼 | `32×28` | 仅当该星的方向/环轨/多锚机制无法同时保持可读时，评估 `40×32`。 | 七张真实地图的统一尺寸。 |
| 星宿普通 1–4 人 | `48×36` | 仅当双宿联动或阶段交接无法在视野中复盘时，评估 `56×40`。 | 团本入口、掉落区或同步范围。 |
| 四圣噩梦 1–4 人 | `48×36` 起测 | 七宿、四圣核心与反制入口无法在同一镜头语义中区分时，评估 `56×40` 或拆分阶段场地。 | 已批准的难度地图或性能结果。 |

所有数值都是白盒测试包络，不是伤害范围、技能半径、地图资源数据或生产尺寸。

## 3. 白盒验收计划

### A. 口径与拆图

| ID | 验收 | 通过条件 |
| --- | --- | --- |
| TT-MAP-ACC-001 | 图解单位隔离 | `640×416` 与全部 `TT_SESSION_CANDIDATE_*` 明确标为 `diagram-unit`，不可作为 terrain cell。 |
| TT-MAP-ACC-002 | 首发预算守恒 | 两张公共白盒候选与分隔/缓冲总占用不超出 `224×80` 天界预留带。 |
| TT-MAP-ACC-003 | 不触发全局扩容 | 本轮不改动 `384×320` 推理基线；任何扩容须形成独立总图裁决。 |
| TT-MAP-ACC-004 | 路线映射完整 | 图解中的临时天庭、南天门、断虹阵、天王殿、周天观台和凌霄门面均映射至两张白盒场景或独立会话。 |
| TT-MAP-ACC-005 | 会话不并入公共图 | 凌霄最终战、七星、星宿普通/噩梦没有被写成公共图内的实际副本、传送或 Boss。 |

### B. 路线、镜头与空间可读性

| ID | 验收 | 通过条件 |
| --- | --- | --- |
| TT-MAP-ACC-006 | 公共路线因果 | 玩家能从门禁回查读出转入内廷的原因；不依赖长距离折返、UI 箭头或不可见任务线。 |
| TT-MAP-ACC-007 | 场景切换清晰 | 两张公共候选场景的边界必须是叙事/视觉切换点，而不是伪装为可无缝穿越的实际道路。 |
| TT-MAP-ACC-008 | 2.5D 预警视线 | 双通道预警、可净化节点、撤离口和反制入口不被地形、装饰或镜头边缘同时遮挡。 |
| TT-MAP-ACC-009 | 四人站位 | 四人同时分流、汇合、撤离时不存在由静态地形造成的无解堵塞。 |
| TT-MAP-ACC-010 | 路径可复盘 | 每次机制失败可从路径、场地轮廓、文字/声音或状态反馈中解释，颜色不是唯一解释。 |
| TT-MAP-ACC-011 | 门面降级 | 周天观台门廊和通天塔门面只承载展示；不暗示现有传送、资格验证或会话创建。 |

### C. 会话与权威边界

| ID | 验收 | 通过条件 |
| --- | --- | --- |
| TT-MAP-ACC-012 | 凌霄前庭隔离 | 公共图的凌霄前庭不能替代私有 `TT_SPEC_SESSION_LINGXIAO_MAINLINE`。 |
| TT-MAP-ACC-013 | 失败/清理不由地形裁决 | 白盒不新增检查点、复活、重连、掉线返回或清理确认例外。 |
| TT-MAP-ACC-014 | 断线成员边界 | 团本 `left` 规则、禁止重连与禁止领奖仍只由既有权威合同裁决。 |
| TT-MAP-ACC-015 | 地图不触及经济 | 白盒不写入来源事件、资格、材料、钥匙、XP、货币、掉落、概率、保底或收据。 |

### D. 施工前验证顺序

1. 先在 `scale-alignment/layout.json` 中验证尺寸预算与分区关系；不写入编辑器。
2. 获得真实 Y3 地图上下文和用户确认后，才读取当前地图、资源、尺寸与既有逻辑资源。
3. 先验收道路、区域、镜头与可读性；再评估出生/入口/Boss 区等逻辑资源；最后才允许纹理、装饰、实体和性能测试。
4. 任何白盒失败只能调整候选分区或拆图策略，不能以放宽权威、经济、清理或无障碍规则通过验收。

## 4. 下游合同

- UI 包可使用两张公共场景的**功能边界**，但不得绑定坐标、地图键或本地资格判定。
- 物编/美术/特效蓝图可使用白盒场地的“无遮挡预警区、可见反制区、边缘框景区”职责，不能预设资源 ID、单位 ID、模型或技能数值。
- 天庭权威运行时基座不读取地图坐标；它只接受由未来可信适配层提供的会话事实。
- 星宿经济、通天塔 run、大 Boss、掉落与赛季仍需要独立的数值、收据和全局塔合同，不能由本裁决推导。

## 5. 禁止事项

- 把 `TT_MAP_`、`TT_R_`、`TT_ROUTE_`、`TT_ZONE_` 或 `TT_SESSION_` 标签当作运行时键；
- 从本文件、预览 PNG 或 diagram 坐标直接创建 Y3 地形、对象、入口、传送或逻辑资源；
- 因地图空间需要而放宽 `active → cleanup_pending → closed`、逐人准入、`left` 禁止重连或经济隔离；
- 在白盒通过前把公共场景、会话包络或两图拆分描述为已建地图。

机器可读来源见 [地图口径与白盒合同](tianting-map-scale-alignment-contract.json)，可复现白盒布局见 [scale-alignment/layout.json](scale-alignment/layout.json)。
