# 天庭物编字段预占规格

`production_gate = closed`。本文件细化的是未来物编的**逻辑卡与字段预占**，不是对象创建清单。每张卡都只描述设计身份、预警、反制、可读性和禁止复用边界；Y3 表类型、对象键、`copyFrom`、资源、字段映射和绝对属性均为 `null/deferred`。

## 使用顺序

```text
声音／投射物语义／表现型 Buff
              ↓
      技能壳（预警、关系、反制结果）
              ↓
      单位或非人形机制体
              ↓
主线、七星、星宿、四圣的遭遇组装
```

这不是要求现在创建上述对象；它规定未来不能倒过来把“先做一个伤害技能”当成机制设计。权威进度、成员、时辰、资格、清理、奖励与经济只能作为未来已确认事实的只读表现输入，不能写入单位、技能或 Buff。

## 通用卡面与延后字段

每张逻辑卡固定包含：设计身份、来源选择器、所属遭遇、职责、三个语义技能槽、P0 空间信号、独立第二通道、反制结果、单人或 1–4 人可读性和复盘痕迹。

所有卡共同预占但尚未填写的字段如下：

| 类别 | 必须保持 `null/deferred` 的内容 |
|---|---|
| 对象 | Y3 表类型、稳定对象键、`copyFrom`、模板键、对象／技能／Buff／投射物 ID、字段映射 |
| 资源 | 模型、动画、特效、声音、材质、图标、资源 ID |
| 数值 | HP、攻击、双防、攻速、攻距、移速、伤害、范围、冷却、前摇、持续时间、频率 |
| 运行时 | AI、波次、出生点、碰撞、地图点、Lua、会话、进度、时辰、资格、清理 |
| 经济 | 掉落、材料、称号效果、奖励、收据、economy-v2 输入 |

机器合同还冻结五个逻辑卡族的来源路径、来源身份、来源内容 SHA-256、P0 七门、关闭态 `evidence-adoption` 直接来源与卡面语义快照。任何来源、卡面、字段结构或包内文件的变更，都必须经由该包测试显式复审；不能以同名身份、额外 JSON、对象字段或文本化数值绕过 `null/deferred` 边界。

未来只有 P0 七门全开、真实对象与资源盘点完成、稳定键与模板审定、并获真实工程写入授权后，才可把逻辑卡转换为 `y3-object-config` 的 `upsert` 输入；转换时保留未指定字段，`overwrite` 固定为 `false`，`copyFrom` 只能引用已盘点确认的模板。

主线首领卡的三个槽永远分别表达“施压动作、关系／节点动作、反制结果动作”；不得压缩为只有伤害的技能。

## 七星单人 Boss

七星每位固定为“一个首领逻辑卡 + 三个技能壳 + 一个本星规则回响”。反制必须可由一名玩家按顺序完成，不得要求第二名玩家同步打断、承伤、占位或救援。

| Boss | 三个技能槽 | P0 信号／结果 |
|---|---|---|
| 天枢·镇枢天将 | 中轴位移、方向翻转、稳定锚回正 | 中轴、外圈、箭向、回归路径。 |
| 天璇·回轮天女 | 内外双轨、旧轨回放、回环通路 | 双轨、旧轨来源、下一落点。 |
| 天玑·匿曜监星使 | 真伪星标、反照误导、暴露窗口 | 真伪至少在轮廓／动态／反馈之一不同。 |
| 天权·衡律天官 | 双侧承压、裁决趋势、归位打断 | 双侧趋势、裁决条、打断征兆。 |
| 玉衡·玉衡灵卫 | 安全位轮替、灵息回流、护持转化 | 两类安全位、回流方向、过用趋势。 |
| 开阳·开阙神将 | 门态切换、冲锋线、破障窗口 | 门开闭、起点、冲锋线、可穿越窗口。 |
| 瑶光·曳光天将 | 轨迹留痕、残影回溯、收束截断 | 当前轨、残影来源、收束点。 |

## 二十八星官：四方基础语法与签名覆写

二十八星官采用“四张方位基础语法卡 + 二十八张独立星官覆写卡”的组织方式。共享的是制作管线，不共享可读语义；声波环、火环、回声环，或真伪、可净化、危险、护持状态，不能只换颜色而复用同一资产。

| 方位 | 共享语法 | 独立星官覆写 |
|---|---|---|
| 东方青龙 | 星链、延迟、真阵眼、扇区、风潮推拉 | 角木蛟：星链重定向；亢金龙：标记列与龙影；氐土貉：阵眼潜遁；房日兔：日轮扇区；心月狐：动作反照；尾火虎：尾扫火痕；箕水豹：水压与链路重排。 |
| 南方朱雀 | 火种、回响、封路、缺口、水脉 | 井木犴：路线／锚点牵引；鬼金羊：铃链截断；柳土獐：交叉封路；星日马：日轨冲锋；张月鹿：空间代理／串行交换；翼火蛇：火环缺口；轸水蚓：下潜出口与水脉。 |

任何带双目标或协作描述的星官，都必须预留单人空间代理或串行版本；1–4 人可以并行，不能把多人协作变成硬门槛。`胃土雉` 等异文只允许保留别名，不能派生第二个星官单位。

## 四圣噩梦

噩梦不创建“强化七宿”的第二套单位档案，而是复用本方位七个星官覆写卡，增加共鸣／净宿表现层和一位四圣首领卡。

| 四圣 | 技能壳 | P0 | 净宿后的 L3 结果 |
|---|---|---|---|
| 青龙 | 龙轨压场、风潮推拉、星链改道 | 龙轨、推拉向量、导流路 | 错误龙轨离开主战区，星链化为导流。 |
| 朱雀 | 火种过热、余烬复燃、火环缺口 | 危险火焰、可净化余烬、护持区异形 | 余烬化为短暂护持或跨火场机会。 |
| 白虎 | 猎印、冲刺、接应区、反猎窗口 | 点名归属、冲刺线、接应区、反猎方向 | 净宿轨迹转成可见破绽方向。 |
| 玄武 | 甲壁推进、冥水切割、护壳轮换、破壁 | 墙体、冥水、破壁点、退路 | 净宿打开可验证的破壁口，不能封死退路。 |

共鸣卡只表现 `贡辉 → 可反制链 → 净宿 → 庇护削弱 → 核心缺口`；它不能重算时辰、资格、成员状态、完成或结算。

## 可读性与权威红线

1. 每个施压槽必须同时有空间／几何 P0 与声音、文字、状态符号或场地变化之一的独立第二通道。
2. Buff 只能表达已确认的表现状态，不写进度、资格、轮换、成员、清理、奖励或收据。
3. 关系实体、阵眼、节点和回响不能成为击杀数、掉落容器或独立胜利条件。
4. 物编卡只能消费未来权威已确认事实，不能反向裁决会话、主线完成、时辰快照、资格、断线或清理。
5. 在稳定键、模板、实机字段映射和绝对标定到位前，不能生成 `assets`、插件或真实物编。

## 离线验收

- `TT-OBJRES-ACC-001`：不出现 `assets`／`mode` 或生成插件。
- `TT-OBJRES-ACC-002`：P0 七道门完整且当前为零通过；对象资源盘点无写入授权。
- `TT-OBJRES-ACC-003`：对象、资源、绝对字段与运行时字段预占均为空。
- `TT-OBJRES-ACC-004`：十一类敌人生态均有唯一逻辑卡，机制体不被承诺为对象。
- `TT-OBJRES-ACC-005`：五组主线均有三语义槽、P0、第二通道与反制。
- `TT-OBJRES-ACC-006`：七星仍保持单人顺序反制。
- `TT-OBJRES-ACC-007`：二十八星官全名唯一，异文只保留别名。
- `TT-OBJRES-ACC-008`：四圣只叠加共鸣表现层，权威与经济仍为只读／空值边界。
