# 天庭战斗数值与单位基线裁决

## 状态与结论

`accepted-relative-balance-baseline / offline-only / production-gate-closed`。

本裁决包冻结的是可复算的**相对战斗数值**，不是一张伪装成可直接物编的 HP、伤害和秒数表。现有四职业已冻结 Lv41–60 裸装公式，但技能循环、装备/法宝/宠物/收集、伤害与双防公式、命中控制、动作帧和地图碰撞尚无同一份已采纳实测基线；直接填 Y3 原始单位值会把未知条件伪造成确定事实。

因此，本包做两件事：

- 用四职业既有裸装公式给出真实可核查的 Lv41、Lv45、Lv50、Lv55、Lv60 玩家参照包络；
- 以 `H0/A0/M0/I0/R0/B0/O0/S0` 这八个无量纲标尺，冻结小怪、精英、五组主线 Boss、七星、二十八星官和四圣噩梦的相对耐久、压力、机动、节拍、读条与 1–4 人缩放。

它不分配对象键、单位 ID、技能/Buff、资源、地图、Lua、进度、会话、资格或任何经济字段。原始对象属性只能在文末的标定门禁通过后另行投影。

机器合同：[tianting-combat-numeric-unit-baseline-contract.json](tianting-combat-numeric-unit-baseline-contract.json)。

## 绝对值标定门禁

只有 [P0 实证采集与采纳包](../../../../implementation/combat-calibration/evidence-adoption/README.md) 所绑定的**完整七门**外部证据均被独立采纳后，才允许新开一次“原始对象字段投影”裁决：

1. `P0-GATE-01`：C01–C04 在 Lv41/Lv55/Lv60 的 12 份完整固定构筑及每份三次确定性回放；
2. `P0-GATE-02`：泛用物理、魔法、双防与穿透顺序；
3. `P0-GATE-03`：命中、暴击与控制抗性公式；
4. `P0-GATE-04`：真实 Y3 动作帧、攻速、移速字段回读；
5. `P0-GATE-05`：真实白盒碰撞、路径、射程和镜头记录；
6. `P0-GATE-06`：不改变既有权威语义的 1–4 人战斗回放；
7. `P0-GATE-07`：稳定对象键、模板与真实字段回读。

这七门的 ID、顺序和父合同 SHA-256 以 `implementation/combat-calibration/contract/cross-profession-combat-calibration-contract.json` 为唯一真源。天庭相对基线不得把六条摘要、旧木桩夹具、结构预检、施工发现、客户端声明或离线 schema 当作任一门的采纳；七门齐备后仍须经过单独的绝对字段投影复审。

在此之前，以下内容必须保持 `null/deferred`：`hp_max`、攻击、双防、攻速、攻击间隔、Y3 移速字段、施法秒数、冷却、阶段血量、仇恨、AI、命中、控制、刷怪数量和波次。
