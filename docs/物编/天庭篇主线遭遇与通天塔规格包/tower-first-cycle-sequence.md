# 通天塔首轮五节拍时序与幂等边界

## 适用范围

本文件将“首轮循环”限定为一个包含五个抽象楼层节拍的离线子循环。它只描述状态的可达性和收束顺序；不是通天塔总层数、实际关卡排表、遭遇配置、地图路径或结算配置。

唯一机器可校验事实源是 [tower-first-cycle-state-contract.json](tower-first-cycle-state-contract.json)。本页是同一合同的可读时序视图。完整 run 的四十层编排、Boss 槽与第八段终局约束由独立的 [tower-economy 裁决](tower-economy/星宿经济来源、全局通天塔运行与赛季裁决.md) 定义；它不改写本页五拍状态语义。

## 主时序

~~~text
ENTRY_CHECKING
  ├─ 逐人 Lv55 校验未通过 ───────────────> ENTRY_DENIED（本子循环终态）
  └─ 逐人 Lv55 校验通过 ────────────────> BEAT_01_ACTIVE
                                               │ 完成
                                               ▼
                                            BEAT_02_ACTIVE
                                               │ 完成
                                               ▼
                                            BEAT_03_ACTIVE
                                               │ 完成
                                               ▼
                                            BEAT_04_ACTIVE
                                               │ 完成
                                               ▼
                                            BEAT_05_ACTIVE
                                               │ 完成
                                               ▼
                                           REST_05_OPEN
                                      ┌────────┼────────┐
                                      │        │        │
                                关闭本轮   自愿退出  下一循环交接
                                      │        │        │
                                      ▼        ▼        ▼
                         SETTLEMENT_PENDING  EXIT_PENDING  NEXT_CYCLE_HANDOFF
                                      │        │          （本合同不创建第六节拍）
                                      ▼        ▼
                                   SETTLED   EXITED
~~~

任一 `BEAT_*_ACTIVE` 在权威失败判定后进入 `FAILURE_PENDING -> FAILED`。任一活动节拍以及 `REST_05_OPEN` 都可请求自愿退出，但不能绕过 `EXIT_PENDING -> EXITED` 的权威收束。

## 节拍合同

| 节拍 | 活动状态 | 唯一完成去向 | 失败去向 | 退出去向 | 不包含 |
|---|---|---|---|---|---|
| 抽象节拍 1 | `BEAT_01_ACTIVE` | `BEAT_02_ACTIVE` | `FAILURE_PENDING` | `EXIT_PENDING` | 地图、怪物、Boss、词缀、数值。 |
| 抽象节拍 2 | `BEAT_02_ACTIVE` | `BEAT_03_ACTIVE` | `FAILURE_PENDING` | `EXIT_PENDING` | 地图、怪物、Boss、词缀、数值。 |
| 抽象节拍 3 | `BEAT_03_ACTIVE` | `BEAT_04_ACTIVE` | `FAILURE_PENDING` | `EXIT_PENDING` | 地图、怪物、Boss、词缀、数值。 |
| 抽象节拍 4 | `BEAT_04_ACTIVE` | `BEAT_05_ACTIVE` | `FAILURE_PENDING` | `EXIT_PENDING` | 地图、怪物、Boss、词缀、数值。 |
| 抽象节拍 5 | `BEAT_05_ACTIVE` | `REST_05_OPEN` | `FAILURE_PENDING` | `EXIT_PENDING` | 第六节拍、总层数、奖励。 |

第五节拍完成是唯一可以打开休整窗口的路径。休整期可请求既有保存构筑的切换，但该请求保持在 `REST_05_OPEN`，不生成额外节拍、奖励、消费或第二个休整窗口。

## 准入与跨篇边界

1. `ENTRY_CHECKING` 只校验每位参与者是否达到 Lv55；不能改用队伍平均值或由其他成员代替。
2. `DF_PROGRESS_YANLUO_HALL_CLEARED` 不是准入输入、资格替代、写入目标或结算依据。
3. 准入、节拍终局、休整关闭、结算、失败、退出和交接均由未来权威游戏逻辑裁决。UI 只可请求或展示，不能本地决定状态。

## 结算、失败、退出与下一循环边界

| 分支 | 来源 | 必经 pending 状态 | 终态 | 明确不做 |
|---|---|---|---|---|
| 结算 | 第五节拍后的 `REST_05_OPEN` | `SETTLEMENT_PENDING` | `SETTLED` | 只可外部引用 economy-v2 的首通/重复奖励与周桶收据语义；未完成精确编译、持久化和证明解析时不发放经济效果。 |
| 失败 | 任一活动节拍 | `FAILURE_PENDING` | `FAILED` | 不定义恢复、记录或奖励。 |
| 自愿退出 | 任一活动节拍或休整期 | `EXIT_PENDING` | `EXITED` | 不把退出等同失败或奖励。 |
| 继续 | `REST_05_OPEN` | 无 | `NEXT_CYCLE_HANDOFF` | 本合同不创建第六节拍；外层四十层编排只允许第 1–7 段交接，第 8 段禁止交接。 |

`NEXT_CYCLE_HANDOFF` 只关闭这个五节拍子循环。独立全局塔裁决已选择八个五拍子循环：第 1–7 段可由匹配权威交接续段，第 8 段仅能沿既有终局路径关闭；真实运行、保存与恢复仍由未来服务定义。

## 幂等语义

未来实现需为每次准入、节拍终局、休整切换和子循环关闭携带同一份“幂等语义包络”：未来 run 范围、操作标识、请求种类、预期源状态、参与者范围、资格快照、事件标识和 schema 版本。这里列出字段语义，不创建任何实际键或值。

| 操作 | 幂等范围 | 重复请求的正确结果 |
|---|---|---|
| 准入 | 同一未来准入语义包络 | 返回首次权威接受或拒绝，不能重复开启节拍。 |
| 节拍完成/失败/退出 | 同一未来 run 范围内的同一抽象节拍 | 首个权威终局胜出，其余请求返回既有终局。 |
| 休整构筑切换 | 第五节拍休整窗口内的同一切换请求 | 不产生第二次状态变化、价值、消费或窗口。 |
| 结算/失败/退出/交接关闭 | 同一未来首轮子循环关闭语义包络 | 第一个权威终局胜出，重复调用只返回该终局。 |

因此，同一节拍不能同时完成、失败和退出；休整窗口不能同时结算、退出和交接。终态也不能直接回到活动节拍。

## 仍需独立裁决

- 全局 run 的记录范围、持久化、断线重连、失败恢复和单人/团队关系。
- 抽象节拍的任何实际内容：地形、遭遇、怪物、Boss、词缀、时长和难度。
- 真实后续循环适配器、run 服务、地图/实例、保存与恢复；离线四十层/八段编排见 `tower-economy/`，不属于本首轮状态合同。
- 奖励槽位、天庭具体 source_profile、运行时资源表编译、收据存储和证明解析；economy-v2 已冻结塔首轮奖励设计值，但不等于可运行结算。
