# UI 交接简报

本包只定义“应当展示什么”和“UI 不能决定什么”。[天庭 UI 与无障碍信息架构规格](../ui/天庭UI与无障碍信息架构规格.md) 已把双通道预警、轮换快照、队伍状态、失败复盘和称号展示转为验收项；[战斗可读性规格](../combat/天庭战斗机制与可读性规格.md) 进一步冻结信息优先级和双通道表达；[二十八星官与四圣机制编排规格](../mansion-orchestration/天庭二十八星官与四圣机制编排规格.md)补齐普通四段、逐星官读线/提交/反制/恢复、成员流失降级与四圣七链的展示顺序；[主线 Boss 叙事与表现深化规格](../mainline-presentation/天庭主线Boss叙事与表现深化规格.md)补齐五组主线的候选引导、复盘、无障碍替代和 L0–L4 责任层；[地图、UI 与资产施工发现清单](../../../../implementation/tianting-surface-construction-manifest/README.md) 只记录未来 UI 根、节点和权威数据通道的现场读取项；不生成 UI 资产、交互代码或本地状态机。

## 玩家可见信息

| 场景 | UI 应展示 | UI 绝不能决定 |
|---|---|---|
| 主线 | 当前调查节点、净化目标、主线与长期收集的关系。 | 章节进度写入或天庭入场资格。 |
| 七星单人本 | 七星图、当前试炼机制提示、对应残片/星君收藏进度、七曜集合称号的解锁条件。 | 残片发放、十枚兑换、称号属性或聚合状态。 |
| 星宿轮换 | 当前权威 rotation_snapshot 的方位、剩余展示时间、普通/噩梦可否请求。 | 用本地时间改方位、跨时辰刷新副本、钥匙消耗。 |
| 普通星宿 | 当前严格四段、当前主星官读线、辅星官关系、可见恢复、下一段读回与权威已确认的终局候选。 | 波次推进、成员锁、胜负和奖励。 |
| 噩梦四圣 | 四圣兽核心、当前主链、至多一条预告附属链、七条宿曜贡辉、七条圣兽庇护、已净宿链路与权威已确认的终局候选。 | 直接净化、链序重抽、Buff 移除、Boss 结算。 |
| 称号 | 单称号的非数值标签与展示方向；七曜/四象集合称号的“替代而非翻倍”说明。 | 真实 title 持久化、实际属性、全局生效范围。 |
| 通天塔 | 仅以“天庭侧离线候选”展示四十层、八段五拍、五层 Boss 槽与四个十层大 Boss 的状态/复盘口径；须等待上位全局塔合同 `../../成长系统规格包/design-spec.json` 显式采纳。 | 不得把候选编排伪装成已生效的全局塔规则，或决定实际楼层/实例、内容抽取、奖励、赛季值、记录与 UI 资产。 |

## 可读性规则

- 青龙星链、朱雀火环、白虎猎印、玄武甲壁要先靠形状和路径可读，再给文字。
- 所有关键预警至少同时使用轮廓/轨迹/场地变化之一与声音、状态提示或文本之一；颜色永远不能是唯一载体。
- 轮换界面必须标识“本次实例已经锁定”，避免玩家误以为跨时辰会中途换宿。
- 噩梦需要同时可读“谁在强化四圣”和“谁被四圣庇护”，不能只显示一个总战力数字。
- 称号页要明确集合称号替代单称号的效果集合，避免玩家误解为七倍或四倍叠加。

## 权威边界

UI 仅展示权威结果并发起请求。天庭进度、rotation_snapshot、团队资格、净宿、失败、结算、钥匙、材料、称号和奖励都不能由本地 UI 改写。候选会话门廊和布局预览不代表实际入口或可由 UI 绕过的传送；在真实 UI 根和权威数据通道被现场读取并获得施工确认前，发现清单中的节点也只能显示为未绑定。

四十层／八段／五层 Boss／四个大 Boss 只属于天庭离线候选，未获上位全局塔显式采纳前不得写入运行时、经济、奖励、资源或实际 UI 状态；相关 runtime key、resource ID 和经济值保持 `null/deferred`。
