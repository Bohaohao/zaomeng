# 天庭内容深化复审简报

## 本轮已完成的离线裁决

1. 七星取代旧“蟠桃园 / 御马监二选一”，成为固定七个单人试炼。
2. 天庭常规主线在凌霄外庭收束；二十八星宿是主线后最高端团队循环。
3. 十二时辰轮换固定为：子/辰/申青龙，丑/巳/酉朱雀，寅/午/戌白虎，卯/未/亥玄武。
4. 普通七宿通关通向方位夜巡钥候选；噩梦中七宿以宿曜贡辉强化四圣，四圣以圣兽庇护反哺七宿。
5. 七星同种残片十枚合成星君称号；七称号集合与四圣集合均采取“集合替代单称号效果集合”的防翻倍语义。
6. 七星/星宿是唯一全局通天塔的候选小 Boss 内容池；四十层、八段五拍、五层 Boss 槽、四个十层大 Boss 创意身份与第八段禁交接仅为天庭离线候选，须等待 `../../成长系统规格包/design-spec.json` 所属全局塔显式采纳，当前不进入运行时、经济或奖励。
7. 主线、七星、星宿与四圣的战斗均补齐预警、决策、反制、可复盘失败和 1–4 人适配；所有坐标和副本尺寸仍是 dry-run 候选。
8. 非通天塔敌人生态已覆盖 11 类小怪、精英、机制与噩梦支援职责；它们不能降格复用任何受保护首领，也不含单位、波次、掉落或经济。
9. 南天门、断虹阵、四门失衡、周天观台与凌霄外庭五组主线首领级遭遇已补齐 P0、第二通道、决策、可见反制、复盘和附属压力接口。
10. 战斗数值与单位基线已冻结：四职业 Lv41/45/50/55/60 裸装参照、无量纲标尺、主线/七星/星宿/四圣相对暴露与压力、共鸣系数、1–4 人缩放及绝对值标定门禁均有机器合同；它不分配原始对象字段。
11. 七星与星宿会话已有进程内离线参考模型，分别复核 owner/观台/七路线和注入上海时辰/逐人资格/三方位/`left`/清理/重放；不把模型记录当作真实权威服务。
12. 五组主线 Boss 已有叙事与表现深化：每组保留入场引导、三段锚点、双通道预警、失败复盘、非经济确认与 L0–L4 责任层；不写会话、进度、资产或结算。
13. 天庭物编已进入离线字段预占：55 张逻辑卡先固定来源身份、三语义技能槽、P0、第二通道、反制和复盘；不生成对象、`assets`、`copyFrom`、资源、绝对数值或插件。
14. P0 已补齐独立的实证采集与采纳控制面：父合同 SHA-256 与完整七门 ID 是唯一真源；真实只读采集、不可变工件、独立复核、外部采纳和绝对字段投影复审互相隔离，当前仍为 `0/7`。
15. 二十八星官与四圣已补齐离线遭遇编排：普通严格四段 `2+2+2+1`、28 张读线/提交/反制/恢复卡、权威成员元组降级、普通/噩梦只读终局候选、同方位 `2+2+2+1` 噩梦链序、净宿只增不减、核心回正和不可跳段/倒退语义边均有机器合同；它不成为会话权威或运行时状态机。

## 复审重点

| 主题 | 必查问题 |
|---|---|
| 叙事 | 主线是否解释了星宿失序，并把“净化而非滥杀”作为可玩行动？ |
| 七星 | 七个机制、称号标签、展示方向是否重复？十枚规则是否被误写为掉落数量？ |
| 星宿 | 是否准确保留二十八全名、四象各七、四段普通结构和最多四人可解？ |
| 星宿编排 | 每条读线是否只有一个主 P0、辅星官是否只承担关系/预告、读错是否能可见恢复？成员死亡或 `left` 后是否只由权威成员元组取消无主目标并仅在下一节拍降级？普通/噩梦终局是否都只是候选，且 `transition_index` 不可跳段或倒退？ |
| 时间 | 是否只由权威 rotation_snapshot 选择方位，且重连不重算？ |
| 噩梦 | 是否真实保留七宿→四圣与四圣→七宿的双向关系，并要求逐链净宿？ |
| 噩梦链序 | 是否同方位固定 `2+2+2+1`，净宿集合只增不减，且绝不重算方位、链序或资格？ |
| 可读性 | 是否每项关键机制都有非颜色唯一的预警、明确决策、可见反制结果与可复盘失败？ |
| 敌人生态 | 受控天兵、机关、云兽、泛称监星使和机制回响是否只放大既有反制，且没有降格复用主线首领、七星首领、二十八星官或四圣？ |
| 主线 Boss | 五组主线首领级遭遇是否都有 P0 来源/关系、第二通道、串行单人解和 1–4 人适配？附属压力是否遮挡 P0、制造清场门槛或越权决定会话/进度？ |
| 数值基线 | 四职业裸装参照是否逐项复算正确？所有单位是否只用声明的无量纲标尺？七星是否仍为单人、星宿是否保留 2+2+2+1、四圣共鸣是否只由权威状态决定？ |
| 绝对值门禁 | 是否有人把相对系数/白盒夹具、离线 schema、Node/Fengari 测试、结构预检或施工发现复制为 Y3 HP、攻击、双防、秒数、Buff、AI 或波次？稳定对象键、伤害公式、动作帧、长期养成与场地回放是否来自可验证外部工件，且采集、复核、采纳与投影复审均独立？ |
| 物编预占 | 是否把逻辑卡误作真实对象？是否仍严格保持 `assets`／`mode`、对象键、`copyFrom`、模板、资源、字段映射、数值和插件为空；每张卡是否有 P0、第二通道、反制与权威只读边界？ |
| 地形 | 是否把候选布局误作真实地图？场地是否为预警、反制、退路与最多四人分工留出读线？ |
| 经济 | 是否没有出现资源键、掉率、保底、数量、属性、钥匙消耗或发奖实现？ |
| 通天塔 | 是否明确四十层/八段/五层 Boss/四大 Boss 仍待上位全局塔显式采纳；是否只把继承第五拍标为候选内容槽、不改状态/转移；是否保持候选第 1–7 段可交接、第 8 段禁交接、不建第二塔且不泄漏掉落？ |

## 仍不可放行

- 天庭入章/完成、实例、时间、失败、清理、重连与资格的**运行时服务、存储、网络协议和 Y3 接入**；离线语义合同已冻结，见 `../authority/tianting-progression-and-instance-authority-contract.json`。
- 所有对象、技能、原始对象数值、秒数、AI、地图、UI 资产；当前只有相对数值设计基线可交接。
- 敌人生态与主线 Boss 的实际单位名册、对象/资源 ID、技能/Buff、AI、波次/刷新、数值、出生点、性能和同步施工。
- 四个全局塔大 Boss 的对象／美术／特效资产蓝图；当前物编蓝图只涵盖天庭主线、七星、二十八星官与四圣，须在上位全局塔显式采纳后另起独立蓝图。
- 任何 Y3Maker 地形、装饰、逻辑资源或会话入口写入；候选坐标、布局预览和门廊不构成施工授权。
- 所有材料、钥匙、称号、法宝的资源表、收据、掉率、保底、属性与兑换。
- 通天塔实际 run 服务、楼层地图/实例、内容抽取、词缀、记录、失败恢复、掉落、收据和赛季值。

在这些前置合同完成前，复审通过只表示策划设计可交接，不表示能够进入 Y3 施工。
