> **状态**：`offline-design-candidate / pending-global-tower-adoption / production-gate-closed`。本文提出天庭星宿经济来源、全局通天塔完整 run、Boss 节拍与赛季边界的**天庭侧候选**；总层数、篇章与槽位只有在上位全局塔合同显式采纳后才可成为全局事实。它不是 Lua、Y3 地图、对象、资源表、经济收据、赛季服务或可直接投产的运行配置。

## 2. 唯一全局通天塔与完整 run 结构

### 2.1 天庭侧候选完整 run：四十层、八个五拍子循环

本包提出 **四十层完整 run 候选**：它由八个“五层段”组成，每一段都必须以既有五拍合同的语义完成并在第五拍后打开休整。四十层候选正好形成四个十层篇章，能够让每十层的大 Boss 成为完整阶段总结，同时不破坏每五层休整的硬约束；它仍待上位全局塔合同采纳。

这是一份**内容与状态编排规格**，不是实际楼层地图、时长、数值、存档或赛季长度。后续运行时必须建立全局 run 外壳与后续子循环适配，但其实现不得反向改写首轮五拍合同。

| 五层段 | 逻辑楼层范围 | 终点职责 | 与既有五拍合同的关系 |
|---|---|---|---|
| 第一段 | 首段至首次休整 | 首次小 Boss 槽；可续段或提前关闭。 | 直接继承 `TT_SPEC_TOWER_FIRST_CYCLE`。 |
| 第二段 | 第二个五层段 | 首个十层大 Boss；可续段或提前关闭。 | 仅由 `NEXT_CYCLE_HANDOFF` 后的未来全局 run 适配器创建；不得把首轮状态 ID 复用成真实键。 |
| 第三段 | 第三个五层段 | 第二个小 Boss 槽；可续段或提前关闭。 | 同一五拍不变量必须保持。 |
| 第四段 | 第四个五层段 | 第二个十层大 Boss；可续段或提前关闭。 | 同一五拍不变量必须保持。 |
| 第五段 | 第五个五层段 | 第三个小 Boss 槽；可续段或提前关闭。 | 同一五拍不变量必须保持。 |
| 第六段 | 第六个五层段 | 第三个十层大 Boss；可续段或提前关闭。 | 同一五拍不变量必须保持。 |
| 第七段 | 第七个五层段 | 第四个小 Boss 槽；可续段或提前关闭。 | 同一五拍不变量必须保持。 |
| 第八段 | 最后五层段 | 第四个十层大 Boss；仅可按既有关闭路径结束完整 run。 | 第五拍先到既有休整，再进入既有权威关闭语义；禁止 `NEXT_CYCLE_HANDOFF` 与第九段。 |

完整 run 的继续路径只允许通过**第 1–7 段**的既有 `NEXT_CYCLE_HANDOFF` 由未来权威全局 run 服务建立下一段；第 8 段在休整后明确禁止交接。任何段在既有 `SETTLED`、`FAILED` 或 `EXITED` 收束后都不能本地续开；它是该 run 的关闭结果，而不是新 run 的准入证明。

### 2.2 天庭侧候选 Boss 槽位：每五层，而不是每三层

本包提出 **每五层一个 Boss 槽位候选**。理由：它与已经锁定的“第五拍后休整”完全同相，避免三层小 Boss 与五层休整交叉造成连续高压、休整前后双结算或额外状态分支；该候选仍待上位全局塔合同采纳。

- 每逢五层形成一个 Boss 槽位并在权威完成后进入既有休整。
- 每逢十层时，该 Boss 槽位**升级为大 Boss**，不与小 Boss 叠放，也不额外插入一场战斗。
- 非十层的五层 Boss 槽位是小 Boss 槽：天庭内容池按“七星、二十八星宿、七星、二十八星宿”的族群轮替；具体哪一位星君或星官由未来权威内容快照选择，当前保持 `null/deferred`。
- 七星/星宿被投放为塔内小 Boss 时，只借用战斗主题和可读性语言；它们不等于七星单人本或二十八星宿团队本的会话完成，不创建跨系统进度、资格、材料或经济来源。

| Boss 槽位 | 内容族群 | 说明 |
|---|---|---|
| 第五层 | 七星小 Boss | 只从七星主题池选择，具体星君未定。 |
| 第十层 | 大 Boss | 升级为四门校律使，不叠放小 Boss。 |
| 第十五层 | 二十八星宿小 Boss | 只从星宿主题池选择，具体星官未定。 |
| 第二十层 | 大 Boss | 升级为九曜司衡官，不叠放小 Boss。 |
| 第二十五层 | 七星小 Boss | 继续七星/星宿族群轮替，具体星君未定。 |
| 第三十层 | 大 Boss | 升级为镇塔监律使，不叠放小 Boss。 |
| 第三十五层 | 二十八星宿小 Boss | 继续七星/星宿族群轮替，具体星官未定。 |
| 第四十层 | 大 Boss | 升级为玲珑塔灵，并进入完整 run 的既有关闭路径。 |

### 2.3 每十层大 Boss：无数值四段总结

| 十层节点 | 大 Boss 设计名 | 主题与玩家决策 | 禁止补全 |
|---|---|---|---|
| 第十层 | **四门校律使·残响合判** | 把相互冲突的门令投射到多条可读路线；玩家需辨认真正命令，并让错误门令互相抵消。 | 单位/技能 ID、伤害、血量、阶段时长、掉落、对象资产。 |
| 第二十层 | **九曜司衡官·错轨天盘** | 多组星轨在场地上错位叠合；玩家先保留正确轨迹，再将偏移轨引入校正窗口。 | 数值、轨迹速度、计时、AI、随机表、奖励。 |
| 第三十层 | **镇塔监律使·万象回声** | 将先前学会的预警回声化；玩家需要区分“原始规则”与“错误复写”，选择正确反制顺序。 | 实际复刻技能、词缀、构筑克制、资源绑定。 |
| 第四十层 | **玲珑塔灵·归律真影** | 将门令、星轨、围猎与封镇的阅读语言汇聚为一次秩序复位；只有持续读出并处理正确关系，才打开完整 run 的权威关闭路径。 | 赛季奖励、结局物品、称号、货币、法宝、任何经济结果。 |

四名大 Boss 的名称、主题与反制方向是本包提出的天庭侧内容候选；它们不是上位全局塔已采纳的事实，更不是实际单位、地图、技能或资产。所有表现仍应遵守“预警 → 决策 → 反制 → 可复盘失败”和非颜色唯一的既有可读性规则。

## 3. 全局 run、断线、清理与幂等

### 3.1 外层运行语义

完整 run 的外层仅定义以下逻辑关系：

1. 未来权威端先逐人完成 Lv55 校验并冻结 run 成员范围；队长、UI、本地缓存或其他成员不能替代逐人校验。
2. 权威端在 run 接受前冻结一次 run/赛季快照；该快照仅描述本 run 采用的内容与赛季语义，不能用于授予奖励。
3. 每个五层段都先遵循既有五拍、休整、pending 与终态语义。只有 `NEXT_CYCLE_HANDOFF` 才可由权威端请求下一段。
4. 第四十层大 Boss 权威成功后，仍先抵达既有第五拍休整，再经既有 `SETTLEMENT_PENDING → SETTLED` 的关闭形态完成 run 关闭。本包不会向该路径填入任何经济字段。
5. 失败、退出或被拒绝同样先使用既有 pending/terminal 语义；外层清理只释放 run 锁，不改写已确定的段终局。

### 3.2 断线与清理

| 情形 | 冻结规则 | 明确禁止 |
|---|---|---|
| 单人 run 参与者断线、生命周期失效或权威失败 | 进入当前五拍段的既有失败/退出收束；run 外层进入清理等待。 | 同一 run 内重连、重入、重用旧 run/cycle 身份、以 UI 恢复活动状态。 |
| 团队 run 成员断线 | 该成员标记为 `left`；剩余权威 `active` 成员能否继续由未来遭遇合同裁决。 | `left` 成员重连、补领、代领、恢复成员资格或形成任何未来经济资格。 |
| run 关闭清理 | 只有匹配未来 run 身份、cycle 身份、epoch、revision 与 cleanup token 的权威确认可解除 run 重入锁。 | 旧/跨 run cleanup、错误 revision、错误 token 解锁，或用 cleanup 回滚正常段终局。 |

### 3.3 回放与幂等

每个未来 run 操作都必须在独立的权威语义包络中处理，至少涵盖 run 范围、cycle 范围、请求种类、预期源状态、冻结成员范围、资格快照、事件语义与 schema 版本。字段名在本包只作为合同名称，所有实际值为 `null/deferred`。

- 同一准入请求：只能返回首次权威接受或拒绝，不能重复创建 run 或节拍。
- 同一小/大 Boss 槽终局：完成、失败、退出中第一个权威终局胜出，重复或竞争请求只返回既有结果。
- 同一 `NEXT_CYCLE_HANDOFF`：只能创建一个后续逻辑段；不得跳段、重放小 Boss、叠加休整或生成额外价值。
- 同一 run 清理：错误或过期确认被拒绝；已经权威接受的正常段终局不因后续清理延迟、失败或重放而回滚。

## 4. 权威时钟与赛季快照

赛季不是客户端日历、本地时区、UI 倒计时或星宿 `rotation_snapshot` 的别名。未来全局塔必须在 run 被权威接受时冻结一次不可变的赛季快照；当前仅冻结其**字段语义与不可变性**，不冻结任何赛季值、时长、时区、起止日期、周桶、词缀、奖励轨或重置日历。

| 快照事实 | 当前状态 | 规则 |
|---|---|---|
| `tower_season_snapshot_id`、`season_catalog_version`、`season_scope` | `null/deferred` | 未来仅由权威端生成并绑定到一个 run；本地不能填写、替换或复制。 |
| `authority_time_basis_id`、`captured_authoritative_instant` | `null/deferred` | 未来权威时钟提供方尚未指定；客户端时钟、时区、重试与重连不可推导赛季。 |
| 赛季主题/内容候选 | `null/deferred` | 只可影响未来已批准的内容选择，不可改变已冻结的五拍、Lv55、每五层休整、十层大 Boss、进度或经济边界。 |
| 赛季奖励、排行榜、周桶、重置、通行证、货币与保底 | `null/deferred` | 本包不设计、不计算、不展示，也不创建持久化记录。 |

完整 run 内快照不可变；只有创建一个新的未来 run 并重新经过权威准入，才可能得到新的赛季快照。星宿的 `Asia/Shanghai` 方位轮换仍只服务星宿会话，不得被本塔赛季快照读取、改写或替代。

## 5. 星宿经济来源：继续为零

### 5.1 当前来源结论

当前唯一不变的天庭零价值来源事实候选仍是：`TT_SPEC_EVENT_LINGXIAO_OUTER_COURT_SUCCESS` 对应的凌霄外庭权威完成。它也尚未获得 `source_profile`、奖励槽位、所有者映射或经济收据。

七星、星宿普通、星宿噩梦以及塔内复用的任何星君/星官/Boss 槽，均不得因为内容设计、战斗成功、净宿、轮换、断线后状态、清理成功或完整 run 关闭而变成经济输入。

| 二十八星宿普通完成 | `null` | `null` | `null` | 不得形成经济来源；夜巡钥仍仅是离线准入候选语义。 |

### 5.2 掉落、材料与赛季经济的冻结

以下字段全部为 `null/deferred`：实际物品/材料/货币/经验、资源表键、奖励类别映射、掉落概率、保底、数量、来源上限、所有者、多人参与箱、roll、周桶、赛季值、排行榜、收据、结算请求、`tower_mode`、`source_profile`、`reward_slot_key`、`qualification_snapshot_id`、`receipt_id`。

既有首轮五拍合同对 economy-v2 的“设计引用”继续存在，但本包不实例化、编译、扩展或填充该引用。没有未来独立批准的塔经济来源、资格快照、所有者解析、证明解析、资源表版本与持久化幂等收据时，任何塔关闭都不得产生经济效果。
