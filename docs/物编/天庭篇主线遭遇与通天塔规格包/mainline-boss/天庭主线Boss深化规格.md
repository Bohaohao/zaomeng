# 天庭主线 Boss 深化规格

> **状态**：纯离线设计规格 / `production-gate-closed`。
> **范围**：仅覆盖非通天塔的天庭主线 Boss 与其场地、预警、小怪/精英接口；不覆盖七星、二十八星宿、四圣、通天塔、掉落或赛季。
> **目的**：把既有主线的“错误天律 → 读图 → 决策 → 反制 → 可复盘失败”深化为后续施工可拆解的首领语法，而不创建任何运行时内容。

## 1. 来源与硬边界

本包只使用下列既有天庭资料作为输入：

- `../mainline-route.md`：主线路径、叙事因果与已命名的首领方向；
- `../combat/天庭战斗机制与可读性规格.md`：战斗教学链、可读性语法、凌霄终局三段与 1–4 人原则；
- `../object-blueprint/天庭物编美术与特效需求蓝图.md`：P0–P2、L0–L4、轮廓、前摇与场地表现约束；
- `../combat-baseline/天庭战斗数值与单位基线裁决.md`：五组主线 Boss 唯一可引用的相对阶段暴露、压力、节拍与 P0/反制窗口；本文件不复写原始单位字段或秒数；
- `../enemy-ecology/tianting-enemy-ecology-contract.json`：非通天塔小怪、精英、机制实体与受保护首领身份的唯一生态身份来源；
- `../terrain-layout/layout.json` 与 `../terrain-layout/天庭地图口径对齐与白盒前置裁决.md`：候选区域的阅读职责、图解/白盒分离与会话隔离；
- `../authority/tianting-progression-and-instance-authority-contract.json`：逐人准入、冻结成员、会话、失败、清理、完成与幂等边界。

以下内容在本包中一律为 `null/deferred`，不得由文本、验收或后续施工简报暗中补齐：

- Y3 单位、对象、技能、Buff、投射物、AI、事件、Lua、资源 ID、对象 ID、地图键、逻辑点、入口、传送、出生点、坐标、碰撞和实际地图；
- 原始对象的伤害、生命、护甲、冷却、施法、移动、仇恨、波次、数量、刷新、超时、复活、性能和秒数；相对阶段暴露、压力与窗口只能单向引用独立数值裁决；
- XP、货币、材料、装备、钥匙、概率、保底、掉落、资格、收据和经济结算；
- 真实进度键、进度写入、成员资格判定、会话创建、会话状态迁移、断线判定、清理确认和重放处理。

`TT_SPEC_*` 仅是离线设计身份，不是资源 ID、对象 ID、地图键或运行时键。主线战斗表现只能消费未来权威端已确认的阶段/成员状态；它不能自行判断成功、失败、成员有效性或写入 `TT_SPEC_PROGRESS_*`。

## 2. 全主线共享首领语法

| 层 | 玩家必须读到 | 设计要求 | 禁止替代 |
|---|---|---|---|
| L0 轮廓 | 谁在施压、哪一块场地具有机制职责。 | 首领、机关、命令源、可净化关系和可用路径的形态不同。 | 用装饰、同色粒子或仅文字替代轮廓。 |
| L1 前摇 | 接下来由谁向哪里施加何种错误规则。 | P0 信号先于结果出现，至少含一种空间/形状/动作线索。 | 无来源的瞬时命中、转段后无提示换义。 |
| L2 关系 | 目标、链路、区域、遮蔽、路线或互斥命令如何关联。 | 关键关系在同一阅读周期内可追踪，并留第二信息通道。 | 只靠颜色、聊天文本或不可读的远景关系线。 |
| L3 结果 | 反制是否生效、错误规则是否已被回正。 | 正确处理给出可见的断链、静默、开口、回正或路径变化。 | 静默后台改状态、让玩家猜是否处理成功。 |
| 复盘 | 为什么失败，下一次应改变什么。 | 失败要能归因至误读、顺序、路线、节点或窗口，而非不可解释的瞬杀。 | 将失败归为输出不足、隐藏数值或未明示同步。 |

每一个 P0 预警还必须有独立第二通道（声音、简明状态、场地状态变化或无障碍文字之一）；颜色绝不是唯一载体。所有机制都要有一人可顺序完成的解法；在未来权威端允许的 1–4 名冻结成员范围内，多人只能把同一解法并行化，不能额外制造第五人职责或同步硬门槛。

## 3. 首领深化

### 3.1 裂云南天门：千里眼／顺风耳的巡天误令

| 项目 | 离线规格 |
|---|---|
| 离线身份 | `TT_SPEC_MAINLINE_BOSS_SPLIT_SOUTH_GATE`；双首领/双命令源的设计身份，不是单位、技能或资源。 |
| 叙事角色 | 将彼此矛盾的巡天命令转化为可读的视觉与听觉压力，证明被污染的是命令源而非守门者天然敌对。 |
| 首领角色 | 千里眼负责可追溯的视线扇区；顺风耳负责可追溯的声波环。二者共同制造“不能把两种判定当作同一招式”的首个主线教学。 |
| 候选场地职责 | 只使用裂云南天门候选区的“两个可辨遮蔽组、声波空隙、中央回转路、门内外周转带”阅读职责；不绑定图解坐标或真实地图。 |

| 阶段语法 | P0 预警 | 玩家决策与反制 | 可见结果与失败复盘 |
|---|---|---|---|
| 异源误令 | 视线扇区与声波环必须有不同的几何轮廓、来源方向和第二通道；遮蔽对哪一种有效要可见。 | 先读出当前命令源，再选择遮蔽、空隙或等待交替路线；不得把一个遮蔽位当成双重免疫。 | 正确路线让一条错误命令短暂失去可执行路径；失败复盘须指出“误把视线与声波合并”“把遮蔽当作万能解”或“未预留回转路”。 |
| 交替校验 | 两种预警的先后关系、下一条安全转换线和保留的回转路同时可读。 | 在不同时承受两种判定的前提下完成交替移动，利用命令互斥暴露来源矛盾。 | 互斥命令被看见而非静默消失；失败复盘须区分“读错前摇”和“在错误时机跨越声波/视线边界”。 |
| 门禁回正 | 被证伪的命令源呈现明确的失效/静默状态，剩余安全通路的方向不与背景门饰混淆。 | 选择沿已被证明安全的交替路线收束，不以持续攻击跳过命令校验。 | 场地回转线可见地恢复；失败复盘应说明是放任错误命令重叠，还是错过已打开的安全转换。 |

**小怪/精英接口**：未来遭遇层可把“受控巡天守备压力”接入两种命令源的读图关系，但不能在本包中生成天兵、精英、波次或刷新。任何附属压力只能强化视线/声波的区分，不得遮挡 P0 边界、制造第三种未预告判定或迫使某名玩家长期占位。

**1–4 人适配**：单人按“观察来源 → 选择一类遮蔽/空隙 → 交替转移 → 回转确认”顺序完成；多人可分别报读来源或分散通过路线，但每名成员都能独立读到两种预警，且任何一人失位不应使机制变成无解的双人同步锁。

### 3.2 天宫道·断虹阵：巨灵神与受控阵眼

| 项目 | 离线规格 |
|---|---|
| 离线身份 | `TT_SPEC_MAINLINE_BOSS_BROKEN_RAINBOW_FORMATION`；巨灵神与阵眼关系的设计身份，不是首领对象。 |
| 叙事角色 | 将“先清怪”改写为“先校验阵眼、再解除被迫参战者的错误秩序”，让玩家理解受控天兵并非天然敌人。 |
| 首领角色 | 巨灵神承担守阵压场与锁链关系的可读锚点；真/伪阵眼承担错误命令的来源辨识。 |
| 候选场地职责 | 只使用断虹阵候选的双支线、居中阵眼、连续观察线与回退阅读职责；不创建云桥、跌落、区域或碰撞。 |

| 阶段语法 | P0 预警 | 玩家决策与反制 | 可见结果与失败复盘 |
|---|---|---|---|
| 阵眼校验 | 真/伪阵眼至少在轮廓、关系线或反馈中有一项不同；巨灵神与受控压力的锁链关系先于本体压迫呈现。 | 先验证真阵眼，再决定处理哪条错误召回关系；不能把所有可见节点当成等价目标。 | 真阵眼与错误关系线的结果不同且可追溯；失败复盘须说明“误认阵眼”或“忽略锁链来源”。 |
| 断链解阵 | 被确认的错误链条、被召回压力和可用支线在同一阅读面内可见。 | 优先切断已验证的错误命令链，再利用松动窗口处理守阵压场；不得以清场替代阵眼校验。 | 链路断开后，受控压力明确减弱/转向，且路线不再被同一错误规则重写；失败复盘须说明“先压首领、后拆阵”导致何种重组。 |
| 守阵回正 | 巨灵神的守阵姿态、剩余真节点和可退路径保留连续历史。 | 在已回正的阵眼关系中收束，而不是攻击被迫参战者来维持场面。 | 已回正关系与未处理关系具有不同结果层；失败复盘须指向“放任错误阵眼召回”或“封死双支线回退”。 |

**小怪/精英接口**：受控天兵只可作为“阵眼错误召回压力”的未来小怪接口；错误阵眼的召回关系可作为未来精英/机关接口。它们的对象、数量、波次、AI、控制、伤害、掉落与存续均为 `null/deferred`，且不得替代巨灵神—阵眼锁链的 P0 信息。

**1–4 人适配**：单人能依次观察双支线、验证真阵眼、断链并回到守阵窗口；多人可并行观察或在不同支线缓解压力，但正确解法不要求两处长期同时交互，也不把“有人清场”设为阵眼反制的前置。

### 3.3 天王殿外缘：四门失衡守备首领／机关群

| 项目 | 离线规格 |
|---|---|
| 离线身份 | `TT_SPEC_MAINLINE_BOSS_FOUR_GATE_IMBALANCE`；四向守备命令源、守备首领与机关群的设计集合，不是四个已建单位。 |
| 叙事角色 | 让四方守备信号在同一时刻互相否定，预演后续四象轮值的“方位关系”而不借用星宿团本资格或轮换。 |
| 首领角色 | 四向命令源分别承担朝向、状态和冲突痕迹；守备首领/机关群只作为这些命令的执行外观，不以单体输出成为解决方案。 |
| 候选场地职责 | 只使用四门候选区的多向观察、可分流但不被完全隔断的路线、阶段汇合线与可复盘冲突痕迹；不绑定矩形区域或实际机关。 |

| 阶段语法 | P0 预警 | 玩家决策与反制 | 可见结果与失败复盘 |
|---|---|---|---|
| 四向显令 | 每一道命令同时具备方向、形态和来源前摇；四向不可只用四种颜色区分。 | 先辨别哪两道命令互斥，再决定观察、处理或暂缓哪一方。 | 冲突来源和受影响路线保留可见对应；失败复盘须指出“只看单一方向”或“把四道命令当作四次独立清场”。 |
| 分流校序 | 彼此干扰的门向、当前可用路径与可会合位置同时可读。 | 单人采用可顺序的开关/验证路线；多人可分流观察或处理，但须按可读顺序回合而非永久分队。 | 正确顺序令一条回响安静并留下稳定痕迹；错误顺序保留可复盘的冲突，而不是无提示重置。 |
| 失衡收束 | 已安静与仍冲突的命令在轮廓、状态或关系层不同；最终汇合线清楚。 | 决定保留哪条已回正的路径，利用它回收未处理的互斥命令。 | 剩余信号不再否定已回正结果；失败复盘须说明“过早切换”“错误分流”或“错过汇合线”。 |

**小怪/精英接口**：失控云兽可作为路线扰动小怪接口，四门守备机关可作为命令执行接口，守备首领可作为方位压力的精英接口；三者均不能新增独立胜负条件。未来内容若接入，必须让玩家先读到方位命令，再读到附属压力，且不得通过刷怪数量、刷新节奏或精英击杀取代开关顺序的判断。

**1–4 人适配**：一个人始终能以“观察四向 → 选择一条可验证路径 → 回看冲突结果 → 处理下一方向”串行完成；两至四人可并行读取或缩短往返，但不得要求四人同时守住四门，更不得因成员数不足而改变命令的正确顺序。

### 3.4 周天观台：监星使与星历裂缝

| 项目 | 离线规格 |
|---|---|
| 离线身份 | `TT_SPEC_MAINLINE_BOSS_CELESTIAL_OBSERVATORY`；监星使、星历裂缝与残缺星图关系的设计身份，不是单位、机关或会话入口。 |
| 叙事角色 | 解释七星锚点熄灭、二十八宿轮换被污染的原因；主线只完成校星叙事，不创建七星/星宿会话或资格。 |
| 首领角色 | 监星使承担误导与观测压力；星历裂缝、星点和链路承担“当前星图不是静态谜题”的可读对象。 |
| 候选场地职责 | 只使用周天观台公共枢纽的中央星图、外缘观察线、短暂回退与轮换预告展示职责；会话门廊仅是展示面，不是入口。 |

| 阶段语法 | P0 预警 | 玩家决策与反制 | 可见结果与失败复盘 |
|---|---|---|---|
| 星历观差 | 星点、链路、变化方向和可净化状态构成连续历史；可交互星点不能与背景星空同层同形。 | 观察变化规律，判断应继续观察还是验证一条链路；不得把当前画面当成静态谜题。 | 已观察的变化方向可被复述/查看；失败复盘须指出“未观察即净化”或“把背景星点认作可验证对象”。 |
| 伪轨分辨 | 稳定链路、错误链路与监星使的误导关系在轮廓、动态或交互反馈上至少有一项差异。 | 先验证稳定关系，或利用错误链路暴露监星使的误导来源；不能仅凭颜色选链。 | 被证伪的链路给出明确拒绝/回正反馈，不伪装成无提示失败；失败复盘须区分“读错变化方向”和“误认链路状态”。 |
| 校星开示 | 正确校星前有可读的最终连线与可净化标记，处理后轮换预告/通路展示发生可见变化。 | 在已证实的链路上完成回正，保留星图证据而不是击杀监星使来跳过校验。 | 星图从裂缝状态转为可读的预告/通路展示；这只是战斗可读结果，不写入观台开放进度。失败复盘须说明“保留了错误星轨”或“错过可净化窗口”。 |

**小怪/精英接口**：残缺星图、未校准星标和裂缝外溢只可作为未来场地压力/精英接口，不能变成无来源的小怪刷怪。它们必须让稳定/错误/变化关系更清楚，而不能遮蔽星点、链路、可净化标记或将观测行为替换为击杀数量。

**1–4 人适配**：单人可按“观察历史 → 验证一条关系 → 回看反馈 → 校正下一条”处理；多人可以分别观察不同关系或共享验证结果，但所有玩家均能独立确认关键链路，且不要求多人同时持续持有多个星点。

### 3.5 凌霄外庭·裂律观台：监律天将与裂律核心

| 项目 | 离线规格 |
|---|---|
| 离线身份 | `TT_SPEC_MAINLINE_BOSS_LINGXIAO_OUTER_COURT`；监律天将、命令节点与裂律核心的主线终局设计身份，不是私有会话、单位或经济事件。 |
| 叙事角色 | 以“旧天律是唯一正确答案”的错误秩序压场，要求玩家保留可净化节点并将证据转化为对裂律核心的限制。 |
| 首领角色 | 监律天将以法尺、文书、裂律符表达执行者；命令节点表达错误规则来源；裂律核心表达试图重置已纠正秩序的终局压力。三者轮廓不可混淆。 |
| 候选场地职责 | 真正战斗属于私有 1–4 人会话候选；场地仅需承担中央阅读区、命令来源、作用区、安全转移线、侧向撤离廊与连续证据历史，不绑定会话地图。 |

| 阶段语法 | P0 预警 | 玩家决策与反制 | 可见结果与失败复盘 |
|---|---|---|---|
| 断令识别 | 法尺指向命令来源；文书/符印在压场前向受影响区域展开；错误命令链短暂失效时出现可净化标记。 | 辨别被强制执行的规则来自哪组命令节点，而不是盲目追击监律天将。 | 被校验为错误的命令链进入可净化窗口；失败复盘须指出“误判命令来源”或“错把可净化节点当作危险源”。 |
| 执令压场 | 当前命令类型、作用区、安全转移线和可用节点同时可读；首领把错误规则覆盖战场前必须露出来源。 | 决定谁先维持通路、谁完成校验、何时跨越被重写区域；单人按顺序处理，团队可并行。 | 正确净化将原限制转为临时可用路线；失败复盘须说明“放任错误节点接管”“封死撤离路径”或“在不可用窗口硬闯”。 |
| 回正裁决 | 裂律核心重组真/伪节点前，先展示其复用的视觉历史；被保留的真节点与伪节点在 P0/L2 上不同。 | 依据已留下的证据保护真节点、放弃伪节点，令真节点反向限制核心；不得机械重复上一阶段。 | 真节点形成对核心的可见限制和收束窗口；失败复盘须说明“误保伪节点”“未复查已纠正证据”或“错过回正窗口”。 |

**小怪/精英接口**：裂律文书、符印与旧令执行压力可作为未来精英/机关表现接口；本终局不依赖必须清空的小怪群。若后续接入受控执行者，只能承担“让错误命令来源更易读”的局部压力，不能遮挡命令节点、替代净化、创建独立资格/结算条件或把首领战改成站桩清场。

**1–4 人适配与权威边界**：单人可顺序完成校验、通路维护、净化和复查；多人可并行分担已可读的同类职责，但任何有效路径不要求第五人。成员资格、成员死亡/离场、全灭、超时、清理、重入和 `TT_SPEC_PROGRESS_MAINLINE_CLEARED` 的唯一写入仍只属于 `TT_SPEC_SESSION_LINGXIAO_MAINLINE` 及其既有权威合同。本包不产生成功事件、进度写入或经济输入。

## 4. 跨首领小怪／精英接入规则

1. 小怪和精英首先是“错误规则的可读放大器”，不是独立刷怪 KPI、伤害填充物或奖励来源。
2. 每个接口必须在首领/机关的 P0 来源、场地路线与反制关系已经可读后才允许出现；不能抢占 P0 层，也不能形成第三种未预告判定。
3. 未来小怪/精英只能沿着本包的五类接口接入：巡天守备压力、阵眼召回压力、四门执行压力、星历裂缝压力、裂律执行压力。名称、对象、AI、波次、刷新、技能、Buff、掉落和数值全部另行裁决。
4. 接口不得让单人解法失效：不可要求持续双占位、同时多点点击、固定人数承伤或先清完所有附属单位才允许识别首领反制。
5. 接口不得写入进度、资格、奖励、收据，亦不得改变冻结成员、`active → cleanup_pending → closed`、断线或清理确认语义。
