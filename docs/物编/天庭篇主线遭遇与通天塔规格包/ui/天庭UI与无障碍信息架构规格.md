# 天庭 UI 与无障碍信息架构规格

> **状态**：`offline-design-spec / production-gate-closed`。本文是天庭篇施工前的 UI 信息架构与无障碍验收规格，不是 Y3 UI JSON、UI 树、Lua、控件配置、网络协议或本地状态机。

> **硬边界**：所有 `runtime_key`、UI node ID、asset ID、图标 ID、音效 ID、特效 ID、文本模板 ID、事件 ID 与存档键均为 `null`。本文不定义奖励、材料、货币、经验、掉率、保底、属性、数值、资格消耗或结算。

## 1. 目标与来源

本包将既有天庭战斗、会话与收藏设计中“玩家必须看见、但不能由本地决定”的信息，拆为可审查的展示职责。它服务于 2.5D 俯视角下的阅读、协作与失败复盘，不改变任何进度、入场、时辰、会话、清理、资格或经济语义。

| 来源 | 可向 UI 提供的语义 | UI 不得补全的内容 |
|---|---|---|
| `combat/tianting-combat-readability-contract.json` 的 `TT_SPEC_TIANTING_COMBAT_READABILITY` | 预警、决策、反制、可见结果与双通道表达要求。 | 伤害、计时、阶段推进、净宿、胜负、成员或会话状态。 |
| `authority/tianting-progression-and-instance-authority-contract.json` 的三段进度、会话、轮换、资格与恢复合同 | 已由权威端接受的进度、冻结成员快照、轮换快照、成员状态、清理/终局结果。 | 权威证明、等级、资格、方位、重连、清理确认或完成收据的创建、修改与重算。 |
| `tianting-content-expansion-contract.json` 的七星与四圣称号规格 | 离线称号名称、集合称号“替代而非重复叠加”的说明方向。 | 实际拥有状态、材料计数、兑换、持久化、效果数值、展示位资产或全局作用域。 |
| `economy-candidates/天庭奖励候选登记.md` | 收藏/奖励仍是候选、不得由界面推导发放的边界。 | 任何奖励、资格、收据、背包变动或经济结果。 |

## 2. 全局信息规则

1. **展示权威结果，不展示本地推断。** UI 只能渲染未来权威端已接受的快照、状态或结果；数据缺失、未确认或版本不匹配时，只能呈现“不可确认/等待权威结果”，不能以缓存、队长状态、客户端时钟或战斗表现补齐。
2. **双通道，但不偷换决策权。** 关键预警至少同时具备一种形状、轨迹、场地变化或文字/状态表达，以及一种独立辅助（例如声音、震动提示、文本、非颜色图形或可选读屏描述）。辅助信息只解释已接受状态，不触发状态改变。
3. **颜色永远不是唯一载体。** 方位、危险、可反制窗口、成员归属、净宿关系、断线与失败结果必须可由颜色以外的形状、方向、纹理、标签、读屏文本或声音区分。
4. **请求与结果分离。** UI 可以发起未来的入场或交互请求，但不得把“已点击”“动画完成”“本地倒计时结束”写成已入章、已通关、已净宿、已获得资格或已结算。
5. **无奖励面板。** 任何完成、失败、称号或资格页面均不得显示或承诺材料、货币、经验、掉率、保底、装备属性、法宝数值、钥匙消耗、奖励槽位或收据结果。

## 4. 各面板的状态表达边界

### 4.1 战斗信息层

- 战斗层只显示“权威已接受的表现状态”；若未来运行时尚未提供该状态，必须保持 `null/deferred`，不能从伤害飘字、镜头、特效或本地计时器反推。
- 七宿—四圣双向关系应分开显示“星官对圣兽的压力”与“圣兽对星官的庇护”；禁止压缩为单一总战力数值。
- 任何可读性提示必须保留失败后可复述的因果，不把失败归因于不可解释的隐藏数值。

### 4.2 轮换与团本状态层

- 轮换面板必须明确“本次实例快照已冻结”；未创建实例时只能展示未来可用的规则说明，不能伪装成当前方位。
- 轮换快照的方位、时辰槽和难度都来自同一权威快照。UI 不可混用不同刷新时刻、不同队友或不同实例的字段。
- 团队状态仅反映冻结成员快照。`left` 成员不得出现可重连、可代领、可补领或可由队长恢复的入口。

### 4.3 失败复盘层

- 复盘应以“读错何种预警、漏处理何种反制、下一次可改变什么”为结构，不展示内部校验字段或责任归属的敏感数据。
- `cleanup_pending` 必须以“仍在等待权威清理确认”的不可操作状态表达；不能提供重入、复活、领奖或更改会话按钮。
- 已接受的主线正常完成与随后清理失败是不同事实：可显示完成已接受与清理仍待确认，但绝不能把后一项解释为完成被撤回。

### 4.4 称号与收藏层

- 七星与四圣页面只解释收藏关系和集合称号的替代语义；不呈现或承诺属性值、经济价值、掉落、材料数量、兑换、奖励或装备结论。
- 实际拥有、解锁、持久化与展示位选择均依赖未来独立的权威收藏合同。没有该合同前，任何“已拥有/可兑换/已发放”都不是 UI 可生成的事实。

## 5. 稳定验收清单

| ID | 验收点 | 通过条件 |
|---|---|---|
| `TT-UI-ACC-001` | 离线边界 | 工件明确为信息架构规格，未生成 UI JSON、Lua、实际控件或运行时状态机。 |
| `TT-UI-ACC-002` | 空 ID | 所有 runtime、UI node、asset、图标、音效、特效、模板、事件与存档 ID 均为 `null`。 |
| `TT-UI-ACC-003` | 权威显示原则 | 缺少或失配权威事实时只显示未确认，不从本地缓存、队长、客户端时钟或表现推断结果。 |
| `TT-UI-ACC-004` | 双通道预警 | 每个关键预警有至少两类相互独立的信息表达。 |
| `TT-UI-ACC-005` | 非颜色唯一 | 方位、危险、归属、反制与终局不能只靠颜色。 |
| `TT-UI-ACC-006` | 战斗不改写权威 | 战斗显示不得写进度、成员、净宿、会话、资格、清理或经济结果。 |
| `TT-UI-ACC-007` | 可复盘失败 | 战斗失败可被玩家理解为预警/决策/反制链条中的可改进点。 |
| `TT-UI-ACC-008` | 快照唯一来源 | 当前团本方位、时辰槽和难度只读同一已冻结权威快照。 |
| `TT-UI-ACC-009` | 本地时钟禁令 | UI、客户端时钟、时区变更、重试和重连不得重算或改写轮换。 |
| `TT-UI-ACC-010` | 锁定说明 | 已创建实例明确显示快照锁定；未创建实例不伪造当前实例事实。 |
| `TT-UI-ACC-011` | 冻结成员显示 | 队伍面板只显示权威冻结成员快照及其已接受状态。 |
| `TT-UI-ACC-012` | 离场隔离 | `left` 成员不能从 UI 获得重连、补领、代领或当前实例完成入口。 |
| `TT-UI-ACC-013` | 清理锁 | 清理中不能由 UI 解锁重入、复活、结束或会话状态。 |
| `TT-UI-ACC-014` | 逐人资格 | UI 不把队长、队友、客户端记录或方位选择当作其他成员的噩梦资格。 |
| `TT-UI-ACC-015` | 最小披露 | 准入反馈只展示非敏感结果/原因类别，不泄露证明、凭证或生命周期内部字段。 |
| `TT-UI-ACC-016` | 失败复盘边界 | 复盘展示不生成重试许可、经济结果或会话终局。 |
| `TT-UI-ACC-017` | 清理后完成不回滚 | 已接受正常完成可与待清理并存，UI 不把清理失败解释为完成撤销。 |
| `TT-UI-ACC-018` | 无奖励面板 | 失败、完成和复盘页面不显示或承诺奖励、数值、掉落、货币、经验、保底或收据。 |
| `TT-UI-ACC-019` | 七星收藏未确认 | 没有未来权威收藏事实时，UI 不推算或声称七星称号拥有、兑换或解锁。 |
| `TT-UI-ACC-020` | 七星集合防叠加 | 七星集合称号被表述为替代单称号效果集合，而不是重复叠加。 |
| `TT-UI-ACC-021` | 四圣链路双向可读 | 星官压力、圣兽庇护和已确认净宿链路分别可读，不能合并为一个数值。 |
| `TT-UI-ACC-022` | 四象集合防叠加 | 四象集合称号被表述为替代四方单称号效果集合，不声明数值或属性。 |
| `TT-UI-ACC-023` | 经济隔离 | UI 不创建、选择或提交 `source_profile`、slot、owner、roll、保底、资格、收据或结算请求。 |
| `TT-UI-ACC-024` | 跨篇保护 | UI 不读取、写入或显示为天庭前置的 `DF_PROGRESS_YANLUO_HALL_CLEARED`；入章结果只展示权威已接受的交接验证结果。 |

## 6. 明示延期

以下内容继续为 `null/deferred`，必须由未来独立专项和权威运行时提供后才可施工：

- 实际 UI 面板、节点层级、控件类型、资源、图标、字体、颜色、动画、音效、读屏实现与多语言文本；
- 战斗表现状态的传输、同步、节流、缓存、断线与恢复协议；
- 章节、会话、成员、轮换、资格、收藏、称号、经济与收据的真实数据服务；
- 任何地图入口、传送、对象、技能、Buff、计时、伤害、数值、奖励、背包或持久化绑定。

通过本规格只表示天庭 UI 的信息边界可进入后续 UI 专项设计；不表示 UI、无障碍功能、副本会话、称号、奖励或结算已经实现。
