# 天庭地图、UI 与资产施工发现清单

这是 P0/P1 之间可并行使用的纯离线交接包。它把已批准的地图口径、主线五组 Boss 白盒职责、双通道 HUD、失败复盘和 P0 资产批次汇集为一份机器可读的**未来项目发现清单**。

它不是 Y3 工程、地图、UI、物编插件、资源表或运行时模块；不会创建、热更或保存任何实际 Y3 内容。

## 当前边界

- `surface-construction-manifest.json` 的所有真实地图根、地图键、UI 路径、UI 节点、对象键、资源 ID 与绝对数值均为 `null`。
- 现有候选白盒、图解尺寸和区域职责只能帮助未来施工人员找到需要重新读取和验证的内容，不能直接转换为编辑器坐标或地图尺寸。
- HUD 只能展示未来权威端确认的事实。未知、过期或未匹配的状态必须显示为未确认，不能由客户端缓存、动画、队长、颜色或本地时钟补全。
- P0 资产批次只包含五组主线教学首领的外观与可读性需求；绝对战斗字段必须等待 P0 标定与稳定对象键。

## 内容

| 区域 | 本清单覆盖 | 不会生成 |
|---|---|---|
| 地图白盒 | 南天门、断虹、四门、周天观台、凌霄外庭五组主线阅读职责 | 地图、坐标、碰撞、逻辑资源、出生点、传送 |
| UI | 双通道战斗预警、冻结成员/清理状态、失败与复盘 | UI JSON、节点树、事件绑定、权威状态机 |
| P0 资产 | 轮廓、前摇、P0–P2、场地交互与对象字段门禁 | 单位、技能、模型、动画、特效、声音、资源 ID、数值 |
| 导入发现 | 未来项目需要实读、确认与验收的项目 | 实际 Y3 MCP 写入授权 |

## 未来进入 Y3 前的顺序

1. 读取实际项目、地图根、现有资源、逻辑资源命名空间和 UI 根。
2. 重新验证地图尺寸、镜头、碰撞、寻路、性能与 1–4 人阅读面；不得复制 dry-run 图解坐标。
3. 获得针对目标地图和施工层的明确写入确认后，才可制作主线白盒。
4. 在真实 UI 根和权威数据传输存在后，才可制作只读 HUD 与复盘面板。
5. 在 P0 绝对标定、稳定对象键、模板与资源盘点全部通过后，才可绑定五组主线资产。

七星、二十八星宿、四圣、通天塔、经济、材料、称号和奖励不在本包范围。

## 校验

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\implementation\tianting-surface-construction-manifest\tests\run-all.ps1
```

校验会验证：来源资料存在、五组主线白盒与五项 P0 资产完整、三项最小 HUD 信息面齐全、所有实际绑定保持空值，以及清单不存在可被误作 Y3 目标路径的值。
