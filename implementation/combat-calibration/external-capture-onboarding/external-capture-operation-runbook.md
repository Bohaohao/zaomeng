# P0 外部实机采集接入运行书

## 适用范围

本运行书只在操作者已经提供一个可只读访问的真实 Y3 map-local 工程根时使用。当前离线工作目录不满足此前提，不能执行现场采集。

## 0. 立即停止条件

出现任一情况即停止本次 bundle，不能补写或拼接：

- 真实地图根未通过既有 `script/y3/{meta,game}` 与 `ui` 结构预检，或只有“通过”字符串而没有绑定预检合同、runner 摘要、不可变报告摘要、只读授权、权威时间和工程/地图身份指纹的来源证明；
- 采集方无只读授权、无法给出隔离进程或权威时钟证明；
- 项目、地图、模板、库存、工具链、时钟或采集依据在同一 bundle 内漂移；
- 采集者、审阅者或采纳机关身份冲突；
- 原始日志、规范工件、输入轨迹或环境证明不是不可变外部引用；
- 有人尝试用本地模板、客户端 UI、离线夹具、布局图、合成目录或自由文本替代现场读回；
- 任何对象、地图、Lua、UI、奖励、收据或经济写入被请求。

## 1. 授权与隔离

1. 外部采集机关填写 `provider-qualification-template.json` 的外部实例，不把凭证或端点回填到仓库。
2. 明确采集方、操作者、独立审阅者和采纳机关两两不同的 principal。
3. 采集进程只拥有读取 Y3/editor/authority 所需的最小权限；采用外部 JSON/IPC 或等价不可变工件传输。
4. Node/Fengari、当前仓库脚本和本地测试不能替代该进程的信任证明。

## 2. 真实工程与环境证明

1. 对操作者提供的真实 map-local 根运行既有结构预检；当前仓库根的失败结果不能转用。该预检只是必要条件，不能单独证明来源。
2. 由合格提供方在外部来源—预检证明中绑定：预检合同 SHA、runner SHA、通过结果、不可变报告摘要、只读授权、权威时间、非秘密工程/地图身份指纹与撤销状态。
3. 在外部环境证明中冻结：引擎构建、真实工程 revision、地图/夹具 revision、对象库存、模板读回、权威时钟、工具链与 capture-basis 摘要。
4. 将 P0 主合同、`evidence-adoption` 合同与预检合同/runner 的 SHA-256 一并绑定。
5. 若任一字段改变，废弃整次环境证明和所有其下 capture bundle。

## 3. 只读采集与规范化

1. 依次采集 G07、G04、G05，再进入 G01、G02、G03 与 G06。
2. 原始工件保留在外部受信任系统；仓库只接收不可变引用与 SHA-256 摘要的结构规则，当前不接收真实记录。
3. 使用固定编码、字段排序、UTC 秒级时间和 SHA-256 生成规范工件；禁止依赖本地时钟、无序序列化、可变路径或后改日志。
4. G01 必须完整覆盖 12 个 profile 每个 3 次一致重放；G06 必须完整覆盖 1/2/3/4 人并含 left、旧生命周期、清理观察。

## 4. manifest 与独立审阅

1. 每个外部 manifest 只能绑定一个冻结的工程/地图/模板/工具链/时钟/capture-basis 摘要族；manifest 的该族必须与环境证明逐字段一致。
2. 审阅者独立检查提供方资格、环境、不可变性、规范化、门级覆盖与拒绝条件。
3. manifest 只能单向交给独立审阅；不得预先或反向引用采纳决定。审阅交接只产生外部审阅请求/结果引用；不能把任一 gate 标记为 adopted。
4. 只有既有 `evidence-adoption` 所指向的外部授权采纳机关可逐门登记决定。

## 5. 采纳后仍需的步骤

七门外部采纳齐备后，仍必须单独复审绝对字段投影。未通过该复审前，天庭对象键、HP、攻击、双防、攻速、移速、技能秒数、奖励与经济输入全部保持 `null/deferred`。
